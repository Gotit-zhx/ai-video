## 修复范围

- 完整请求与正文截止时间，并取消挂住的HTTP操作；不在通用传输层自动重发商品创建POST。
- 店铺类目与物流并行读取，仍先校验组织/店铺授权。
- 批量准备与提交最多3件同时进行；已收到的任务立即独立轮询，不等全部提交结束。
- 状态逐项即时显示，终态详情同步不阻塞其余任务；同步失败可继续补同步。
- 进度读取在关弹窗、切换组织、重入时有取消与代次隔离；过期响应不能覆盖新任务。关闭弹窗不会停止已开始的批量准备/提交或后台任务。
- POST前保存准确payload和幂等键；未知响应仅以同键重试，不按相同店铺模糊关联其它工作流。

按用户要求放宽等待：店铺配置180秒，商品准备/任务提交单请求90秒，进度/详情补同步30秒；图片生成在后台继续，不由页面等待时限终止。后台GET完整读取90秒，普通POST60秒、multipart90秒。

## 自动重试边界

- 店铺配置、商品只读准备和创建上传工作流，遇到超时、网络断连以及 HTTP 408/429/502/503/504，单轮最多尝试 3 次（首次加 2 次重试），两次重试分别等待 2 秒、5 秒；上述超时是每次请求的期限，不是整个批次期限。
- 店铺配置在同一轮提交中共享请求与最终失败结果，避免每件商品重复发起三轮请求。权限、业务校验与主动取消不自动重试。
- 创建工作流自动重试时始终沿用已保存的准确 payload 和幂等键；PATCH 失败先回读状态，不盲目重放修改。
- 进度和商品详情同步分别最多连续失败 3 次，然后显示“重试进度同步”；停止页面同步不会停止后台工作流。尚未创建工作流的商品显示“重试未提交商品”，手动重试跳过已有工作流的商品，并恢复暂停的进度同步。已存在的 FAILED 后台工作流不会由此按钮重新上传。“全部商品已提交”表示任务已受理，每件商品的 SUCCEEDED/上传成功才表示上传完成。
