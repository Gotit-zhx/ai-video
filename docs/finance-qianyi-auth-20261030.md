## 已核对与验证

- App ID / App Secret 来自千易「设置 → 三方应用对接」。
- 仅使用官方国内、海外、测试环境 HTTPS 地址。
- POST `multipart/form-data`，UTF-8；公共字段为 `appId`、`serviceType`、`bizParam`、`timestamp`、`sign`。
- 签名串按 ASCII 顺序拼接为 `appId=…bizParam=…serviceType=…timestamp=…`，末尾追加 App Secret，UTF-8 MD5 小写。
- `bizParam` 只序列化一次，签名与发送的 JSON 完全相同；等待限流结束之后才生成毫秒时间戳。
- 不发送 App Secret 原文；服务端加密保存，配置读取不返回密钥。
- 兼容 `bizContent` 为 JSON 字符串或对象；外层失败、内层显式失败、非零错误码、损坏分页均不推进同步。
- 响应最多 2 MiB，完整请求含响应体读取最多 20 秒，避免只限制响应头阶段而无限等待正文。

验证命令：`mvn -q -Dtest=FinanceQianyiClientTest test`。
5 项测试通过：独立计算的签名向量、实际请求表单字节、响应格式、错误/异常分页、超大响应取消。
示例凭据仅用于离线签名测试；正式联调使用用户授权保存的凭据，不在文档或日志中记录密钥。

官方页面示例签名文字与该页 Java/Python 算法计算值不一致。
以该页明确算法为准：示例完整拼接串经独立 Python hashlib 计算得到
`46bc640fe3d0e2866afde2980fe85392`，Java 实现测试一致，不能复制示例签名作为固定参数。

## 正式接入和范围

- 国内正式环境的店铺列表、售后单列表和库存流水请求均已成功；权限开启前返回的 `SERVICE_TYPE_NOT_ALLOW` 已解除。
- 读取 838 家千易店铺，以平台类型及 `onlineShopId` 完全一致绑定 47 家本地财务店铺；3 家没有唯一对应 ID，未按相似名称猜测。
- 仅接入售后/退回入库成本，不替换普通商品、贴单、广告成本或结算日期。
- `inventory.cost` 的币种及单价/流水金额语义仍需证据核验。新连接 `cost_basis_verified=false`，售后资料可同步；核验前保留原已确认退货成本，不将退款金额当作商品成本。
- 确认后千易替换该店历史退货成本来源，不与历史来源叠加。

## 同步与查询优化

- 最多 3 路店铺并行，单店由租约/配置版本串行保护；HTTP 不持有数据库事务，分页完成后才提交断点。
- 一页最多 200 条，合并查询已存版本；相同来源哈希跳过数据库重写。
- 未核验的资料采集、无变化的重复页不会清空整个财务 BI 缓存。
- 对真实返回的 `REQUEST_IS_THROTTLED` 使用全通道共享等待及自适应降速，不误提示为鉴权错误。
- 8 项真实隔离 MySQL 集成回归通过，包含慢店不阻塞其他店、并发租约、缓存保留、来源替换、防重复绑定和旧响应保护。配置界面自动化验证通过。
