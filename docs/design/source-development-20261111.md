# 小团队源码直接运行方式

更新：2026-11-11。用户明确将目标改为内部开发、联调和验证，替代之前的正式镜像发布及未完成的文件制品发布方案。本次直接实施该目标，不再以打包/候选/标签/正式发布作为代码生效条件。

- Java21/Spring Boot4.1保持原技术栈，使用 Maven dev profile 的 `spring-boot:run`；必要编译仅生成 `target/classes`，不执行 `package`、repackage、JAR/OCI/静态包构建。
- 外部轻量 watcher 自动增量编译 Java/资源；DevTools 只在成功编译后的 trigger 文件变化时快速重建上下文。前端直接读取 `frontend/`，HTML/JS/CSS不打包。开发浏览器感知源码修订后自动刷新，Java仍有必要的编译与上下文重启时间，不能宣称任意Java修改零延迟。
- 本地默认隔离开发 MySQL/Redis 与私有 `.env.development`；共享服务器保留既有业务库、会话、卷、密钥、授权、上游限流和检查点，只替换应用的启动方式及静态源码目录。继续保留现有TLS/登录/权限，DevTools远程更新接口不开放。
- 本机首选原生JDK/Maven，依赖容器只启动基础设施。服务器复用已验收运行环境与完整Compose链，绑定源码、编译输出、Maven/JDK工具与缓存；不为每次业务改动构建新镜像。
- 共享数据热重启在同一维护锁内暂停领取新业务并等待当前工作安全点，再触发重启、确认新上下文健康、恢复本次门控。编译失败不触发重启，不能清库/清队列/改迁移校验和来恢复。直接操作源码不等于可以覆盖其他会话的未提交工作。
- Git只管理协作和历史；运行未提交源码不需要版本标签、Candidate或生产发布审批。默认feature到develop，提交仅包含本任务；旧main-tree/release/hotfix作为历史与恢复资料保留，不改名、不强推。按影响验证必要功能，完整回归在后台/手动运行，不阻塞保存后的开发运行。
- 更新AGENTS.md、README、开发/运维/CI与服务器交接及其他常驻入口。旧发布记录保留历史事实并明确不再是日常运行入口。

验收：实际前端改动不重建应用、实际Java改动无需package即可改变运行上下文并提供新结果；同一页面能显示更新；失败编译保留可用状态；共享环境的配置、真实数据、会话和工作器保护保持；记录启动命令及真实热更新耗时。旧发布WIP独立保存，不进入本次实现。
