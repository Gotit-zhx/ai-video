# 寻源匹配响应与零匹配停止

- 现场记录：版本 5 的寻源首批 15 人收到 Java 分析接口的 HTTP 502。旧接口未记录失败阶段，连接器也丢弃了分类，因此无法追溯断言该历史请求的唯一原因。
- 已复现并修复：兼容网关的 `error:null`、`tool_calls:null` 和 `tool_calls:[]` 曾被误判为错误或工具调用。真正的工具调用、截断、缺失结束标志和不完整候选人仍拒绝发布。
- Java 记录处理阶段、耗时和异常类型；连接器仅传递固定错误代码及本地中文提示。响应正文、凭据和候选人资料不进入错误日志。
- 网页每次最多分析 5 人，剩余卡片留在队列中。自动分页、去重、暂停恢复、连接恢复和达到目标人数后停止均保留。
- 本轮累计成功分析 100 人仍零匹配时停止。后端拒绝继续该轮，前端停止读下一页和提交下一批。已有匹配时不受此零匹配阈值限制。
- 修改建议来自各条条件的 `unknown` / `unmatched` 计数，不追加模型调用，不自动降低条件或分数。
- 历史错误不会自动重跑。真实供应商请求未作为测试重复发起；离线模拟验证不能等同于真实供应商端到端成功。

验证覆盖：

- Java：兼容流与非流响应、5 人完整序列化条件分析、候选人及条件身份校验、真工具调用和截断拒绝。
- Python：固定错误代码脱敏、禁止重复调用、100 人边界、重放幂等、已找到人才时超过 100 人继续。
- 网页：超过 22 页、额度与连接恢复、暂停保留队列、每批最多 5 人、精确停止在 100 人、展示建议且不再请求。
- 浏览器：本地模拟的停止提示及建议布局，未改动用户当前生产页。
