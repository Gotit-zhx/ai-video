# 主动邀约等待反馈、每日额度和岗位匹配度

## 已发布范围

2026-10-08 发布服务端与网页版本 `/opt/heyi/releases/hr-greeting-20261008`，并更新当前 Mac 已安装助手的运行时和连接器。岗位评分网页版本为 `/opt/heyi/releases/hr-matching-score-20261008`。Windows 安装包仍为 0.1.14，本次未重建新包。

原问题是明确由 HR 批准的打招呼仍走后台请求额度，后台达到 100 次后等待，虽然每小时 120 次的硬上限仍有预留交互额度。现在批准的打招呼及必要职位核验使用交互额度；硬上限、风险暂停和写操作间隔仍保留。网页显示具体等待原因与预计时间，弹窗内显示准备状态及错误。

本地和服务端均按账号限制每天最多 150 次打招呼尝试，北京时间零点切换日期。服务端原子领取避免多台助手突破额度；本地在调用前持久化次数与不确定状态。丢失回执也计入额度，重启和重新登录不清零。结果不确定的写操作不自动重试。

## 回复后索要简历

仅确认打招呼成功的记录可进入后续流程。助手使用候选人加密标识和职位标识，核对会话详情后绑定，禁止按姓名猜测或跨职位关联。

对应求职者回复后，主动邀约流程直接进入索要简历队列，不再发送一条重复的首次回复。保持现有请求预算、写操作间隔、职位开放状态及风险暂停。已收到简历或已有索取记录时复用记录，避免重复索取。简历入池保留 `origin=active`，HR 可按主动邀约筛选。

现场已批准的一条打招呼返回 HTTP 200、平台 code 0，但 SDK 未确认业务发送成功，本地与云端保留 uncertain。传输成功不能替代业务回执；本次未标记成功或再次发送，也未向其他真实候选人发送测试消息。

## 岗位匹配度

候选人卡片展示百分制评分和黑白进度条，优先使用既有 `verifiedMatch`，即已匹配权重占全部条件权重的比例。资料覆盖率和待核实条数另列；旧记录有权重时按已知评分乘覆盖率换算。未核实条件不计入已确认匹配权重，但不代表确认不符合。

示例：已知条件评分 94.3、信息覆盖 70%，卡片展示 66 / 100。逐条依据仍可展开。仅改展示，不追加模型调用，不更改原有入选阈值及必需条件校验。
