# 裂变印花必须原生透明（2026-09-15）

用户明确每张裂变印花使用透明底。此前的“透明优先、非透明时本地去底”不再适用于新生成的独立印花。

## 生效行为

- PRINT_EXTRACT、PRINT_VARIANT、批次 EXTRACT / VARIATE 分组请求使用真实透明 PNG 输出参数。
- 原生透明能力表同时控制请求参数与路由。不支持该能力的 Grok／未知主路由在调用前明确停止；透明请求的主模型拒绝或结果未知时不切换到非透明备用路由。普通商品照片的原有回退不受影响。
- 付费响应先保存原始结果，再校验真实 PNG、alpha、可见图案与边缘连通透明画布。JPEG、不透明 PNG、孤立透明像素、过薄透明框、全透明空图不能成为合格母版。
- 不合格结果为 `TRANSPARENCY_REJECTED`，批次明确失败、保留原图，不进入套版。同一次恢复不重复付费。生成阶段可显式重试这张，仍受原批准预算限制；已进入套版的旧结果需新批次，避免替换冻结素材后复用旧成品。
- 批次再次读取旧生成素材时也校验；旧白底提取缓存不会被新批次直接复用。上传的静态图案仍保留原有素材处理规则。
- 前端显示“透明背景不合格”，原稿可查看，失败素材不计入已完成结果。
- 上传来源的独立印花提示词不会再被“生成去印花商品底图”的提示覆盖。示例服务的明确模型拒绝保留为 `REJECTED`，不再误标为结果未知。

此检查确认文件及透明画布满足要求，不声称能单凭 alpha 自动判断每个白色区域究竟是设计元素还是残留背景。
