## 请求与失败恢复

- `POST /api/v1/commerce-batches/create-and-start` 接受原创建字段及 `confirmed: true`，返回 `batch`、`execution`、`maxModelCalls`。
- 草稿、商品项、创作计划、执行记录、调用额度在同一数据库事务中写入。启动校验失败则整笔回滚，接口内不调用生图服务。
- 同一 `Idempotency-Key` 重放返回原批次与原执行状态，不恢复、重启或重新设置额度。原草稿接口保持兼容。
- 根据冻结计划的来源数量、款式数量、独立图案组和实际可见方位计算模型调用上限，超过单批 1000 次会明确拒绝，不截断款式或数量。
- 前端防重复点击；未确认请求的内容和 key 按组织保存在本标签页 sessionStorage。搜索、切换模板后切回、重开弹窗不会仅因界面操作丢掉该 key。同内容重试恢复原批次，确认成功后清除。
- 启动 POST 的客户端等待上限为 60 秒，超时只中止当前等待并解锁表单，不代表后台已取消；重试核对原请求。切换公司也会停止旧请求的客户端等待。
- 启动响应携带的批次和执行状态立即进入工作台，列表读取失败也不会挡住执行轮询。切换公司后旧响应不能恢复旧批次。

## 后台长请求

执行器使用有界后台并发，默认同时处理 2 个批次，`app.batch-execution.concurrency` 可设 1–8。独立心跳线程每 30 秒续租，只延长同一 token 且未过期的 RUNNING/PAUSING 租约。模型请求超过 5 分钟时保持当前任务所有权；无空闲槽位时不领取更多任务。

失租任务不能复活或重复提交，外部提交账本和阶段提交的 token 校验继续生效。关闭服务停止接单并标记在途批次暂停；进程被终止后的外部晚到结果仍不能保证写入，未决调用保留核查规则。
