# 招聘部门、储备人才库与招聘需求池

入口为人力资源 → 储备人才库（`#hr-pool`）。沿用现有指定平台管理员权限，不扩大账号可见范围。

## 独立的招聘部门管理

入口 `#hr-departments`，数据保存在 HR SQLite 文件的 `hr_departments` 表。与系统组织架构完全独立，不读取、复用、导入或修改原系统部门。
部门改为从钉钉组织架构同步，不提供手动新建/编辑；原手动保存 API 同样拒绝写入。进入页面自动同步，手动“同步钉钉部门”可重新读取通讯录；完整读取成功后才在事务中更新部门、上下级和成员数量。读取失败不改现有记录。
以平台企业、钉钉应用和部门 ID 建立来源映射。唯一同名的历史手工部门沿用内部 ID，保留岗位与人才关联；不同分支同名部门分开记录。部门改名保留 ID，重复同步不递增业务版本。缺失或不在可见范围内的部门停用并保留历史记录，不删除关联。旧快照不能覆盖新同步结果。
负责人从该部门成员下拉列表选择，支持姓名查询和成员分页。选择与确认时均调用钉钉成员详情，验证该员工确实属于当前部门；身份凭据绑定企业、应用版本、内部部门、钉钉部门和部门版本，五分钟过期。选择后仍需明确确认负责人，查询不发送通知。已有合法负责人保留；离开部门或应用版本变化的绑定失效，需重新选择。
需求使用 `departmentId` 关联这份独立目录，服务端校验并带出部门名称和经理；停用部门不能用于新需求。
已有需求的岗位资料及 AI 输入按保存时快照保留，重新编辑需求可选用最新部门信息。

## 储备人才库

- 招聘阶段：邀约、一面、二面、已录取，不展示“全部”阶段筛选，默认进入邀约。来源流程新加入的人才默认进入邀约。
- 部门：统一复用部门管理目录，移除独立项目组维护入口。全部部门、各部门、待关联部门使用与招聘阶段相同的横向按钮，选中黑底，部门较多时横向滚动；与招聘阶段、面试结果、关键词及分页组合筛选。刷新数据时复用未变化的部门按钮，保持焦点和滚动位置。原项目组数据及旧 API 保留兼容。
- 不提供手动新建和卡片编辑入口。人才由简历审批、AI 寻源等业务流程入库；学历、工作年限、城市、最近公司从候选人资料及已保存简历正文补齐。未明确提供的信息显示“简历未提供”，不使用岗位最低要求充当候选人经历。
- 人才卡片使用紧凑的自适应网格，保留四项履历和面试操作。分页固定每页 20 人，底部始终展示页码按钮、上一页/下一页、总人数；单页和空列表也能看到分页状态，切换部门或阶段回到第一页。
- 卡片不再单列“一面资料”按钮；点击姓名或头像打开原资料详情，键盘可聚焦并打开。点击其他卡片区域不会打开详情；“开始一面”和面试意见仍是明确的独立操作。
- 新审批记录按招聘账号与职位 ID 精确关联需求的部门；已有记录优先使用已送达面试资料的对应需求，否则同样使用账号与职位关联。多个不同部门匹配时不猜测，标记待关联；明确保存的部门和非空资料不会被回填覆盖。回填仅访问数据库正文，不下载文件、不请求 BOSS、不调用模型，写版本和审计记录，保留阶段及更新时间。
- “邀约”仅标记内部跟进阶段，不向候选人发送消息。
- 一面负责人在部门管理中从钉钉部门成员选择并确认；关联部门的岗位自动使用，无需逐岗位填写 UserID 或输入手机号。
- 数据保存在平台的 `/opt/heyi/boss-agent/runtime/talent-pool.sqlite3`，不依赖本机助手在线或 BOSS 登录。该文件必须纳入服务器常规备份；运行中备份使用 SQLite backup API。
- BOSS 标识重复入库会被拒绝。新建请求带 UUID，响应丢失后重试同一请求不会重复创建；已有资料使用版本号避免覆盖并发更新。

## 面试意见与结果

- 一面资料确认送达后，发送弹窗隐藏“钉钉设置”“发送一面资料”，保留关闭和送达记录。卡片将原更新时间位置改为“一面意见”，二面候选人有“二面意见”。
- 填写意见后选择“通过”或“不通过”。一面通过在同一个事务中保存意见并进入二面；一面不通过留在一面的未通过分类。二面仅记录结果，不自动录取。
- 一面、二面各有“待填写意见、通过、未通过”横向按钮，进入对应阶段默认选中“待填写意见”，不展示“全部结果”。与上方阶段选择保持相同布局，并与部门、关键词和分页组合筛选。已进入二面的候选人仍出现在“一面 → 通过”，不会丢失上一轮记录；全部人才数量按人去重。
- 一面、二面阶段按钮旁的数字仅表示当前轮次尚未记录意见的人数，随部门与关键词一起筛选。已处理结果仍保留在通过/未通过分类；接口保留历史 `counts`，前端使用独立 `pendingCounts` 展示待办数字。
- 人才详情提供“下载资料 ZIP”，包含简历、岗位 JD 和可打印的面试题库。已有发送记录使用发送时快照；尚未发送时按选定的已审批简历及同账号具体职位的有效需求生成。下载走当前管理员身份校验的 `/api/v1/hr/pool/interview/package`，私有、不缓存、不生成公共链接；校验原文件摘要，生成 ZIP 仅在内存中进行，不调用 BOSS、模型或钉钉，也不新建发送记录。
- 每人每轮只确认一次结果，提交 UUID 支持响应丢失后的安全重试，人才版本防止并发覆盖。已确认意见可查看，资料回填不删除面试记录。面试意见使用独立表 `hr_interview_reviews` 并写审计记录，不发送 BOSS 或钉钉消息。
- 流转成功后同步菜单及对应阶段：简历审批通过进入储备人才库的邀约，一面资料确认送达后关闭此次发送弹窗并进入待填写一面意见，一面通过进入待填写二面意见，二面通过并填写入职信息后进入入职安排及跟进。目标人才列表回到第一页并清除旧的部门、关键词筛选，避免流转后看不到候选人。查看历史已发送资料不触发跳转；未确认送达、保存失败、退出登录或关闭后迟到的响应不触发跳转。菜单按招聘工作台、招聘需求池、职位管理、简历池、储备人才库、入职安排及跟进、话术管理、部门管理排列。

## 招聘需求池与驱动模型

入口 `#hr-demands`。字段包括需求日期、招聘岗位、归属部门、部门经理、岗位类别、需求状态、编制人数、最低学历、最低工作年限、岗位职责和任职要求。需求状态为待启动、招聘中、暂停、已完成、已取消。

平台 `/api/v1/hr/demands` 保存需求，`/save` 保存修改，`/generate` 明确发起一次后台生成。数据与人才库使用同一 SQLite 文件。

0.1.9 起，“招聘岗位”关联当前本机招聘账号下的具体职位 ID（同名职位也独立区分）。
选择后读取完整 JD；点击 AI 生成时再次经本机助手调用已固定版本 CLI 的 `hr jobs detail`，
保存账号标识、JD 原文、获取时间和摘要，再把原文与 HR 补充信息交给现有 DRIVER 接口。
读取失败、账号变化、返回职位不一致、JD 为空或过期均不启动模型调用；生成结果保留来源版本和 JD 摘要。
打开需求列表和查看已有分析不调用 BOSS 或 AI。原有自由文本需求可查看，编辑和生成前需补充职位关联。
Java `/api/v1/recruitment-ai/generate` 使用 `ModelConfigService.driverConnection(organizationId)` 选择该组织系统配置的启用驱动模型，复用模型并发配额。
仅调用该模型的纯文本接口，不提供工具、不创建自动操作任务，不调用 BOSS。密钥留在 Java 服务内，不下发前端或保存到人才库。

输出人才画像、4–8 项胜任能力、6–12 道含追问与评分标准的结构化面试题。结果保存实际模型名、生成时间及需求版本。
同一组织一次仅生成一项需求。生成中重复点击不会发起第二次调用；无自动重试或多模型兜底开销。模型请求最多等待 5 分钟；
服务重启或超过任务期限将给出失败状态，用户可手动重试，不无限转圈。修改岗位需求后保留旧结果并标记待更新。
