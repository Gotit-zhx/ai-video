# 财务恢复、千易退款与店铺别名（2026-11-02）

## 当前线上行为

- “订单与退款 → 退款”使用千易售后接口已同步到本地的数据，默认退货单，支持类型、退款状态、退货状态、日期和编号筛选；明细、全量筛选合计与 Excel 导出使用一致条件。
- 用户明确取消“千易退货成本冲回”。页面、店铺/分组汇总和导出不再展示冲回成本，营业成本与利润不再使用该值，也不因千易成本未确认而被阻塞。后台不再调度库存成本核验；售后单同步继续。
- 营业成本明细原先的“确认退款”取平台汇总。现在单独读取千易 `orderRefundAmount`，筛选 `refundStatus=FINISH`，按千易创建日期和当前分组/店铺/平台范围读取，按原币分列，明确标注来源。未知币种不合计，缺失金额不填零。此金额只用于核对，不再次扣减利润。
- 平台结算账单仍为收入、平台费用及现金结算的依据。取消库存成本冲回不会再次扣除退款，不会修改平台原始流水。
- 财务店铺配置增加“店铺别名”，写入既有 `finance_connections.display_name`。同公司共享，财务页面和导出优先显示；空字符串清空，缺失字段保留已有值。保留平台原名、店铺 ID 及订单绑定。重新授权不会覆盖别名。最多 100 字，拒绝控制字符。保存后使公司汇总缓存失效。
- 财务普通导出及对账导出增加店铺名称列，优先显示别名，同时保留已有店铺 ID 列。成本、贴单、千易导出原本已优先使用显示名。

- 已删除旧备份和临时文件约 24.69 GiB；保留原订单及导入源数据。
- 仅复制已发布的贴单聚合代次，核对数量与金额后原子替换。新的清理每事务最多 5,000 行、每轮最多 10 批，清理积压期间不再产生新代次，续租并设置低磁盘空间保护。
- 应用、前端、MySQL 和 Redis 的 Docker 日志驱动均为 `none`。没有增加持久化日志。
- 备份保留最新两份完整文件，单份上限 6 GiB；启动要求至少 14 GiB 空闲，低于 8 GiB 终止；上限一小时，校验 gzip 后原子发布。禁止部署后补跑积压定时任务。
