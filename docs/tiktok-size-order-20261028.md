# TikTok 上传尺码顺序

2026-10-28 核对最新三条 TikTok 上传任务，均为七种颜色、每色六个尺码，共 42 个 SKU。原始 `sort_order` 为采集返回顺序；最新成功任务以 `XXL、S、XL、XXXL、M…` 开始。此前上传只规范颜色/尺码维度顺序，没有规范尺码值顺序。

## 修复

`TikTokShopOfficialPublishingProvider.buildSkus()` 在身份、规格、图片、价格和库存全部绑定后，交给 `TikTokSkuOrdering` 排列完整 SKU 行：

- 保留颜色及其他非尺码维度的首次出现顺序，同一组合内按尺码由小到大排列。
- 支持 `XXS、XS、S、M、L、XL、XXL/2XL、XXXL/3XL` 与扩展尺码；括号中的体重说明保持原样。
- 数字尺码按数值排序，避免 `10` 排到 `8` 前面。
- 使用最终确认的目标规格，显式目标映射优先于来源规格。
- 不改 SKU 编号、价格、库存、图片或规格文案，不补造缺失组合，也不合并 `XXL` 与 `2XL`。
- 无法识别的自定义尺寸保持相对顺序；不同尺码体系不推测换算，纯 ID 规格不根据 ID 大小猜测尺码。

## 验证

新增回归在修复前 6 项中有 5 项失败，修复后通过。连同上传请求、草稿核对、颜色图片、尺码表与发货仓测试，共 53 项通过，0 失败、0 跳过。

官方 Create Product 202309 文档当日已核对：请求包含有序 `skus` 数组及每条 `sales_attributes`；未发现独立的尺码排序字段。本次修复调整发送数组，而不增加未定义请求参数。官方文档不承诺所有卖家页面都严格按数组展示，因此实际页面仍需以发布后结果为准。

本次不自动重传或改写已有平台商品，避免生成重复草稿。新上传使用修复后的排序。
