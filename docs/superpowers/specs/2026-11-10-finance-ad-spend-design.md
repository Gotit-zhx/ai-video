# 财务广告消耗工作台设计

用户要求以店铺、店铺分组和店铺消耗明细三张主表组织 TikTok 与 Shopee，完整展示现金、信用额度、广告赠款三项消耗及合计。用户确认推广系列可能跨店，缺少官方拆分依据时保留待分配，核实金额后归属，不按名称、账户访问关系或销售额估算分摊。

## 数据与归属

广告账户用于来源身份和重复检测，不能强制等同单一店铺。现有授权账户继续自动同步；手工报表须登记实际账户 ID 和来源名称，但无需先提供令牌。初稿曾考虑仅按独立来源名称生成身份；审查发现此方式无法在后续 API 到达时可靠去重，且缺少可靠的身份核验依据，因此最终设计保留真实账户 ID 作为必需元数据。旧未知身份来源仍保留，潜在重叠标记待核对，不能直接相加。这个约束不要求 OAuth 授权，也不绑定单一店铺。原平台账单广告费/广告佣金保留为辅助核对，主表分析媒体投放消耗，不将平台费用与 GMV Max 重复相加，不改变利润计算。

API AD/AD_GMV 作为只读事实来源；导入资金消耗独立存储，保留原币、源符号和来源行。TikTok 标准资金表按负数扣费转换为正数消耗，正数退费转换为负数冲减；通用 Shopee 模板显式选择符号约定。推广系列 ID 和账户 ID 均作为文本保留。未知金额分项为 null；三项均已知时必须等于总额。原表三项全部显示，总金额用于控制核对。

同平台/账户/日期/币种/推广系列的导入资金记录优先于相同 API 系列记录；账户级 BASIC 合计与系列级记录不叠加，记录覆盖提示，不能宣称完整对账。重复文件和重叠导入按稳定业务键去重，金额冲突拒绝整份发布。文件名及系列名称只展示，不自动决定归属。

人工金额分配以单条来源为单位，支持多个同公司、同平台店铺。三项分配金额分别守恒；未分配余额继续单列。分配保存来源金额指纹和审计版本；源金额变化后旧分配失效并提示复核，不静默覆盖。官方已明确归店的 API 明细继续使用官方归属。

TikTok 来源 ID 为广告账户 ID；Shopee 店铺报表使用真实平台店铺 ID，可从现有财务店铺中选择，不绑定 TikTok 账户。Shopee 来源 ID 唯一匹配财务店铺时自动归属。人工已核实的资金分配优先保留，不被后到的自动匹配覆盖；来源金额变化仍须重新复核。

## 页面

共用当前日期、平台、分组、店铺、币种及参考汇率筛选。先归属再筛店铺/分组；原币视图按币种分行，不能混币合计。三张表均显示三项金额、合计及来源完整性；明细另显示账户、系列 ID/名称、原币、来源及分配操作。已知零、未提供、待分配、部分金额分别展示。搜索和分页只改变明细；汇总与导出覆盖完整筛选结果。支持全量三表导出，保留标识符文本。

原有账户同步状态、平台账单广告费用、归因效果移至折叠辅助区；授权管理仍在财务店铺管理。新查询失败时明确提示，允许查看已有辅助资料，不把失败显示成零。权限隔离及本站写请求保护复用现有财务控制器。

## 边界

现有 API 的 spend/cost 未提供现金/信用/赠款完整拆分时保持未知，不从 net_cost、充值或余额推断三项。Shopee Ads 权限仍需官方批准；可用接口事实与显式导入共用展示模型，未取到的投放费用不宣称完整。此任务开发和本地验证，不隐含生产数据导入或上线。
