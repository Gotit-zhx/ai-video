# 源码模式下的 CI 与统一运维

更新：2026-11-11。主应用当前直接运行源码。CI 用于协作检查、定向验证和后台回归；旧 Candidate、正式标签、OCI 镜像传输和 Production deployment 不再是内部代码生效条件。旧体系的实现与验收仍是历史事实，见[旧发布工作流归档](../history/legacy-release-workflows/)和[一期收尾](../releases/infrastructure/devops-phase1-closure-20261107.md)。

## 日常开发与 CI

本地入口：

```bash
python3 scripts/dev.py init
python3 scripts/dev.py run
```

无参数执行 `scripts/dev.py` 等同于 `run`；已有兼容依赖时可加 `--no-deps`。Java 使用 JDK 21、Maven 3.9.11 和 dev profile 的 `spring-boot:run`。普通保存只编译到 `target/classes`，成功后触发 DevTools；不执行 `package`、repackage、JAR 或 OCI 构建。前端直接读取 `frontend/`，不执行 npm 打包、gzip 或静态发布目录构建。

CI 按影响选择检查：

| 变化范围 | 必要检查 |
| --- | --- |
| 文档、CSS、文案、普通页面 | 链接/引用、语法、对应页面行为 |
| Java 普通逻辑 | `compile`、相关单元/集成测试、运行上下文健康 |
| 财务查询、导出、金额、权限 | 缺陷复现、相关查询/导出、公司/店铺隔离；SQL 使用可销毁隔离库 |
| 依赖、Flyway、共享配置、租约/工作器 | 扩大兼容、启动、恢复及安全点验证；`pom.xml` 依赖变化受控重启，迁移和运行配置走显式维护 |
| 桌面或独立服务分发 | 按所属模块 README 构建；不捆绑主应用日常运行 |

`Development checks` 运行 `42961363055` 已成功，`develop` 必要检查已改为新检查。完整回归可按任务在后台或人工运行，不阻止保存后的源码开发。失败、跳过和缺失条件必须记录；源码能启动不等于所有业务链路已验收。

## Git 协作

仓库默认分支为 `develop`，必要检查为 `Development checks`。检查在 PR 与 `develop` 更新时执行；功能分支的每次保存和源码运行无需等待 CI。旧自动打包及发布开关已关闭。

本次合并和 GitHub 默认分支调整尚待收尾记录；不据此宣称默认分支已变更。

普通改动从 `develop` 建立 `feature/<主题>`，通过 PR 合入 `develop`；需要保留分支关系时使用 `--no-ff`。运行未提交源码不需要 Candidate、Release 或版本标签。`main-tree`、既有 `release/*`、`hotfix/*` 与历史标签保留为旧发布和恢复资料，不改名、不强推、不用它们覆盖当前协作历史。

## 共享服务器源码入口

规范源码根为 `/opt/heyi/dev/ai-video`。团队可通过 VS Code Remote SSH 直接编辑，或使用经批准的定向源码同步。同步前读取服务器工作区差异，只传当前任务文件；不得自动上传全部本地 worktree、私有环境文件或凭据。

服务器保留现有 TLS、登录、权限、真实数据库、Redis、业务卷、密钥、同步计划、检查点、租约和上游限流。Java 热重启仍须在维护锁内：停止领取新工作，等待当前工作达到安全点，完成编译后触发重启，确认健康与关键鉴权，再恢复本次门控。编译失败保留上一可用上下文，不清库、不清队列、不改 Flyway 校验和。

共享服务器主应用与前端已真实切换，见[源码运行现场状态](source-runtime-status.md)。服务器前端由 Nginx bind `frontend/`，本地静态源码由 Spring 提供；其他独立服务未切换。

## 迁移与专用维护

数据库结构仍只通过新增 Flyway 迁移演进。共享 Flyway 自动执行已禁用，migration 源码/hash/history 守卫阻止普通保存执行 DDL。`pom.xml` 依赖变化会受控重启 app；迁移、环境配置、工具链和 watcher 本身须显式维护和专项验证。

V148 广告结构维护与 V150 广告资金/归属维护保留原数据保护：使用各自专用维护实现和精确 SQL，不把工具扩展为通用 SQL 入口；保留迁移前缀、广告账户、店铺关系、同步状态、分页、租约和限流。部分 DDL 或失败状态不清库、不修改已应用迁移、不用 `repair` 掩盖差异。旧应用兼容与恢复资格仍以原独立回执为准，源码模式不自动扩大资格。

涉及加密密钥的变化必须提供已有密文兼容或迁移方案。数据库凭据只通过受限私有输入进入进程，不写入参数、日志、Git 或回执。

## 监控、备份与恢复

既有本机巡检、证书续期、备份和通知可继续运行，但积压本身不能触发重启。当前旧自动自愈为 false，CD/release_flow 为 false，源码维护继续遵守维护锁和安全点。日志保持脱敏、有界；不保存完整请求/响应、Cookie、令牌或业务导出。

备份仍维持已验收的数量、单份体积、空间和时长上限，timer 保持 `Persistent=false`；源码启动或重启不触发漏跑补备份。禁止全局 Docker prune、清理业务卷或按日期整删历史目录。旧镜像恢复前核对当前 schema、配置、接口和业务兼容性；应用恢复不等于数据回滚。

## 历史自动发布边界

旧 `scripts/ci/release_flow.py`、候选证明、GHCR/OCI 传输、systemd 发布执行器和正式标签协议保留为历史审计或明确恢复入口，不是日常命令。未部署的文件制品发布方案已被[源码开发运行设计](../design/source-development-20261111.md)取代。需要查当时的证明链、开关、磁盘预算和回滚隔离时，读取归档和对应发布记录，不把其中命令直接用于当前服务器。
