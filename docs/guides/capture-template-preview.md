# 采集模板

入口：商品运营 v2.0 → 采集模板，路由 `/#product-capture-templates`。旧 `/capture-template-upload.html` 自动跳转到该路由。当前已接入后端与私有 OSS，不再使用 IndexedDB 保存新模板。

## 采集链接与印花套版

在「商品运营 v2.0 → 采集链接」下载并安装赫逸印花采集插件。在 Shopee 或 TikTok Shop 商品详情点击「采集印花图 v2.0」，插件将商品资料、规格和最多 20 张用于提取的商品图写入当前企业，随后打开采集记录。已采集的商品从最近采集列表打开。

左侧列表显示最近 30 条 v2.0 采集记录，可搜索名称或刷新。顶部「监控」查看采集数量、当前商品图及处理状态。「布局」切换左右或上下。可勾选多张商品图，确认按张计费后依次提取。成功和失败结果分别保留，重新打开记录可查看旧结果。点击结果缩略图或对应商品图切换印花，右侧先显示透明印花。可选择已上传底图的款式或草稿，拖动印花调整位置，拖动右下角缩放。点击「排版」也可以用滑块微调。预览在浏览器中合成，下载 PNG 最长边为 2048 像素。

套版确认后点「开始上架」，直接勾选一家或多家店铺。商品资料、规格组合及各规格售价来自原采集链接，缺失的库存沿用 V1 默认值 999。新版印花插件采集规格资料。旧记录可复用同一企业内同一链接的完整规格，也可在原链接重新采集后继续使用已有印花。确认后，后台用 GPT Image 2.6 按款式关联的主图风格模板逐张合成，标记原样保留的图片直接使用模板原图。没有风格模板时使用当前排版合成一张主图。后台按模板里的颜色和色值分别生成规格图，同一颜色的各个尺码共用该颜色的图。同一草稿的多个店铺共用已归档的成品图，遇到结果不明时按原模型任务回读。页面按店铺显示主图和颜色图的制作进度、销售 SKU、资料校验、上传和上架状态。Shopee 完成商品和规格上传后立即请求上架，TikTok Shop 直接提交平台审核。平台回读为审核中时，显示「待平台审核」。演练使用本地数据检查流程。

「商品运营 v2.0 → 店铺管理」和 V1 的入口使用同一企业的官方授权。Shopee 返回续期凭据已过期后，两处店铺管理都会显示「授权已过期」。上架准备会停止重试该店铺并提供管理入口。重新授权后可重试未提交的商品。

销售颜色使用采集模板的颜色配置。各颜色的尺码、售价和库存使用采集链接中匹配的规格。未配置模板颜色时沿用采集规格。套版生成的 SKU 依次使用款式编码、颜色编码、尺码编码和 8 位随机编码，例如 `A01-BK-M-8F3A6C2D`。同一个印花结果跨店上架时复用随机编码。已提交任务继续使用提交时的 SKU。

v2.0「采集链接 → 提取印花」固定使用企业已启用的 `gpt-image-2.6`。采用简版提示词提取平面主印花、保留原文字和白色细节，要求返回带真实 alpha 的 1024 × 1024 PNG。每条请求最多调用一次该模型。历史请求继续显示原结果或原失败状态。OSS 暂不可用时，已生成且通过透明 PNG 检查的印花可从请求结果读取并套版。点击「重试归档」继续保存到 OSS，沿用原请求编号。

部署时在「模型接入」中确认该企业已启用模型标识为 `gpt-image-2.6` 的 OpenAI 兼容图片连接。可沿用经该模型验证的上游网关，新增连接无需设为企业默认。企业缺少可用连接时，提取入口会提示配置。

插件采集需要 `product:collect`，工作台和提取接口需要 `product:edit`。采集记录和图片按企业隔离。v2.0 插件写入独立数据范围，重复提交相同图组会复用记录。

「采集模板」在商品款式下方直接展开「主图风格模板」和「定制模板配置」。新建草稿也可以配置，首次保存任一配置时会自动保存所属款式。「采集链接」页的 v2.0 定制模板入口已移除。旧 v2.0 主图风格地址进入「采集模板」。

每个款式可保存一套主图风格模板。图片上传、自动提取、重试、修改与导出提示词、归档沿用现有规则。可复制已完成提取的企业风格模板，复制后的配置可独立修改。归档后可以添加另一套。原商品运营的主图风格库继续保留。

每个款式的定制模板配置分别保存 Shopee 和 TikTok Shop 的详情、包裹规格及店铺设置。Shopee 的物流渠道、TikTok Shop 的发货仓沿用原校验规则。在详情文案下方上传 PNG 或 JPG 尺码图，最大 8 MB。保存后，制作上传按目标平台和类目规则带入尺码图。原商品运营的批量上传可指定本次尺码图。首次打开未保存的平台或店铺配置时带入当前企业「采集链接」的对应值，保存后按款式独立读写。旧商品运营入口仍使用企业配置。v2.0 的印花提取和套版预览继续使用各自的参数。

发布本功能前，按共享服务器运维流程核对在跑的任务和维护状态。用隔离环境先验证新入口、旧采集、原批次上架入口、权限和模板读取，再决定正式发布时间。

## 数据与权限

- 模板名称、说明、款式、款式编码、颜色及其编码和版本保存在 MySQL。模板以企业为边界共享，客户端不能指定企业；后端从当前会话取企业编号。
- 图片复用 `CommerceImageArchive` 的私有 OSS 归档，按企业哈希与文件 SHA-256 隔离、去重。数据库只存归档引用，不存 Base64。
- 图片通过带登录和企业校验的同源接口读取，避免向客户端暴露存储凭据或接收任意外部 URL。
- 查询需要 `product:view`、`product:edit`、`product:publish` 或 `product:collect` 之一；写模板和上传图片需要 `product:edit`。无会话返回 401，无写权限返回 403，跨企业模板或图片返回 404。
- 每个模板仅一个款式、一个款式图片，可配置 1–30 个颜色。款式编码沿用原系统规则：一个英文字母加两位数字（例如 A01）。颜色编码为 1–16 位英文字母或数字（例如 BK、WH、001），同一款式内不能重复。编码去除首尾空格并转大写，保留数字前导零。图片支持 PNG/JPEG/WebP，最大 8 MiB，至少 128×128，最多 4000 万像素。前后端均校验，服务端按实际内容解码，不信任扩展名或声明 MIME。
- 保存携带版本号；冲突返回 409，不覆盖更新的内容。相同编号、相同内容的保存重试和相同图片上传可以安全重试。
- OSS 不可用时上传/读取失败，不回退成本地服务器存储或假装本机保存成功。

## 页面行为

进入时读取现有款式，左侧「填写模板」用于新建。编辑款式资料后自动保存，也可点击「保存」。款式名称和款式编码并排填写，每行颜色填写名称、编码和 HEX 色值，保留取色器。一次上传仅接受一张图片，多文件拖入会提示重新选择。上传即时写入 OSS，随后自动关联模板。只读和未登录状态禁用写操作。

旧预览版本的浏览器本地数据不自动上传、不删除，也不跨企业导入。新版本的跨设备共享依赖登录同一企业及相应权限。

在商品款式下方添加尺码并自动保存。每个款式最多 30 个尺码，名称和编码不可重复。英数字尺码名称可用作默认编码。胸围、衣长、肩宽和袖长为选填，单位为 cm。已填的尺寸会随商品详情上传。没有上传尺码图且目标类目支持时，系统可用填写的尺寸生成尺码表。未配置尺码时，SKU 默认使用 NOSIZE。未配置颜色时，SKU 默认使用 UNK。每个颜色使用单独的成品规格图。完整款式保存在 `content_json`。V189 增加 `draft_json` 保存未填完的草稿。套版优先使用最近一次完整保存的款式，新建草稿上传底图后也可套版预览。旧 JSON 缺少编码仍可读取，补齐后会更新可用款式。

## 接口

统一响应结构为 `ApiResponse`；图片响应为带 `Cache-Control: no-store` 的图片字节。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/product-capture-templates?offset=0&limit=50` | 分页读取当前企业模板，返回 items/total/offset/limit，limit 上限 100 |
| GET | `/api/v1/product-capture-templates/{id}` | 读取模板和版本 |
| PUT | `/api/v1/product-capture-templates/{id}` | 新增或更新；新模板 version=0，更新传当前版本 |
| POST | `/api/v1/product-capture-templates/images` | multipart 字段 file；上传 OSS 后返回图片 id、同源读取地址、文件名、尺寸 |
| GET | `/api/v1/product-capture-templates/images/{id}` | 校验权限与企业后读取 OSS 图片 |

保存体：

```json
{
  "version": 0,
  "name": "基础圆领 T 恤",
  "description": "",
  "variants": [{
    "id": "22222222-2222-2222-2222-222222222222",
    "name": "圆领短袖",
    "styleCode": "A01",
    "imageId": "11111111-1111-1111-1111-111111111111",
    "colors": [{"id":"33333333-3333-3333-3333-333333333333","name":"本白","hex":"#FFFFFF","colorCode":"WH"}],
    "sizes": [{"id":"44444444-4444-4444-4444-444444444444","name":"M","sizeCode":"M","chestCm":94,"lengthCm":65}]
  }]
}
```

所有 id 使用 UUID。`imageId` 必须来自当前企业成功上传的图片；服务端不接受 Base64、任意图片 URL 或存储 key 作为替代。
