# 财务默认全部币种修复

2026-10-29

## 原因

线上 `finance-workspace.js` 与已发布版本一致，上次切换店铺后清理旧币种的修复仍然存在。

本次遗漏在重新进入页面的恢复逻辑：旧 `sessionStorage` 同时保存展示币种和原币筛选，其中还可能包含接口自动选出的 MYR。恢复后即使店铺仍是“全部店铺”，请求也会携带 `currency=MYR`，导致只统计马来币种。人民币模式下携带 MYR 同样会先过滤再换算，仍然漏掉其他国家。

新增测试使用本次从线上下载的脚本复现了该问题：`displayCurrency=CNY`、`currency=MYR` 的旧缓存使默认总览错误携带 MYR。

## 修复

- 新一次页面加载恢复日期、店铺、分组、平台选择，金额默认人民币、原币筛选默认全部；忽略并覆盖旧缓存中的币种字段。
- 不再将当前展示币种或接口解析出的原币写入筛选缓存。
- 页面内仍可明确选择原币核对；原币下的“全部币种”选项切回人民币，完整汇总跨币种数据。
- 重新选择同一个店铺/分组/平台范围也会清除旧原币和汇率，避免“全部”值未变化时残留隐藏筛选。
- 总览、明细、对账、费用、广告、大屏及导出共用同一逻辑。

## 验证

`test-finance-default-currency-ui.mjs` 覆盖两种旧 MYR 缓存、七个报表入口、月份保留、跨国汇总、显式原币选择、重新选择全部及一致的导出条件。

既有 `scope-currency`、`filter-retention`、`operating-currency`、`query-speed`、`order-dates-search` 五组前端回归全部通过。没有改变账单日期、收入成本公式或后台同步。

发布脚本：`scripts/release-finance-default-all.py`。仅覆盖线上 `finance-workspace.js`、`index.html` 及压缩版本，入口版本为 `20261029-default-all-1`；保留后端、数据库、同步工作者和容器配置。
