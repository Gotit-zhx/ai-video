# 模板配置：参考图驱动的服装结构建模

2026-09-11。将实验室的服装结构拟合流程接入现有商品与印花模板，而非嵌入 localhost:8769 演示页面。

## 使用

进入「模板配置 → 商品与印花模板配置」，上传正面/背面纯色商品底图。原图已无印花时可直接使用，否则沿用项目现有去印花流程。可按「正面、背面、左侧、右侧」补充各面的底图。

点击「生成 3D 模型」，完成后可旋转、缩放、切换面向和白色线框。模板名称旁的「保存新版本」将模型、来源图、印花位置及检测报告一并保存；「读取模板」可恢复。

当前基础结构支持短袖与斜肩上衣。对能识别出彩色外衣、灰色单肩带及灰色内层下摆的双层上衣，会分别创建衣片、内层和肩带网格；这不是通用服装结构识别。帽子、裤子、多层复杂叠穿等不在当前支持范围。纯色背景分割失败会显示失败原因。

## 计算与判断

- 浏览器读取已归档的同源底图。利用边缘背景连通分割和主体连通块，拒绝空图、裁切和明显多主体。
- 在有领口、袖口、下摆开口及胸背支撑的结构库中选择基础网格，再作有界拟合。普通短袖、此前灰色斜肩款先验、短袖连肩衣片使用不同结构。分层分支直接用外衣轮廓生成前后衣片，按侧面约束建立厚度与袖口，再添加内层与肩带；最终分数重新栅格化完整网格对完整参考轮廓计算，不沿用外衣单独的分数。
- 衣身宽度的变化限制在合理范围；深度以少量平滑控制量调整，避免先前无限制分层拟合造成的塌陷和鼓包。没有侧面图时厚度采用预设，并明确提示。
- 逐面计算网格实际投影与参考轮廓的 IoU，以及 P95 边界距离。报告目标为 IoU≥0.95 且 P95≤参考框对角线的1.5%。缺少方向不计分，未全部通过不标记全方向达标。
- 报告是当前参考图上的拟合误差，并非独立实物验证；AI 补充视图仍属于推测参考，轮廓高分不代表褶皱、材质、隐藏结构或尺寸准确。
- 检查有限顶点、有效三角面、边拓扑、四个开口、深度。尚未执行完整自交检测或物理布料模拟。
- 粗模计算在浏览器本地执行，3D 渲染使用 WebGL。无额外生图调用，无 Python 临时服务依赖。补充参考图的生图耗时另外计算。

## 保存与故障处理

配置新增可选 reconstruction，包含算法版本、网格、来源底图 hash 和报告。继续使用原 config_json，无数据库迁移。旧模板不含该字段时仍正常读取。

后端验证来源 hash 与当前底图完全相同、坐标有限且在范围内、面索引有效、三角面非退化，并限制模型/报告大小。浏览器提供的分数不被视为服务端认证；productionReady 仍为 false。

更换/移除底图会清除旧模型；取消、切换公司或切换模板会中止当前任务并忽略迟到结果。重建失败保留此前模型。生成期间阻止保存尚未完成的模型。

印花预览投射到真实粗模表面，并依据来源图的主体框调整位置。它仍是位置预览，不是最终生产文件。

表中 KUOSE v2 是此前单层算法的历史基线，并非当前分层结果。新版已增加独立灰肩带及内层下摆，仍不能把轮廓分数解释为布料、接缝或隐藏结构的还原度。

参考对向一致性检查比较固定正交假设下相反相机的轮廓，可揭示明显不一致；它不能识别所有前面到侧面的肩高、材质及隐藏结构矛盾，因此仍须按统一的结构约束检查生成结果。

实际编辑器浏览器测试使用真实图片读取与拟合、内存模拟的模板保存接口。已验证显示、生成、取消、恢复模型、源失效、线框及390px布局。没有把模拟的保存声称为用户登录会话中的真实数据库保存；后者的配置往返由Java测试覆盖。本次独立登录页仍需要用户登录。


## 本次 KUOSE 参考与分层修复

用户要求本次拟合全部使用同一组 AI 参考。`output/garment-kuose-20260911/v4/` 的正、背、左、右均由同一张生成图裁切，原始商品照片不作为正面拟合掩码；原图用于核对款式与比例。v1/v2/v3、原图正面诊断模型均保留在实验记录中，不混入最终参考集。

v4 使用项目现有 gpt-image-2 能力、原图与上一版完整视图集定点修改，耗时 59.1 秒。它保留黄灰双层、斜领、单灰肩带和正确侧面胸前方向，但并未完全通过一致性校验：正背宽高比例仍偏宽，侧灰肩带比黄色高肩略高，各格缩放不完全相同。`v4/consistency-review.json` 将它标为实验参考，不能当作真实多视角照片，也不承诺四面达到目标。

新版分层几何按外衣实际横截面向内收，降低内层穿透；内层下摆跟随外层斜摆，中心保持空腔。肩带为有限宽度的薄带，使用可见带宽与中心线斜率，而不是肩带整个包围框或最高单像素；它的前后隐藏连接仍为推测。对前领口的遮挡检查排除透过领口看到的后衣片，避免错误地将前肩带挤到背面。

提示词只定义一套物理结构和穿者坐标，再指定四个相机；比例约束只施加于正背，避免同时要求侧面具有相同衣身宽度。提示词单元测试也拒绝互相矛盾的方向覆盖。生成图的实际检查仍不可省略，提示词正确不代表输出必定遵守。

目前模板内的「生成 3D 模型」对已保存参考在本机浏览器建模；本次四面 AI 补图由项目生图脚本调用，不是点击这个按钮会自动生成四面图。白色线框、灰模及原材色预览均可切换。


## 衣片网格实验与验收原则

同组 v4 参考暴露出旧结构的限制：大圆袖在侧面与领口重叠，外轮廓检测并不能发现这个问题。新增 `garment-armhole-detection.js` 检查侧面同色材质中的孤立暗椭圆，记录图像上的袖腔位置。当前左右袖腔高度约为外衣高度的 28.5% / 28.8%；该暗部测量不是对隐藏结构的认证。

`garment-panels.js` 试验由参考外轮廓生成前后裁片，保留领口、袖口和下摆。耳切后的长窄三角面会带来放射状假折痕，不能靠增加细分数量解决；因此在赋予深度前翻转内部边、均匀分布内部顶点，保持边界与开口。每次修改同时看前、后、两侧、斜角、灰模和白色线框。出现假折痕的高 IoU 候选同样不予采用。

所有侧面比较保留真实开口。严格正交侧视可能透过两侧对齐袖口，而 AI 参考画的是不透明暗袖腔；不得封住实际袖口只为提高分数。固定 90° 比较与任何相机姿态估计必须分开报告，不更换相机后沿用旧的检测含义。
