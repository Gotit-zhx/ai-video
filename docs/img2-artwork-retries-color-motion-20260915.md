# IMG2.0 透明印花重试与 SKU 取色动效（2026-09-15）

## 模型与输出

批量印花提取、印花裂变，以及示例页的 `PRINT_EXTRACT` / `PRINT_VARIANT`，专用 IMG2.0（`gpt-image-2` 及已确认的 `gpt-image-2-2026-04-21` 快照）。只选择当前公司的有效图片配置，保留该配置自己的地址、凭据和模型身份，不借用其他模型的配置，不回退 Grok。缺少可用配置时在提交前停止并说明原因。

请求明确指定原生透明 PNG；结果仍检查真实文件格式、alpha、可见印花与边缘连通的透明画布。白底 JPEG、不透明 PNG、空透明图等不能直接进入套版，也不会通过本地抠底冒充原生透明结果。

## 批量重试与计次

- 同一张逻辑印花最多 **3 次总尝试，包含首次**。只有已确认可重试的服务商拒绝、已归档的不合格透明图片，或已保存原始响应的明确坏图，才创建下一次尝试。认证、模型能力、请求配置、内容或版权限制等问题直接明确停止。
- 每次尝试固定来源版本、参考图、提示词、模型配置及所属图案分组，使用独立且稳定的请求键。旧尝试标记 `RETRIED`，保留原响应及已归档图片；已完成的其他印花不会重生成。
- 新批次在原基础调用数上，为每张需要生成的印花增加 2 次预留空间。只扩大印花的调用上限，商品底图和各 SKU 颜色照片不乘以 3；单批总上限仍为 1000。旧批次预算不自动扩容，重放启动请求复用原预算。
- 新尝试在同一事务内检查执行租约、暂停状态、失败记录、完整重试链和剩余预算，再创建任务。重复恢复复用已持久化的后继任务，后续提交复用同一次预算预留。
- 透明印花运行时每个任务最多发送 **1 次供应商 POST**，关闭内部并发、明确拒绝和网络重试，也不切换备用模型。批量的 3 次上限由 Java 任务与预算统一管理，避免两层重试叠加。
- `SUBMITTING`、`UNKNOWN` 或待归档结果不会触发新的生图尝试。连接中断、响应超时、下载失败或存储失败保留原请求，不能当作“未生成”重新付费提交。第三次仍失败、预算耗尽或无法确认结果时，给出具体停止原因。

自动重试限于对应的 `EXTRACT` / `VARIATE` 阶段；已经进入套版、复核或发布的旧素材不通过回退阶段替换。**本轮没有重新生成或改写已发布的狐狸草稿及其图片。**

## 示例与普通商品照片

示例页透明印花每次明确生成请求只尝试一次，不加入批量三次重试链；同一请求重复读取或恢复不新增模型调用。商品照片、去印花底图和其他普通图片保留原有模型选择及恢复逻辑，不受透明印花专用路由与计次规则影响。

## 动效与验证
