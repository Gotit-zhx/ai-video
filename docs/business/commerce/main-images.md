# 主图风格与逐图进度

核对日期：2026-11-05。本文合并原主图分析进度、工作流详情进度两份微说明，保留当前操作和恢复边界。早期测试数字、镜像和单个用户失败任务不作为当前系统状态。

## 使用

主图模板支持按顺序上传 1–9 张参考海报，分析商品区域、布局、字体、配色、背景、光线、装饰与可复用提示。批量上传默认不选择模板，因而不额外发起主图生成；显式选择后按模板图片逐张生成和检查。

工作流结果与当前模板版本关联。修改模板会使相应未完成槽位重新核对；发布前检查当前素材，不能把旧模板结果直接当作新结果。无商品的信息页可按既有策略保留原图，不代表跳过所有商品身份检查。

采集原图、SKU 图、描述、尺码图和目标店铺设置继续分别保存。生成及复核的真实效果仍需具体商品样本验收，不能以模板分析成功或模拟服务通过替代。

## 进度含义

- 文件上传用实际传输字节；传输后的服务端校验/保存单独显示等待与耗时。
- 队列中的图保持排队，工作器开始才变成分析/生成中。分析进度来自 Pi Agent SDK 的等待、输出、验证事件，显示实际字符数和经过时间，不显示推理原文，也不编造百分比。
- 商品详情、发布弹窗和批量历史共享逐图状态：等待、排队、生成、保存、复核、修正、完成、保留原图、失败或停止。任务结束后未完成图片不能继续显示活动动画。
- 读取进度不调用模型、不自动重试、不读取图片正文，也不返回凭据、供应商响应或推理文本。刷新应保留已加载图片及当前输入，旧请求不能覆盖新公司/模板的状态。

## 失败与恢复

维护窗口会暂停领取上传和生图工作；维护标记移除后，原有定时工作器必须自动继续轮询。维护检查只包裹业务回调，不能跳过调度器自身的 Future 执行，否则下一轮定时任务也会消失。恢复时保留原工作流、图片任务和幂等身份，不靠重新上传或重置任务状态恢复队列。

批量页面的“已自动重试”记录可能来自进度读取/同步，不能据此判断模型已实际调用。应结合工作流领取次数、当前步骤和逐图任务是否创建核对，见[定时上传恢复修复](../../releases/commerce/upload-scheduler-recovery-20261107.md)。

分析调用的当前默认边界见 `services/pi-runtime/src/product-main-image-style.js`：首个有效输出等待 180 秒，输出后的空闲上限 90 秒，总上限 240 秒；空事件和页面进度心跳不延长截止时间。SDK 自动重试关闭，不能把响应未知当作未调用后重新提交。

已有失败图片使用对应重试入口，不要求重新上传整套参考；重试应沿用明确请求身份及原已保存资料。未知生成结果优先查询原操作，已收到但未归档的结果只恢复归档。具体持久重试限额以当前服务实现为准，不按手工修改状态绕过。
