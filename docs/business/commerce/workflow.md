# 商品采集与创作发布工作流

核对日期：2026-11-05。本文是业务与开发共同使用的当前入口，取代初版绑定码设计和早期“批次自动执行尚未接通”的阶段待办。具体外部平台规则与验收仍以对应记录为准。

## 从采集到上传

1. 在[采集扩展](../../../apps/browser-extension/README.md)登录平台账号，从当前 Shopee / TikTok Shop 商品页采集。插件读取第一方页面与商品数据，不传递商城 Cookie 或代替官方店铺授权。
2. 在商品资料中检查标题、原价/售价、商家 SKU、颜色/尺码、详情图、视频和尺码图。完整性不足或字段不一致时先核对，不生成猜测的 SKU 组合。
3. 根据需要发起图片处理或选择[主图风格](main-images.md)。采集原图、SKU 图及已有结果各自保留；生成失败与保存失败分别处理。
4. 在商品列表批量上传入口选择商品及目标店铺，核对目标平台的类目、属性、仓库、物流、库存、价格和尺码图。上传可只选一件商品。
5. 确认后提交持久化发布工作流，在批量历史及商品详情查看逐件结果。关闭弹窗或刷新不代表远端任务取消；提交结果未知时先核查原请求。

商品运营店铺与财务店铺分别管理。插件凭证用于采集；官方发布凭证在服务器加密保存。新环境默认保持 Dry Run，真实发布受提供方、live 开关、用户权限、店铺授权及必填校验共同控制。参见[官方集成](official-shop-integration.md)、[必填字段](marketplace-required-fields.md)和[接口导航](../../guides/api.md)。

## 模板裂变批次

需要创作裂变时，选择来源、模板、款式和目标店铺，再固定启动配置。执行实例保存阶段、子任务、模型调用次数、已收到结果及恢复检查点；采集、提取、裂变、套版、复核和发布的推进以真实状态为依据。仅创作批次保留不上架边界。

`CommerceBatchLaunchService`、`CommerceBatchExecutionService`、`CommerceBatchExecutionWorker` 和对应 `CommerceBatch*` 服务负责批次启动及执行。早期设计中关于金额预算结算、关键词市场数据、广告测款和完整生命周期的计划，不能因批次已能执行就视为全部实现；具体范围以源码与独立验收为准。

暂停只停止新工作，不宣称撤销在途模型请求；取消仍保留已生成结果和已发生调用。结果未知不能自动重新付费或重复创建商品；已有模型结果的归档恢复不应触发新的生成。重复启动、刷新及恢复使用原执行与幂等标识。

## 开发时核对

主要代码在 `src/main/java/com/yingdao/aicommerce/product/`、`shop/`、`frontend/commerce-*.js`、`frontend/product-bulk-*.js` 与 `services/pi-runtime/src/`。新增/重命名静态资源时检查 Dockerfile 清单和页面引用；本地源码挂载不代表发布镜像已完整打包。

修改后检查企业与店铺范围、来源版本、模板变更、SKU/价格/库存、原图保留、重复提交、未知结果、单项失败及重启恢复。批次调用次数上限不等同已完成金额预算核算，模拟服务通过也不等于已通过真实图片保真或官方上架验收。

当前 SKU 命名及上传款号规则见[共享图案规则](../../sku-shared-cost-total-20261104.md)。其余历史实现、样本验收及修复见[电商发布记录](../../releases/README.md#电商与图片)。
