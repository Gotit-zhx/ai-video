# 广告费用统计与广告分析

更新日期：2026-11-12。本页记录当前源码的广告业务口径与采集边界，接口权限、历史回补及实际运行状态另查对应现场回执。历史数据质量核对见[修复记录](../../releases/finance/finance-ad-data-quality-20261110.md)，既有统计与广告通道记录分别见[统计记录](../../releases/finance/finance-advertising-20261106.md)、[连接记录](../../releases/finance/finance-ad-connection-acceptance-20261107.md)；历史结论不能替代本轮权限及运行核对。

## 费用口径

页面与导出统一使用以下三个金额名称，不能将不同口径的合计相加：

| 名称 | 业务含义 |
| --- | --- |
| 广告费用（已入账） | 平台账单广告费（含广告佣金）与普通独立广告报表或历史导入的 `AD` 费用，沿用既有经营及利润口径。 |
| 广告消耗（投放报表） | 投放三表中的来源消耗合计，包括按既有重叠规则保留的投放报表及资金消耗报表；不表示已入账或全媒体数据已完整。 |
| 净广告消耗 | 来源明确提供的不含广告赠款、优惠券的净额，或资金报表中均已明确的现金与授信之和；不等于现金付款。 |

财务总览头部「广告费用（已入账）」按所选时间范围汇总 **平台账单广告费（含广告佣金）+ 普通独立广告费用**。公司、分组、平台、店铺及币种筛选继续生效，不受明细分页影响。

| 来源 | 统计方式 |
| --- | --- |
| 平台账单广告费 | 已入库 `FEE` 中明确的广告费：`pay_per_sale` / 成交广告费、`gmv_max_ad_fee_amount` / GMV Max 广告费用、`smart_promotion_fee_amount` / 智能推广费用；兼容原字段路径和中文类别 |
| 其中：广告佣金 | 按业务确认，将 `affiliate_ads_commission_amount` / 达人广告佣金、`tap_shop_ads_commission` / 合作伙伴店铺广告佣金纳入平台账单广告费。账务核对表、分组及店铺明细显示「其中广告佣金」，费用构成继续按两类分别列示；其中项不再与账单费用重复相加 |
| 独立广告消耗 | 已同步账户报表和导入的 `AD` 记录；沿用现有来源幂等和重复接入限制 |
| GMV Max 专项 | 自动按官方店铺读取 `AD_GMV`，在分组/店铺及专项分析中单列消耗、归因收入、SKU 订单及归因 ROI；与普通报表、账单的覆盖关系待核对，不直接相加 |

普通报表不保证覆盖 GMV Max，不能把专项固定解释成普通报表的子集。当前合计表示已入账费用，不代表已完整核对所有媒体消耗；无法证明跨来源覆盖关系时，保留来源及待核对状态，不按同日同金额猜测去重，不重复扣利润。

广告充值、账户资金划转、无法拆分的「广告充值或技术支持费」混合字段、优惠券和普通达人/合作伙伴佣金不能仅凭名称当作广告费用。`GMV_PAYMENT_FOR_TIKTOK_ADS` 支付调整也不能代替对应日期的投放消耗报表。新平台字段须核对含义后显式加入分类。

广告佣金是广告带来的成交佣金，与广告账户的媒体投放消耗分项展示。字段含义参考 TikTok 官方《About the affiliate creative commission》（2026 年 3 月更新），业务在 2026-11-06 明确要求将两类广告佣金纳入广告卡片；普通达人佣金仍按原平台费用分类。

平台账单按官方结算费用日期，独立广告按账户报表或导入费用日期统计；不改按关联订单的首次结算日期。负向返还保留符号。原币按选定币种统计；人民币按每笔已确认业务日的历史参考率换算后汇总，同一查询与导出沿用同一历史快照，原始账目保持原币。

分组经营明细按店铺当前类目归属汇总，店铺经营明细逐店汇总；仅有当期广告费用的店铺也显示。未分配账户费用单列，在全部范围及「未分组」中可见，不强摊到其他店铺或类别。

## 总览与已入账核对的数据来源

| 页面项目 | 原始接口与字段 | 展示关系 |
| --- | --- | --- |
| TikTok 账单广告费 | `GET /finance/202501/statements/{statement_id}/statement_transactions` 的 `fee_tax_breakdown` 中明确广告费叶子；平台有符号金额取反后作为费用 | 进入「广告费用（已入账）」 |
| 其中广告佣金 | 同一接口的 `affiliate_ads_commission_amount`、`tap_shop_ads_commission` | 已包含在「广告费用（已入账）」中，不能再次相加；只有佣金类费用时与已入账合计相等 |
| Shopee 结算广告费 | `GET /api/v2/payment/get_income_detail` 确认实际释放日期，`get_escrow_detail` / 批量拆分的 `order_income.pay_per_sale` 提供按成交计费广告费 | 保留原符号，进入「广告费用（已入账）」；普通联盟佣金和充值/技术支持混合费不替代广告消耗 |
| 普通独立广告 | 广告账户报表或合规异常补录的 `AD` 事实 | 进入「广告费用（已入账）」，与账单广告佣金分项；不把空返回视为零 |
| GMV Max 报表 | TikTok Marketing `/gmv_max/report/get/` 的实际 `cost` | 总览卡片另列说明，分组及店铺表有独立「GMV Max 报表消耗（待核对）」列，不叠加到已入账广告合计或利润 |

已入账费用与单列 GMV Max 按相同期间、店铺归属和历史汇率日期规则展示；这不代表结算广告费与投放账户报表已经完成跨来源对账。没有已入账记录的单元格继续显示缺失状态；GMV Max 有记录时可从独立列查看，不因已入账列为空而隐藏。

Shopee 独立投放已于 2026-11-12 启用独立 Ads Service CPC 日报采集；正式配置可用，两家已授权店铺已完成近 90 天 CPC 日报回补，其余店铺仍需完成新应用授权。历史权限问题如下。官方提供 CPC 日报/小时报表及独立 GMS 报表，但需要应用具备相应 Ads 接口权限；普通店铺订单、结算授权不等于拥有该权限。2026-11-10 对现用应用在 PH/TH/MY 做有界只读探测，CPC 和 GMS 均返回 HTTP 403 / `error_api_permission`。该历史结果的 Shopee 费用范围是已入库结算广告费及已有导入，不能宣称覆盖全量投放，也不能将空白补成零。当前独立通道配置与边界见[正式激活回执](../../releases/finance/finance-shopee-ads-activation-20261112.md)；不把另一应用的密钥与原应用令牌混配。

## 利润与完整性

广告展示保留全部符合筛选的广告费用，包括原始账单中已标记订单的来源。利润继续沿用刷单排除、平台净结算、商品和贴单成本规则。

计入经营范围的账单广告费及广告佣金已随平台净结算及费用处理，利润只额外扣减独立 `AD` 消耗；不能再整体扣减广告卡片合计，也不能再扣减「其中广告佣金」。说明明确区分这两个来源，未改变原始记录或金额计算公式。

缺失金额显示已知部分；实际零值保留。没有费用记录时金额不补成 0；店铺表另区分未能归属、自动补齐、同步异常和 GMV Max 来源。覆盖表按所选日期记录接口成功返回，包括空报表，并显示返回记录数。空列表显示「接口未返回记录」，金额为「—」，不证明没有实际消耗；确有返回记录且净额为零时显示「报表合计为0」，不声称每条记录都是零。旧响应缺少记录数时显示「返回记录数未核实」，保留已知非零金额。部分日期继续标示部分覆盖；当天和近期数据仍可能延迟。未返回曝光、点击和转化时保持未知，必需指标缺失或分母为零时，比率显示「—」。账户状态读取失败时保留已入库费用统计并提示刷新。

## 店铺广告消耗工作台

主视图维护「分组广告消耗」「店铺广告消耗」「店铺消耗明细」三张表，TikTok 和 Shopee 使用同一组织形式。三张主表分别占满一行，窄屏时仅表格内部横向滚动，不把整张卡片压缩成窄列。三表均保留现金消耗、信用额度消耗、广告费用赠款消耗、「广告消耗（投放报表）」及「净广告消耗」；推广系列、账户及类型保留为追溯依据。明细前置店铺、币种和金额，辅助身份字段放到右侧。没有取得数据的店铺也保留未知状态，不填写零。

顶部金额卡按展示币种分组，每个币种各有现金、授信、赠款、投放报表消耗和净广告消耗五项；原币视图不把不同币种相加。选择人民币时，先逐行按报表业务日换算，再形成对应卡片与三表合计。

- 来源 ID 不等于独占一家店铺：TikTok 使用广告账户 ID，Shopee 店铺范围报表使用真实平台店铺 ID。导入可选择已连接的相应来源，或直接填写平台 ID，无需先提供广告令牌；Shopee 不要求绑定一个 TikTok 账户。资金报表没有来源列时须补充来源身份，不能把文件名当作账户或店铺的可靠依据。
- TikTok 标准资金报表按「负数扣费」转为正数消耗；正数退回转为负数冲减，不用绝对值抹掉退款方向。Shopee/通用报表可选择正数消耗口径。三项均已知时必须与合计一致；源接口未提供的分项保持未知，不能从总消耗、净消耗、充值或余额推导现金/信用/赠款。
- 导入按同平台、账户、业务日期、币种、推广系列识别同一事实；可选类型列、文件名或名称变化不改变经济事实身份。同一身份金额冲突时整份事务拒绝发布；重复导入不重复累计。资金明细优先于同身份 API 系列行，账户总额与已取得系列明细不叠加，重叠来源保留在辅助核对区。来源覆盖不能直接宣称完整。
- 官方精确系列来源只对应一家店铺且金额完全相符时自动归属；Shopee 来源平台店铺 ID 精确对应唯一财务店铺时自动归店。可能跨店或不明确时先待分配。按原币核实每家店金额，支持部分分配，余款继续保留；不按名称、账户访问关系或销售额比例猜分。分配保存审计版本和来源金额指纹，原金额变化后必须重新核验。已明确核实的资金分配不被后到的自动匹配覆盖；清除人工分配后重新匹配。旧来源缺少账户身份且后来出现潜在 API 重叠时，明细保留并标记来源待核对，汇总仅显示可确认的已知部分。
- 日期、平台、原币先限制来源范围；店铺和分组在金额归属后筛选。原币视图分币种展示，人民币视图沿用同一历史汇率快照。系列/账户查询、归属状态及明细分页不改变三表期间汇总；导出包含全部查询页、三张表、账户资金核对及口径/历史汇率说明，长 ID 保持文本。
- 专门资金导入上限 12 MiB、20,000 行；来源查询及分配后的明细上限 50,000 条，超过须缩小范围，不发布截断合计。导入资金表独立存储，不自动写入旧 AD 利润流水；既有经营汇总和利润公式保留。

工作台与 V150 的历史实现边界见 [店铺广告消耗开发记录](../../releases/finance/finance-ad-spend-workspace-20261110.md)，布局调整另见 [布局修复记录](../../releases/finance/finance-ad-spend-layout-20261111.md)。这些记录不证明本轮 BC 资金权限或 Shopee Ads 权限已取得；当前运行基线以运维源码模式入口及现场状态为准，源码变更按[源码运维指南](../../guides/operations.md)在维护锁及安全点内生效，不要求 Candidate、标签或镜像发布。

## API 资金指标与净广告消耗

三张主表以「净广告消耗」表示来源明确提供的净额；现金、信用额度、广告赠款仍保留独立列。未知金额区分接口未拆分、接口未返回、报表未提供和业务日汇率缺失，不用零表示缺口。

| 来源 | 官方字段 | 展示含义与边界 |
| --- | --- | --- |
| TikTok GMV Max `/gmv_max/report/get/` | `cost`、`net_cost` | 计划及日粒度的总消耗、剔除广告赠款和优惠券后的净消耗。净消耗可能延迟 11 小时，不能标为现金付款。已存原始 `net_cost` 可直接读取，无需重新导入。 |
| TikTok 同步 BASIC `/report/integrated/get/` | `spend`、`billed_cost` | 普通投放总消耗、净消耗；两者均使用账户币种。BASIC 不替代 Shop 创建的 GMV Max 报表。 |
| 同一 BASIC 账户日报 | `cash_spend`、`voucher_spend` | 账户级现金消耗、赠券消耗；官方不支持将这两个指标直接用于系列、小时或终生粒度，可能延迟 24–48 小时。仅在相同实际账户日报来源展示，不复制到 GMV Max 系列或跨店金额。 |
| TikTok Business Center `/bc/account/cost/get/` | `amount`、`cash_amount`、`grant_amount`、`tax_amount` | 按单日筛选采集账户财务费用，来源为 `API_BC_COST`；分别保留总额、现金、广告赠款和独立预估税额。没有系列/店铺拆分，`credit_amount` 与 `net_amount` 保持未知；只进入账户级资金核对，不进入媒体投放三表或利润。 |
| Shopee CPC / GMS 投放报表 | `expense` | 店铺或推广计划广告消耗；所核对报表未提供现金、授信、赠款和排除优惠后的净消耗分项。接口权限不足与分项未开放是不同问题。 |
| 财务资金报表 | 现金、信用额度、广告费用赠款、合计 | 保留原分项；现金和授信均明确时，它们的和可作为该资金事实的不含赠款净消耗。退款及冲减保留方向。 |

当前采集使用 v1.3。补查 v2.0 的正式「Supported metrics for Ad Reports」页面，`cash_spend`、`voucher_spend` 仍明确仅支持账户级；同步接口的系列级示例与此限制不一致，不据该示例扩大可用粒度。v2.0 同步报表另将旧 GMV Max 报表类型列为弃用，不能凭普通 Ad Report 示例宣称已替代当前 GMV Max 专属报表。

`ad credit` 在净消耗定义中指赠款/优惠，不能译成授信消耗；`spend_credits` 是应用内花费积分转化次数，亦不能映射到财务信用额度金额。没有可靠接口分项就保留未知，不用 `cost - net_cost` 倒算现金、授信或实际赠款。

「账户级资金核对」默认为折叠区，不增加第四张经营主表。普通 BASIC 投放账户日报与 BC 资金费用按来源分别汇总，即使同一账户、日期、币种同时存在也不相加。BASIC 账户总额因与系列重叠被主表排除时，已取得的资金指标仍可核对；BC 资金费用始终排除在三张媒体主表之外，不重复加到「广告消耗（投放报表）」「广告费用（已入账）」或利润。预估税额按来源单列，不再次加进费用合计。

店铺/分组筛选只显示当前已可见来源相关或已明确配置专属店铺的账户，其完整账户金额不被解释为该店金额。BC 账户没有系列标识，不能用名称、账户访问关系、模糊关键词或销售比例归店；共享账户仍保留账户层级核对。明细搜索和分页不改变此期间核对范围。导出包含独立核对工作表及税额、净广告消耗和金额口径，长 ID 仍为文本。

人工分配仍只核实原资金字段；API 已知净消耗不能按合计分配比例自动拆给各店，也不能将整条净消耗复制给每个分配行。资金分配按已明确的现金与授信计算本行净消耗，否则标记「净消耗未分配」。新净额字段不加入旧资金指纹，避免仅补充可读信息就使原有人工分配失效。

## BC 账户日资金采集与权限

2026-11-11 本轮只读现场探测：28 个启用账户按实际令牌去重后为 1 组授权，`/bc/get/` 返回 `40001`，未取得可核对的 BC 资金明细。该结果不能解释为账户消费为零；现有 BASIC/GMV Max 数据继续保留，后续需要管理员补齐对应 BC 访问权限及财务角色并核对重新授权。

BC 发现使用公开 `/bc/get/`，令牌置于 `Access-Token` header；`page=1&page_size=50` 是完整合法的发现请求，不需要补传 `app_id`、`secret` 或广告账户 ID。费用使用 `/bc/account/cost/get/`，传入 BC ID 与相同 `filtering.start_date`、`filtering.end_date`，按广告账户时区取得一天的费用；`cost_list.advertiser_id` 只与本公司已连接账户做精确匹配，BC 汇总 `transaction_summary` 不复制给账户或店铺。

`amount`、`cash_amount`、`grant_amount`、`tax_amount` 按账户原币主单位读取，不擅自除以 100 或其他倍数。负数扣费转为正数消耗，正数退款转为负数冲减；金额按精确十进制读取、暂存与保存，缺失字段保留未知。税额是单独的预估税额，不能当作额外广告消耗。该接口没有独立授信消耗或净额字段，不能用现金、赠款、税额之间的差额补造 `credit_amount` 或 `net_amount`。

授信额度、已占用授信、可用余额、充值、资金转账和发票金额均不替代逐日消耗。公开 Payment Portfolio 的 `credit_line_allocation.used_amount` 是当前授信占用快照，没有逐日或系列维度；它不同于赠款 `ad credit`，也不在本次费用事实中折算为授信消耗。

BC 采集与 BASIC、GMV Max 各自执行、保存状态及退避，资金权限失败不阻塞媒体报表。相同公司、相同令牌的账户合并查询；单日全部已确认财务角色的 BC 及全部分页完成后，才事务发布该日费用。事实按公司、广告账户、业务日、币种唯一，BC 或令牌变化不增加金额；不同 BC 返回同一账户的金额不一致时保留旧数据并完整重查。分页不完整、费用行缺失或刷新为空时不擦除已有事实；明确返回的真实零值可以更新。

首次回补近 90 天，之后每小时近 7 天、每日近 31 天回查；当前日及近期费用仍可能延迟。`funding.returned_days` 只统计已返回账户费用记录的不同日期，`records` 只统计已保存记录数；它们不是请求成功覆盖天数，更不能证明现金、授信、赠款均已完整或没有记录的日期费用为零。财务店铺管理与账户核对区可展示独立资金状态；专属店铺永久删除会有界清理对应账户的 BC 暂存及费用，其他账户与共享令牌任务保留。

## Shopee 官方店铺 CPC 日报

Shopee 独立广告使用已经通过 Go Live 的 **Ads Service** 应用，与订单/结算 ERP 的密钥和店铺令牌分开保存。2026-11-12 已核对正式应用可用，公开签名预检和正式配置探针通过，接入源码已激活。店铺日报仍须由管理员完成新应用官方授权后取得；11 月 11 日的审核中状态保留在历史记录中。

服务端配置 `APP_SHOPEE_ADS_CREDENTIALS_FILE` 指向只读私有 properties 文件（格式见 `config/shopee-ads.properties.example`），包含 `live-enabled=true`、正式 `partner-id` 和 `partner-key`；私有文件须位于 Git 外且权限 `0600`，并核对真实应用挂载。未显式指定路径时读取固定挂载 `/run/heyi-finance-ads/shopee-ads.properties`，文件不存在或关闭时不发请求，不借用 ERP 凭据。`auth-base-url`、`api-base-url` 仅允许已支持的官方 HTTPS 域名；应用或地址变化会使旧一次性授权会话失效。财务店铺管理生成一次性独立授权链接，回调 `/api/v1/shop-authorizations/callback/shopee_ads` 校验公司、应用版本、有效期与单次使用；官方管理员授权后，按同公司 `external_shop_id` 精确匹配财务店铺。无唯一对应店铺时保留等待状态，不按名称猜测或创建重复店铺。

`GET /api/v2/ads/get_all_cpc_ads_daily_performance` 返回店铺每日 `date` 与 `expense`；请求使用 `dd-MM-yyyy`，本实现按日历月分窗，每次最多 30 个业务日（含首尾）；31 日月份拆分末日且不发送相同起止日期，最末单日用相邻日重叠请求。金额经签名客户端的精确十进制解析入库。首次回补近 90 天，优先上个完整月，再补本月和更早日期；已有检查点保持原窗口。每小时回查近 7 天、跨天回查近 31 天；应用共享请求间隔至少 5 秒，限流后保留原范围并共享退避。一天没有返回行不能补造为零，缺金额、重复/越界日期、warning 或刷新缺少已有事实日都拒绝整窗发布；平台明确返回的 0 可以更新旧值。

暂停或权限异常过久导致检查点超出六个月可读范围时，从当前可读范围的最早日期重新逐月回补到今天，保留仍可读取的未完成历史及所有已入库消耗。检查点持久记录不可读历史边界；完成可读窗口后显示“历史覆盖待核对”，过期范围内尚未入库的日期仍未知，后续回查也不消除该提示。恢复采集或重新授权不会将这类缺口视为零值或完整覆盖。

V154 独立保存 Ads 授权、共享令牌组租约和店铺日事实。原未应用的 V153 候选因现场已有成本输入安全迁移而改号，不编辑已应用的 V153。令牌组租约独立于单店暂停/删除；轮转结果可以保存给仍有效的兄弟授权，但不恢复已删除凭据，也不允许暂停店铺的晚返回写入日报。ERP 授权、原账单、`AD` 已入账流水和利润公式保持不变。

三张主表和导出复用同一来源 `API_SHOPEE_CPC`，业务日历史汇率按每条日报计算。相同公司、官方店铺、日期与币种的官方店铺总额优先于导入/旧 API 行，避免把系列明细再加到总额；原始导入保留。CPC 日报不提供现金、授信、赠款或净额拆分，对应字段继续未知；GMS 报表和 CPC 的覆盖关系尚无真实授权核对，不将它们相加，也不宣称已覆盖全部广告产品。

状态读取与管理接口为 `/api/v1/finance/shopee-ads`、`POST .../authorize`、`PUT .../{external_shop_id}`。写操作沿用财务管理权限、同源和公司校验；广告分析显示应用配置、授权、采集错误与覆盖边界。应用审批、正式配置和官方店铺授权是外部前置条件；本地合同与模拟测试不等于真实店铺金额已经补齐。

## 广告报表日历史换算

投放三表与账户资金核对先保留原币，再按每行广告报表业务日换算人民币；BASIC、GMV Max 使用报表日期，BC 使用单日费用查询对应的账户业务日，导入使用报表提供的业务日。平台账单广告费沿用已确认的真实费用或结算业务日，不用关联订单日期、人工归属月份锚点或当前行情替代。

历史参考率由 ECB 数据经 Frankfurter 获取，采用不晚于业务日的最近已公布参考率；周末及节假日使用相应前一公布日。先逐行转换，再汇总到币种卡、分组、店铺、明细及账户核对；不将整个历史期间乘以查询当天汇率。缺少业务日或对应币种的历史率时，换算金额保留未知或已知部分，不补零，也不改变原币金额与原币对账结论。

分页、筛选和导出沿用同一历史快照，补充尚未覆盖的日期不会重写已经冻结的业务日汇率。导出附「历史汇率」工作表，列出业务日、汇率公布日、原币、兑人民币参考率及来源，并在明细保留对应换算依据；参考换算不等于银行实际结汇金额。

## 广告授权与账户显示

广告账户只有在回调校验、授权码换取令牌、账户查询与原子保存全部成功后才会显示。失败的授权码不自动重放，须重新生成授权链接。令牌交换未给出账户编号时，自动调用 `/open_api/v1.3/oauth2/advertiser/get/` 补查；令牌位于 `Access-Token` header，query 仅传字符串 `app_id` 与 `secret`。平台拒绝和成功返回空账户分开处理，不能把查询失败解释成没有账户。

账户详情使用 TikTok 官方 `/open_api/v1.3/advertiser/info/`，请求字段为 `advertiser_id`、`name`、`currency`、`timezone`；返回的账户名称也从 `name` 读取。`advertiser_name` 不在此接口的字段白名单中，不能将其他账户列表接口的名称字段套用到详情接口。OAuth 回调与直接连接账户共用字段定义。

依据：[TikTok 官方 Get ad account details](https://business-api.tiktok.com/portal/docs?id=1739593083610113)，2026-11-06 核对请求字段白名单与响应示例。协议回归使用独立的官方字段约束，拒绝错误字段，不再让测试响应迁就实现中的错误。

授权回执使用固定、脱敏的分类：`DNS`、`NETWORK`、`TIMEOUT`、`TLS`、`PLATFORM`、`CALLBACK`、`CONFIGURATION`、`TOKEN_EXCHANGE`、`ACCOUNT_DISCOVERY`、`ACCOUNT_INFO`、`ACCOUNT_SAVE`。平台拒绝仅保留数值错误码；不保存原始异常、请求/响应、授权码、令牌或密钥，不新增持久日志。

财务店铺管理区分「公司尚无账户」和「账户被当前分组筛选隐藏」，提供「查看全部广告账户」。自动发现的多店账户可在各对应分组中看到；普通账户未归属总额仍在未分组中保留。仅凭店铺访问关系不会把普通账户所有费用绑定到该店。

连接修复过程见[修复历史](../../releases/finance/finance-ad-connection-repair-20261107.md)、[节点验证](../../releases/finance/finance-ad-vmess-validation-20261107.md)及[最终连接验收](../../releases/finance/finance-ad-connection-acceptance-20261107.md)。历史临时通道和旧失败回执不能作为当前连接状态；连接成功也不证明新报表读取权限或数据完整性。

## 自动获取与店铺归属

授权后后台自动调用 `/gmv_max/store/list/`，以同公司 TikTok 财务店铺 `external_shop_id` 精确匹配官方 `store_id`。不按名称模糊匹配，不更改 GMV Max 主投放账户。尚无财务店铺时仍读取有权限的报表，后续连接店铺自动重新归属，费用身份及金额不变。

普通报表和每个官方店铺的 GMV Max 报表分别保存 checkpoint、状态和退避；一处失败不阻塞其他来源。首次近 90 天，之后每小时近 7 天、每日近 31 天回查，使用广告账户时区。GMV Max 读取计划及日期维度，涵盖商品、直播和已删除计划；分页先暂存，完整窗口验证成功后事务发布，失败不清除上次可用数据。

当前主投放/可用标志不代表历史报表资格；已有关系的历史 GMV Max 继续读取和展示，不因当前 `is_gmv_max_available=false` 删除历史费用。仅专属单店账户适合直接绑定普通广告费用；多店账户不强摊费用，GMV Max 按官方店铺身份分别归属。

手动暂停是持久选择，重新授权更新凭据但不自动恢复暂停账户。暂停及显式恢复撤销旧租约，旧请求晚返回不得发布；未来退避继续保留。专属店铺的接口账户即使已暂停也阻止再导入同份广告费，恢复前再次检查导入冲突。明确充值、转账或未拆分混合字段不能导入为广告消耗，真实消耗返还仍保留负号。

完整窗口刷新如未返回已有事实日期的记录，保留该窗口原费用、覆盖及检查点，提示待核对并自动退避重试，不静默擦除已知费用。明确返回的零消耗记录仍可更新旧金额。初次空窗口只记录请求覆盖，不制造费用记录。已返回日期按完整分页报表更新，不按同金额猜测补齐计划。

管理员只负责平台必须的人为授权及确实无法自动解决的权限/店铺身份问题；无须逐次触发采集、手填 GMV Max 店铺 ID 或定期导入。尚未完成回补、普通报表无法确定店铺、跨来源费用重叠待核对时继续明确显示缺口，不宣称自动对账完成。

## 接口与实现

`GET /api/v1/finance/overview` 新增 `advertising`，返回合计、来源、分组、店铺、费用类别、趋势、投放指标及 GMV Max 统计。`commission` 是账单广告费中的广告佣金子集，在总报告和各分组/店铺下提供。

账单广告费明细使用 `/api/v1/finance/records?kind=FEE&advertisingOnly=true`，导出使用 `/api/v1/finance/export?view=FEE&advertisingOnly=true`。同一类别条件在分页前作用于计数和数据；导出覆盖全部查询页，保留原筛选、个人字段和冻结汇率。该参数拒绝其他类型；广告导出不附带无关结算对账表。

广告事实在原有日汇总扫描中、经营排除前保留，不重复扫描整个账本。共享快照按公司、分组和店铺同步裁剪广告事实，历史汇率快照缓存使用 `v19-historical-fx` 键空间。V148 提供媒体报表的店铺发现、独立进度、分页暂存和覆盖表，V151 保存历史汇率与冻结快照，V152 保存独立 BC 账户资金事实；凭据、完整请求/响应及原始异常不写入这些资金状态或诊断日志。

实现入口为 `FinanceAds`、`FinanceAdAutomation`、`FinanceAdBcApi`、`FinanceAdBcFunding`、`FinanceAdFunding`、`FinanceAdSpendService`、`FinanceAdSpendReport`、`FinanceAdSpendController`、`FinanceAdvertisingReport`、`FinanceFx` 与 `FinanceFxHistory`，页面为 `frontend/finance-workspace.js` 和 `frontend/finance-ad-spend.js`。V152 独立保存 BC 同步进度、分页暂存及账户费用，不写旧 `AD` 流水。`GET /api/v1/finance/ads` 可携带 `start` / `end` 读取期间覆盖；账户响应保留 `stores`、`streams`、`coverage`、`requestedDays`，另提供独立 `funding` 状态与返回记录统计。

## 验证入口与边界

Java 入口包括 `FinanceAdvertisingReportTest`、`FinanceAdvertisingQueryTest`、`FinanceAdBcApiTest`、`FinanceAdBcFundingScheduleTest`、`FinanceAdBcFundingIntegrationTest`、`MarketplaceHttpExactMoneyTest`；页面入口为 `node scripts/qa/test-finance-advertising-ui.mjs` 与 `node scripts/qa/test-finance-ad-spend-ui.mjs`。UI 使用合成数据，覆盖日期/币种/分组/店铺、零值和缺失值、分页、编号查询、导出、只读权限、账户异常及旧响应隔离。数据库集成只连接可销毁的隔离测试库；测试入口的存在不代表真实 BC 权限、运行生效或完整资金对账已核实。

以下为历史回执，不代表本轮 BC 权限及运行状态：11 月 6 日统计核对见[当时验收](../../history/finance-advertising-development-20261106.md)，11 月 9 日隔离数据库和模拟平台回归见[自动化验收](../../history/finance-ad-automation-20261109.md)。2026-11-10 已持共享双锁将核对扩大至全部 56 个账户与店铺组合：5 组有非零的 10 月 GMV Max，3 组原历史回补尚未完成；使用完整计划分页与逐日 overview 对照后补入 9,007 条真实缺失明细，最终授权范围内的月报金额一致。未以当前主账户或可投放标志排除历史；当时店铺发现仍仅关联两家财务店铺。
