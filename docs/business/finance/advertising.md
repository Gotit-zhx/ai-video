# 广告费用统计与广告分析

更新日期：2026-11-10。广告自动化已进入生产；本次数据质量修复和真实只读核对见[修复验收](../../releases/finance/finance-ad-data-quality-20261110.md)。实际激活版本以正式 Release 和服务器回执为准。既有统计发布见[发布验收](../../releases/finance/finance-advertising-20261106.md)，广告通道修复见[连接验收](../../releases/finance/finance-ad-connection-acceptance-20261107.md)。

## 费用口径

财务总览头部「广告费用」按所选时间范围汇总 **平台账单广告费（含广告佣金）+ 独立广告消耗**。公司、分组、平台、店铺及币种筛选继续生效，不受明细分页影响。

| 来源 | 统计方式 |
| --- | --- |
| 平台账单广告费 | 已入库 `FEE` 中明确的广告费：`pay_per_sale` / 成交广告费、`gmv_max_ad_fee_amount` / GMV Max 广告费用、`smart_promotion_fee_amount` / 智能推广费用；兼容原字段路径和中文类别 |
| 其中：广告佣金 | 按业务确认，将 `affiliate_ads_commission_amount` / 达人广告佣金、`tap_shop_ads_commission` / 合作伙伴店铺广告佣金纳入平台账单广告费。卡片、分组及店铺明细显示「其中广告佣金」，费用构成继续按两类分别列示；其中项不再与账单费用重复相加 |
| 独立广告消耗 | 已同步账户报表和导入的 `AD` 记录；沿用现有来源幂等和重复接入限制 |
| GMV Max 专项 | 自动按官方店铺读取 `AD_GMV`，在分组/店铺及专项分析中单列消耗、归因收入、SKU 订单及归因 ROI；与普通报表、账单的覆盖关系待核对，不直接相加 |

普通报表不保证覆盖 GMV Max，不能把专项固定解释成普通报表的子集。当前合计表示已入账费用，不代表已完整核对所有媒体消耗；无法证明跨来源覆盖关系时，保留来源及待核对状态，不按同日同金额猜测去重，不重复扣利润。

广告充值、账户资金划转、无法拆分的「广告充值或技术支持费」混合字段、优惠券和普通达人/合作伙伴佣金不能仅凭名称当作广告费用。`GMV_PAYMENT_FOR_TIKTOK_ADS` 支付调整也不能代替对应日期的投放消耗报表。新平台字段须核对含义后显式加入分类。

广告佣金是广告带来的成交佣金，与广告账户的媒体投放消耗分项展示。字段含义参考 TikTok 官方《About the affiliate creative commission》（2026 年 3 月更新），业务在 2026-11-06 明确要求将两类广告佣金纳入广告卡片；普通达人佣金仍按原平台费用分类。

平台账单按官方结算费用日期，独立广告按账户报表或导入费用日期统计；不改按关联订单的首次结算日期。负向返还保留符号。原币按选定币种统计，人民币使用同一参考汇率快照，原始账目保持原币。

分组经营明细按店铺当前类目归属汇总，店铺经营明细逐店汇总；仅有当期广告费用的店铺也显示。未分配账户费用单列，在全部范围及「未分组」中可见，不强摊到其他店铺或类别。

## 总览两列的数据来源

| 页面项目 | 原始接口与字段 | 展示关系 |
| --- | --- | --- |
| TikTok 账单广告费 | `GET /finance/202501/statements/{statement_id}/statement_transactions` 的 `fee_tax_breakdown` 中明确广告费叶子；平台有符号金额取反后作为费用 | 进入「广告费用」 |
| 其中广告佣金 | 同一接口的 `affiliate_ads_commission_amount`、`tap_shop_ads_commission` | 已包含在「广告费用」中，不能再次相加；只有佣金类费用时两列相等 |
| Shopee 结算广告费 | `GET /api/v2/payment/get_income_detail` 确认实际释放日期，`get_escrow_detail` / 批量拆分的 `order_income.pay_per_sale` 提供按成交计费广告费 | 保留原符号，进入「广告费用」；普通联盟佣金和充值/技术支持混合费不替代广告消耗 |
| 普通独立广告 | 广告账户报表或合规异常补录的 `AD` 事实 | 进入「广告费用」，与账单广告佣金分项；不把空返回视为零 |
| GMV Max 报表 | TikTok Marketing `/gmv_max/report/get/` 的实际 `cost` | 总览卡片另列说明，分组及店铺表有独立「GMV Max 报表消耗（待核对）」列，不叠加到已入账广告合计或利润 |

两列按相同期间、店铺归属和同一参考汇率展示；这不代表结算广告费与投放账户报表已经完成跨来源对账。没有已入账记录的单元格继续显示缺失状态；GMV Max 有记录时可从独立列查看，不因已入账列为空而隐藏。

Shopee 独立投放自动采集尚未接入。官方提供 CPC 日报/小时报表及独立 GMS 报表，但需要应用具备相应 Ads 接口权限；普通店铺订单、结算授权不等于拥有该权限。2026-11-10 对现用应用在 PH/TH/MY 做有界只读探测，CPC 和 GMS 均返回 HTTP 403 / `error_api_permission`。因此当前 Shopee 费用范围是已入库结算广告费及已有导入，不能宣称覆盖全量投放，也不能将空白补成零。应用管理员需核对 Ads 权限或提供另一款已获权应用的服务端配置；不把另一应用的密钥与原应用令牌混配。

## 利润与完整性

广告展示保留全部符合筛选的广告费用，包括原始账单中已标记订单的来源。利润继续沿用刷单排除、平台净结算、商品和贴单成本规则。

计入经营范围的账单广告费及广告佣金已随平台净结算及费用处理，利润只额外扣减独立 `AD` 消耗；不能再整体扣减广告卡片合计，也不能再扣减「其中广告佣金」。说明明确区分这两个来源，未改变原始记录或金额计算公式。

缺失金额显示已知部分；实际零值保留。没有费用记录时金额不补成 0；店铺表另区分未能归属、自动补齐、同步异常和 GMV Max 来源。覆盖表按所选日期记录接口成功返回，包括空报表，并显示返回记录数。空列表显示「接口未返回记录」，金额为「—」，不证明没有实际消耗；确有返回记录且净额为零时显示「报表合计为0」，不声称每条记录都是零。旧响应缺少记录数时显示「返回记录数未核实」，保留已知非零金额。部分日期继续标示部分覆盖；当天和近期数据仍可能延迟。未返回曝光、点击和转化时保持未知，必需指标缺失或分母为零时，比率显示「—」。账户状态读取失败时保留已入库费用统计并提示刷新。

## 广告分析页面

- 四张卡片：总广告费、平台账单广告费、独立广告消耗、未分配费用；账单卡片另列其中广告佣金。普通独立明细页签明确命名「普通独立广告消耗明细」，避免将此单一来源空列表误认为全部广告费为空。
- 趋势图分别展示合计及两个来源，各来源缺少记录的日期留空，不能因另一个来源有费用就将此来源补成 0。
- 费用构成、分组广告消耗和店铺广告消耗使用相同期间统计，支持按分组和店铺下钻。分组及店铺表单列广告佣金和 GMV Max 消耗；仅有 GMV Max 的店铺也展示，已入账合计不叠加待核对来源。
- 投放概览包括曝光、点击、转化、CTR、CPC、CPM、CPA 和点击转化率。比率按汇总分子/分母计算，不平均各行比率；成本指标仅使用有相应投放指标口径的独立广告报表，不将账单广告费混入 CPC。
- GMV Max 专项独立展示；归因收入不作为平台结算收入或利润。
- 同步区展示自动识别的一对多店铺关系、币种/时区、逐来源状态、所选期间覆盖天数、返回记录数和原币报表消耗；当前筛选下的店铺关系按财务店铺去重。发现待完成或失败时保留未知状态，不能断言未授权。普通 BASIC 不包含部分从 TikTok Shop 创建的 GMV Max，其空返回不能代替专项报表结论。授权和账户管理仍在财务店铺管理页完成；人工导入在「异常补录」中作为 API 无法提供数据时的兜底。
- 独立广告、平台账单广告费和 GMV Max 各有明细、字段设置、编号查询、分页和导出。编号查询仅过滤明细，卡片按完整日期及分组/店铺范围汇总。

## 广告授权与账户显示

广告账户只有在回调校验、授权码换取令牌、账户查询与原子保存全部成功后才会显示。失败的授权码不自动重放，须重新生成授权链接。令牌交换未给出账户编号时，自动调用 `/open_api/v1.3/oauth2/advertiser/get/` 补查；令牌位于 `Access-Token` header，query 仅传字符串 `app_id` 与 `secret`。平台拒绝和成功返回空账户分开处理，不能把查询失败解释成没有账户。

账户详情使用 TikTok 官方 `/open_api/v1.3/advertiser/info/`，请求字段为 `advertiser_id`、`name`、`currency`、`timezone`；返回的账户名称也从 `name` 读取。`advertiser_name` 不在此接口的字段白名单中，不能将其他账户列表接口的名称字段套用到详情接口。OAuth 回调与直接连接账户共用字段定义。

依据：[TikTok 官方 Get ad account details](https://business-api.tiktok.com/portal/docs?id=1739593083610113)，2026-11-06 核对请求字段白名单与响应示例。协议回归使用独立的官方字段约束，拒绝错误字段，不再让测试响应迁就实现中的错误。

授权回执使用固定、脱敏的分类：`DNS`、`NETWORK`、`TIMEOUT`、`TLS`、`PLATFORM`、`CALLBACK`、`CONFIGURATION`、`TOKEN_EXCHANGE`、`ACCOUNT_DISCOVERY`、`ACCOUNT_INFO`、`ACCOUNT_SAVE`。平台拒绝仅保留数值错误码；不保存原始异常、请求/响应、授权码、令牌或密钥，不新增持久日志。

财务店铺管理区分「公司尚无账户」和「账户被当前分组筛选隐藏」，提供「查看全部广告账户」。自动发现的多店账户可在各对应分组中看到；普通账户未归属总额仍在未分组中保留。仅凭店铺访问关系不会把普通账户所有费用绑定到该店。

连接修复过程见[修复历史](../../releases/finance/finance-ad-connection-repair-20261107.md)、[节点验证](../../releases/finance/finance-ad-vmess-validation-20261107.md)及[最终连接验收](../../releases/finance/finance-ad-connection-acceptance-20261107.md)。历史临时通道和旧失败回执不能作为当前连接状态；连接成功也不证明新报表读取权限或数据完整性。

## 自动获取与店铺归属

授权后后台自动调用 `/gmv_max/store/list/`，以同公司 TikTok 财务店铺 `external_shop_id` 精确匹配官方 `store_id`。不按名称模糊匹配，不更改 GMV Max 主投放账户。尚无财务店铺时仍读取有权限的报表，后续连接店铺自动重新归属，费用身份及金额不变。

普通报表和每个官方店铺的 GMV Max 报表分别保存 checkpoint、状态和退避；一处失败不阻塞其他来源。首次近 90 天，之后每小时近 7 天、每日近 31 天回查，使用广告账户时区。GMV Max 读取计划及日期维度，涵盖商品、直播和已删除计划；分页先暂存，完整窗口验证成功后事务发布，失败不清除上次可用数据。

当前主投放/可用标志不代表历史报表资格；已有关系的历史 GMV Max 继续读取和展示，不因当前 `is_gmv_max_available=false` 删除历史费用。仅专属单店账户适合直接绑定普通广告费用；多店账户不强摊费用，GMV Max 按官方店铺身份分别归属。

手动暂停是持久选择，重新授权更新凭据但不自动恢复暂停账户。暂停及显式恢复撤销旧租约，旧请求晚返回不得发布；未来退避继续保留。专属店铺的接口账户即使已暂停也阻止再导入同份广告费，恢复前再次检查导入冲突。明确充值、转账或未拆分混合字段不能导入为广告消耗，真实消耗返还仍保留负号。

完整窗口刷新如未返回已有事实日期的记录，保留该窗口原费用、覆盖及检查点，提示待核对并自动退避重试，不静默擦除已知费用。明确返回的零消耗记录仍可更新旧金额。初次空窗口只记录请求覆盖，不制造费用记录。已返回日期按完整分页报表更新，不按同金额猜测补齐计划。

管理员只负责平台必须的人为授权及确实无法自动解决的权限/店铺身份问题；无须逐次触发采集、手填 GMV Max 店铺 ID 或定期导入。尚未完成回补、普通报表无法确定店铺、跨来源费用重叠待核对时继续明确显示缺口，不宣称自动对账完成。

## 接口与实现

`GET /api/v1/finance/overview` 新增 `advertising`，返回合计、来源、分组、店铺、费用类别、趋势、投放指标及 GMV Max 统计。`commission` 是账单广告费中的广告佣金子集，在总报告和各分组/店铺下提供。

账单广告费明细使用 `/api/v1/finance/records?kind=FEE&advertisingOnly=true`，导出使用 `/api/v1/finance/export?view=FEE&advertisingOnly=true`。同一类别条件在分页前作用于计数和数据；导出覆盖全部查询页，保留原筛选、个人字段和冻结汇率。该参数拒绝其他类型；广告导出不附带无关结算对账表。

广告事实在原有日汇总扫描中、经营排除前保留，不重复扫描整个账本。共享快照按公司、分组和店铺同步裁剪广告事实；自动化缓存版本为 v18。V148 提供店铺发现、独立进度、分页暂存和覆盖表；本次不新增迁移或持久日志。

实现入口为 `FinanceAds`、`FinanceAdAutomation`、`FinanceAdvertisingReport`、`FinanceRepository`、`FinanceService`、`FinanceController` 与 `frontend/finance-workspace.js`。`GET /api/v1/finance/ads` 可携带 `start` / `end` 读取期间覆盖；账户响应新增 `stores`、`streams`、`coverage` 和 `requestedDays`。
