## 页面

千易售后查询按北京时间的实际 `receiveTime` 筛选，默认当月，独立显示“收货时间”和“退回物流状态”。
统计须同时满足：收货时间落入查询区间、退货状态已完成、对应运单有明确退回卖家签收轨迹；没有收货时间不以创建、完成或修改时间替代。
退回途中、普通正向发货签收、未知物流状态均不计入。可切换“全部单据（核对）”并使用类型和状态筛选，汇总仍只计算符合三项条件的退货单。
列表、汇总、营业成本内退款核对和导出使用同一口径。单据须为未删除的 `SALES_RETURN`、`returnStatus=FINISH`；`refundStatus` 可筛选但不是额外必需条件。退款金额是千易订单退款金额，按原币分开统计。另有独立的「退回商品成本合计（CNY）」：按实际收货月份和数量匹配分组成本表，缺价时显示已知小计及待补齐笔数。它不等于退款金额，不触发库存或利润冲回。签收短语与参考成本分别见[退回短语](../../qianyi-reverse-phrases-20261104.md)、[成本合计](../../qianyi-return-total-20261104.md)。

千易退款页刷新或重新进入时，只保留已定义的筛选值；未设置的状态不序列化为 `undefined` 或 `null`。用户主动清空的状态及日期保留为空，列表与导出继续使用同一筛选。后端仍严格拒绝无效状态，不能用放宽校验代替页面修复。

- 财务总览：已结算额度、订单、退款、平台费用、广告消耗、物流贴单成本、商品成本和利润额；收入趋势、店铺排行、费用构成、订单状态、广告成本趋势及店铺汇总。
- 结算中心：账单、交易明细、TikTok 官方预计待结算；三个独立合计卡片展示当前筛选的金额和笔数，趋势图紧凑显示并跟随所选板块，三类金额不相加。账单合计仅统计平台账单，导入账单用于对账。
- 对账中心：同店铺、账单编号、币种的账单金额和结算交易金额核对。明细分页未完成、金额未知、数据缺失不会标为一致。页面每页 50 张账单，显示总数；Excel 导出支持当前筛选的全部账单（最多 100,000），不受当前页限制。
- 订单：默认「全部订单」，按店铺本地下单日显示已采集的官方源订单，含取消、未结算及其他月结算。完整编号可跨创建日期搜索，但保留公司/店铺/分组/平台/币种限制；详情与导出同口径。切换「已结算订单」仍按首次平台结算日期。全部订单视图不展示结算汇总冒充其合计，见[源订单验收](../../finance-source-orders-20261105.md)。
- 退款、费用与调整：分页明细及对应口径的趋势，退款日期不代替结算日期。
- 广告分析：平台账单广告费（含广告佣金）与普通独立消耗的已入账合计、趋势和投放指标；分组及店铺另列自动获取的 GMV Max 消耗，待核对来源不直接叠加。广告账户自动发现和匹配店铺，覆盖表区分部分日期、失败和接口返回零消耗，人工导入仅作「异常补录」。详见[广告费用口径与分析](advertising.md)；自动化候选尚未部署或验证正式账户的新报表权限。
- 财务店铺管理：统一配置独立财务店铺与广告账户。店铺授权状态、令牌与商品运营分开保存。当前官方授权成功后在同一事务启用财务同步并建立通道，财务管理员可按店铺暂停或恢复；历史 V118 初始关闭关联同步不代表新授权仍默认关闭。移除店铺需输入完整名称确认，随后停止同步、清理授权并后台永久删除该财务店铺的数据；不是保留历史的软隐藏。分组共享成本及商品运营店铺不在删除范围，详见[删除规则](../../releases/finance/2026-10-24-finance-shop-deletion.md)。广告账户连接、更新授权、启停同步全部在此，广告分析页仅保留报表功能。
- 实时大屏：独立暖白橙红展示页，支持全屏；今日订单金额、有效订单数、客单价、小时趋势、店铺成交榜、订单状态及最新订单。不显示买家个人资料。

沿用 HR 看板的 Tabler 设计参考和本地 ECharts 6.1.0。原有首页、全局配色、助手和 HR 业务不变。财务页面支持完整月份、上月整月及自定义起止日期，未指定日期时默认完整上个自然月，按店铺时区解释所选范围；图表自动选择适宜聚合粒度，不再提供日/周/月 K 或快捷周期按钮。趋势连接空缺点，空缺金额仍为未知而非补零。

手动筛选、翻页显示局部加载状态并保留原内容，后台轮询只更新变化部分。无新数据时保留图表实例和数据，不重复执行动画；有新数据时更新变化的序列，保留缩放、图例选择和页面焦点。

## 店铺分组与公司共享

- 在财务店铺管理右上角维护分组名称，用户按类目自行配置。已有店铺初始为「未分组」，可在配置中调整；有店铺的分组不能直接删除。
- 每次生成店铺授权链接必须选择分组。分组、发起人和目标店铺写入一次性授权会话，回调再次检查公司归属。更改弹窗选项后旧链接立即隐藏。旧版未带分组的待授权链接需重新生成。
- 公司、平台和外部店铺 ID 唯一。重复连接提示「店铺已存在」，更新原授权，保留原分组、内部 ID、同步断点及历史；显式重新授权按本次选组调整目标店铺归属。
- 总览、明细、对账、广告分析、实时大屏和导出使用同一个 `groupId`；「未分组」同时包含未绑定店铺的广告费用。广告随专属店铺分组归集，跨店未分配费用不强摊。
- 分组变更后，历史报表按店铺当前归属统计，不复制账务记录。总览提供分组经营明细。前端更改分组或平台立即收窄店铺选项并清除过期选择，包括月度贴单发票；后端仍独立校验范围，不能依赖前端选项隔离。见[筛选级联](../../finance-group-shops-20261104.md)。
- 读取改为公司范围；保留历史存储 `user_id`、凭据 AAD 和幂等 ID。新授权使用稳定的公司财务存储标识。令牌轮换按公司内的授权组锁定全部成员，并逐条使用原归属加密，支持同一授权组混合新旧存储归属。
- 字段显示及导出列仍为个人偏好。Redis 快照按公司、分组和其他完整筛选共享，新缓存版本避开旧账号隔离快照。

## 人民币切换

“原币 / 人民币 ¥”一键切换常规看板、图表、明细及支持换算的导出。费用矩阵「全体导出」始终按原币分工作表，不受该开关影响；商品成本及刷单费中的 CNY 字段保留其原有人民币口径。原币模式按单一币种统计；人民币模式可把不同币种分别换算后汇总。原始账单永不被改写。

参考汇率来源：ExchangeRate-API 免费接口 `https://open.er-api.com/v6/latest/CNY`，页面及导出提供来源链接。将以 CNY 为基准的报价取倒数，得到每一单位原币对应的 CNY。使用 BigDecimal 计算，换算金额保留六位用于汇总，页面显示两位。

每天缓存一个参考快照。外部服务故障时最多使用三天内快照，并显示汇率日期；没有可用汇率或某币种缺失时明确报错，绝不只换算部分金额后冒充总额。刷新按钮重新选取可用快照；翻页及导出固定使用当前看板快照。

采用同一参考汇率重述所选时期的金额，**不等同历史交易汇率、银行结汇金额或人民币会计账簿**。原币对账结果不受人民币四舍五入影响。

## 官方接口与口径

| 数据 | Shopee | TikTok Shop / TikTok for Business |
|---|---|---|
| 订单 | `/api/v2/order/get_order_list` + `/get_order_detail` | `/order/202309/orders/search` |
| 退款 | `/api/v2/returns/get_return_list` | `/return_refund/202309/returns/search` |
| 已释放结算 | `/api/v2/payment/get_income_detail`，`income_status=1` | `/finance/202309/statements` |
| 结算拆分 | `/api/v2/payment/get_escrow_detail` | `/finance/202501/statements/{id}/statement_transactions` |
| 预计待结算 | 当前版本不以订单金额推算 Shopee 待结算 | `/finance/202507/orders/unsettled` |
| 广告消耗 | 支持导入平台账单 | `/open_api/v1.3/report/integrated/get/` |
| GMV Max 专项 | 不适用 | `/open_api/v1.3/gmv_max/report/get/` |
| 采购、头程等成本 | 手工导入 | 手工导入 |

当前不提供资金流水、提现、银行到账、打款接口。平台结算不意味着银行到账。

源订单列表按店铺本地创建日期；已结算订单及经营结果保留首次平台结算日期等既有结算口径，结算和平台费用按平台结算日期，广告按平台返回的账户报表日期。千易收货使用北京时间实际收货日，独立于这些日期。待付款及取消订单保留记录但不计入订单金额；Shopee `ACCEPTED` 按平台确认退款计入合计，`CLOSED` 是关闭申请而不是退款成功；TikTok 保留官方完成/换货退款成功状态判断。明细分开展示「平台退款金额（原币）」和「确认退款金额」，取消、关闭及处理中请求仅显示原始申请金额，不计入确认退款合计。依据 Shopee 官方 [Return Refund Management](https://open.shopee.com/developer-guide/227) 流程图及 [退款详情](https://open.shopee.com/documents/v2/v2.returns.get_return_detail?module=102&type=1)。空金额保留未知，不伪造为零。

TikTok 结算扣费的负数转为费用正数，退款返还相反；原始响应保留。平台结算账本汇总 TikTok 交易的 `settlement_amount`。Shopee 的账单与结算明细均取 Income 接口本次的 `released_amount`，日期取 `actual_payout_time` 并转换为店铺时区；累计 `escrow_amount_after_adjustment` 保留为原始字段，不替代本次释放金额。Shopee 商品收入优先取最终 `cost_of_goods_sold`（0 也有效），再减商家优惠券及金币返现；平台费用拆分与本次净释放金额保持一致。旧记录随整月补抓逐步刷新，具体实测差异和验收状态见上述发布记录。

当前 `FinanceProfitReport` 展示公式为：利润额 = 销售收入 − 已结算平台费用（含物流、调整及账单广告费）− 独立广告消耗 − 营业成本；营业成本 = 商品成本 + 物流贴单成本。等价于平台净结算账本金额减去广告、营业成本，避免平台费用重复扣减。退款影响以平台结算为准，不再次扣按退款日期汇总的确认退款金额。商品成本和月度仓库贴单按订单首次平台结算日期计入一次，广告按平台报表日期，其他外部费用按自身计入日期；这是当前已同步、已录入数据的期间口径，不确认银行到账。缺少成本或汇率时利润留空；未配置广告或物流贴单支出时按 0 暂计并明确标为“暂估”。结算账单与明细不能相加，广告归因收入与订单金额不能相加。

已取消订单和已取消商品明细不计商品成本，不受发货状态影响；平台实际扣费保留。免费样品单依据官方 `order_type=SELLER_FUND_FREE_SAMPLE` 标注，不通过零金额推断。订单、结算明细、订单成本及导出保留样品类型和真实状态，已履约样品的商品成本及平台费用继续统计。平台明确返回 0、尚未返回金额、负向结算分别显示说明。

GMV Max 需在广告账户连接弹窗填写可选的广告平台店铺 ID（不是假定商品店铺内部 ID）。使用官方 `advertiser_id, stat_time_day` 维度和 `cost, orders, gross_revenue, net_cost` 指标。该专项授权出错不会阻塞普通账户报表；错误单独显示。跨店账户可保持未分配，不强行摊到某个店铺。

广告授权使用 TikTok for Business 官方授权链接。在「财务店铺管理 → 广告账户」点击「复制广告授权链接」，系统生成并尝试复制一次性链接，由账户管理员在自己的浏览器选择账户、完成授权。剪贴板受限时仍显示链接及手动复制按钮。指定账户、专属店铺和 GMV Max 店铺是可选项；更改后需重新生成链接。界面不再要求使用者填写 App ID、App Secret 或 Access Token。

广告应用由服务端统一配置，优先读取 `APP_TIKTOK_ADS_CREDENTIALS_FILE` 指定的 UTF-8 properties 文件（字段 `app-id`、`app-secret`），也可用 `APP_TIKTOK_ADS_APP_ID`、`APP_TIKTOK_ADS_APP_SECRET`。模板见 `config/tiktok-ads.properties.example`；真实文件必须放在仓库外，限制文件权限。`compose.finance-ads.yaml` 提供只读目录挂载，可原子替换私有文件更新密钥。配置的文件缺失或无效会明确失败，不回退到另一应用。密钥更新使此前该服务端应用签发的待授权链接失效，已连接广告账户的授权令牌和同步进度不变。

需将 `/api/v1/shop-authorizations/callback/tiktok_ads` 对应的正式回调地址登记到广告开放平台。不能使用 TikTok Shop 应用密钥替代广告应用。未完成服务端配置时，不生成虚假链接，页面提示联系管理员。历史数据库应用仅为原授权流程兼容保留；之前签发的有效链接仍使用原应用完成回调，页面配置写入接口停止接受更改。新服务端应用可供不同公司使用，但一次性 state、广告账户及数据仍按公司隔离，密钥不在响应或 state 中返回。

广告回调为 `/api/v1/shop-authorizations/callback/tiktok_ads`，使用 32 字节随机、一次性、带过期时间的 state；数据库只存 state 摘要。服务端以 `auth_code` 调用 `/open_api/v1.3/oauth2/access_token/`，再通过 `/advertiser/info/` 验证账户。账户 ID 留空时接入本次授权返回的账户，保留已存在账户的归属；指定账户时必须出现在本次授权中。全部验证和写入以事务完成，失败不部分导入，重复回调不重复交换令牌。新账户默认跨店未分配；绑定专属店铺需指定账户 ID。

广告令牌 AES-GCM 加密保存，不回显。店铺授权不等于广告授权。广告接口及导入的广告费用不能在同一个绑定店铺重复接入。服务端广告应用独立配置；已有公司应用和账户保留原加密归属，系统不会复制商品运营应用凭据。

账户详情请求及名称保存使用官方 `name` 字段，回调失败时按网络、平台拒绝或账户保存阶段返回脱敏原因，见[广告授权与账户显示](advertising.md#广告授权与账户显示)。这项修复目前仅在本地，不能视为线上授权已恢复。

## 同步与数据质量

- 历史订单及退款通道：完成一轮后每 10 分钟同步增量。
- 结算、待结算、广告：每小时。
- 独立 `ORDER_LIVE` 通道首次补当天；之后从上轮请求截止时间向前重叠 5 分钟读取更新，整轮成功后 60 秒再次排队，不依赖大屏是否打开。水位保存请求截止时间，不用任务完成时刻，避免分页耗时造成漏单。历史 `ORDER` 通道和实时通道各自保存游标、租约与退避。
- 实时大屏每 15 秒读取已入库数据；关闭或隐藏后停止页面轮询。平台回传、分页、多店排队等会延迟，页面展示实际完整同步时间，不能承诺逐单秒级推送，也不能承诺百店均在一分钟内完成一轮。
- 初次分批回补近 90 天平台仍提供的数据；凌晨后的首次增量回看最近 30 天。平台权限、接口保留期和店铺开通时间决定实际覆盖范围。
- ORDER / SETTLEMENT 优先补齐店铺时区的完整上个自然月，再恢复原历史区间；不再用“最近 30 天”代替上月。历史日期/分页/账单交易游标嵌套保存后原样恢复。上月完成必须同时有两个通道的完整月证明，且没有阻塞的 PARTIAL/DATE_PENDING 账单；最近一次成功不等于整店完成。同步进行中的看板和明细每 15 秒刷新，页面隐藏或有编辑弹窗时延后刷新。
- 预计待结算为动态快照，每小时完整检查最近 90 天及系统仍保存的更老待结算记录，只有分页完整后才清理消失的预估记录。
- 独立 4 线程同步池，每个平台在单个应用实例内最多并发 2 个店铺；同一家店铺的全部通道串行。抢占使用短事务及店铺行锁 `FOR UPDATE SKIP LOCKED`，跨实例也不能同时领取同店铺的有效租约。10 分钟租约每 30 秒续期，游标、成功和失败更新均校验本轮令牌；过期任务不能覆盖新任务进度。分页间隔 2 秒，平台每页条数不变；失败仍指数退避，最大六小时。广告保持原来的独立任务。
- “立即同步”持久化提高原通道优先级，继续现有分页和历史游标；重复点击合并请求，不重置进度或绕过冷却。手动优先、缺失上月收入补抓与一般刷新按现有调度执行，详见[优先级](../../releases/finance/finance-sync-priority-20261103.md)。
- API 稳定 ID 幂等更新，不按名称/金额判重。未识别响应结构不会当作“无数据”推进游标。
- Shopee 收入接口兼容文档中的 `income_detail_list.list`、嵌套形式及实测的 `response.list`。成功响应的空 `response: {}` 表示该区间无收入，可继续下一时间段；缺少响应体、未知字段或损坏的列表仍会报错并保留游标。
- TikTok 账单逐页抓取交易，完整后才改为已结算对账状态。上游数量在分页期间变化则重放该账单/时间窗，已有记录幂等覆盖。
- 原始响应仅用于留存和校验，详情接口不直接返回可能包含买家信息的原始 JSON。

## 可配置字段

明细与对账提供“字段设置”，按企业、用户和数据类型保存。主要字段默认保留；“显示”和“导出”是两套独立选择，不必为了导出而撑宽页面。对账、全部明细和每种业务记录分别配置，CSV 和 XLSX 实际使用所选列。

扩展字段来自已留存官方响应中的白名单路径，包括支付方式、平台时间、商品行数/名称、运费、优惠、结算佣金/手续费/税费、广告曝光/点击/转化等。只提取安全标量，保留未知值；不返回买家资料、令牌或原始 JSON。不同平台字段不混用，不适用字段为空。扩展金额明确标注原币；人民币模式只转换已定义的金额及对账列。

## 导入、导出

支持 UTF-8 CSV / XLSX，标题行映射，单次导入最多 20,000 行、12 MB。类型为账单、广告费、物流贴单成本；验证全部行后事务提交。相同文件与映射重复导入不重复入账；记录编号稳定时允许更新原记录。文件中的公式不执行，导入需先转为值。

一般财务导出按当前分组、平台、店铺、日期、编号和币种筛选，不限于当前页面；单项上限及字段以对应导出接口为准，常规明细最多 100,000 条。结算/对账导出保留其说明及对账内容；全部源订单导出不附加无关结算对账表。支持人民币换算的常规导出带汇率快照；金额为数值单元格，订单等长 ID 保持文本，CSV 做公式注入防护。

费用构成卡片的「全体导出」是独立异步任务，冻结提交筛选，以费用类型为行、店铺为列，按每种原币分别提供金额表和记录数表。即使看板为人民币，也不换算、不合并跨币种总额；负向补贴保留符号，缺金额显示待补齐。任务按公司和用户隔离，完成后 30 分钟过期且重启丢失，详细限制见[费用矩阵验收](../../finance-fee-export-20261104.md)。

成本、月度贴单和刷单费是各自的专用导入流程，不能套用一般财务账单导入格式。成本文件中仓库、型号、月份及数值单价完全一致时保留一条（`2` 与 `2.00` 相同）；同键不同价仍整次拒绝并提示冲突，不静默覆盖。详见[成本去重](../../finance-cost-dedupe-20261104.md)。

刷单费下载使用 [原始模板](../../../frontend/assets/templates/finance-brush-cost-template.xlsx)，文件名为「母婴刷单费导入模板.xlsx」。保留十一列及两个按位置区分的「结算月份」，原数据全部清除，长订单号按文本填写。`代刷费CNY` 即已有刷单费，内部字段为 `service_fee_cny`，不新增另一项服务费或计算规则；订单本币金额继续用于识别/核验，首次结算归属、去重及刷单经营报表排除保持现状。见[模板验收](../../finance-brush-original-template-20261105.md)。

刷单成本页新增与订单核对表一致的来源合计：非零本金记笔数，非零代刷费按人民币求和；按当前费用分组和订单编号查询全部分页，逐行统计，零值不计。平台/店铺/结算日期的首次结算去重统计另行显示，经营费用口径不变。详见[刷单统计范围](costs.md#贴单刷单费及其他费用)。
