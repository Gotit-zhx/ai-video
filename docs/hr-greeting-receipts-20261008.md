# 打招呼成功回执同步修复

2026-10-08 已发布网页与服务端版本 `/opt/heyi/releases/hr-greeting-receipts-20261008`，并更新当前 Mac 已安装助手。Windows 安装包仍为 0.1.14，本次未重建。

## 原因与行为

打招呼请求可能返回 HTTP 200、平台 code 0，但 SDK 未确认业务发送成功。此前此类记录被保留为 uncertain，随后又被会话核对逻辑排除；前端也停止轮询 uncertain，导致真实发送成功后卡片仍显示“发送结果待核对”。

本次记录调用前的 attemptedAt，将 uncertain 纳入受预算控制的只读核验。通过加密候选人标识和职位标识核对会话，再验证准确的收件人、HR 发出方向、已批准话术、消息类型、有效消息 ID 和发送时间窗口。HTTP 200 或平台 code 0 本身不能判定成功；SDK 明确携带 sent=true 的指定结果也必须同时匹配候选人和职位。

核验成功后持久化本地回执、重新开放成功报告并绑定会话，在同一次助手轮询中上报云端。前端每 5 秒读取云端待核对状态，成功且会话已绑定后停止轮询。云端防止延迟的 uncertain 报告覆盖 sent；仅向声明 greeting-receipts-v1 能力的助手提供待核对联系人，不将 uncertain 作为重发命令。

核验不重新发送打招呼、不增加每日发送计数，也不触发 AI 获取。保留每小时 120 次硬上限、每日 150 次尝试限制、写操作间隔和风险暂停；回执核验有全局冷却、单记录冷却、时间范围及请求预算限制。若候选人已有被动邀约流程，保留 existing_flow，避免重复回复或索取简历。
