# TikTok 默认发货仓库修复（2026-10-23）

## 问题与行为

Sweet Me 店铺官方接口返回三个启用的发货仓，但均未标记 `is_default`。原前端只接受用户缓存的仓库、平台默认仓或唯一仓库，因此在上传准备阶段无法选出仓库。另外，仓库状态应读取官方的 `effect_status`，不能只读取旧的 `status`。

修复后：

- 只选择目标授权店铺的可用 `SALES_WAREHOUSE`；不使用退货仓或停用仓。
- 跨境 `LOCAL_REPLICATION` 店铺进一步与官方 `inventory_rules` 校验。
- 优先模板中明确配置的仓库；自动模式按平台默认仓、海外仓、其他发货仓排序，同级按字符串 ID 稳定选择。
- 上传配置新增 TikTok 店铺和仓库下拉框，展示对应发货地址；未配置时直接使用自动模式，不要求重新保存模板。
- 显式配置的仓库失效时提示重新选择，不静默切换发货地址。
- 服务端也处理未传 `warehouseId` 的请求。已经提交且明确指定仓库的任务继续沿用原选择。
- 新配置按公司、店铺、商品功能模块隔离，保存使用版本校验，与模板保存处于同一事务。

当前 Sweet Me 的自动选择结果为海外发货仓 `jackson.`，官方库存规则允许使用该仓库。传给平台的是官方仓库 ID，由平台关联已有发货地址。
