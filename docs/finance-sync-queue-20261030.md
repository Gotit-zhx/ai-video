# 店铺同步与贴单汇总解耦

2026-10-30 再次发生订单同步 SQL 超时。线上执行计划确认已有订单号索引生效；
同时 `performance_schema.data_locks` 显示贴单汇总阶段对来源明细持有
265,478 个主键共享记录锁、270,094 个二级索引共享锁。同步事务直接更新贴单行，
因此即便索引正确仍会等锁超时。

## 修复及发布

- schema 139 新增 `finance_label_arrivals`。订单事务只通过一致性读检查是否有未匹配来源，
  再写入按公司/订单唯一的持久队列，不更新贴单明细或公司汇总状态。
- 后台每批处理至多 200 个订单通知，同一轮合并至多 2,000 个，再构建一次金额结果；
  事务回滚保留通知，重复到达合并，匹配完成的订单不反复请求全量重算。
- 汇总 `INSERT ... SELECT` 使用单语句 READ COMMITTED 快照，避免锁住来源行。
  文件计数先用非锁定查询汇总，然后只在短发布事务中写入每个文件的计数。
- 原有来源版本检查、金额去重、整代结果切换保持。订单同步断点、店铺配置和金额原始数据未改。
- 已发布 `ai-commerce-platform:finance-sync-queue-20261030`，仅覆盖 3 个类族及新建队列表。
  原千易功能和其他应用类保持。5 个失败订单通道从原断点重试，随后线上同类 SQL 错误数为 0。

13 项贴单 MySQL 集成测试通过，包括真实行锁下订单仍可保存、汇总仍可读已提交来源、
通知回滚重放、多店并发、来源去重、源文件删除和按结算日期归属。
千易 8 项集成回归、配置界面测试亦通过。
