# 商品采集插件与一键发布设计

## 目标

这套功能用于把 Shopee、TikTok Shop 页面上的商品整理成平台内可审核的刊登草稿。插件只负责识别当前页面和读取用户可见字段；第三方商品 API、AI 图片处理和店铺发布都由平台后端执行。

测试分支默认开启安全模式：第三方数据源不消耗额度、图片处理不覆盖原图、发布只生成 dry-run 记录，不会向店铺提交商品。

## 用户流程

1. 用户先登录赫逸平台，在“商品采集/发布”页面生成一次性插件绑定码。
2. 用户在插件弹窗输入绑定码。平台校验用户、企业和 `product:collect` 权限后签发短期插件令牌。
3. 用户打开 Shopee 或 TikTok Shop 商品详情页，也可以在商品列表卡片上点击“一键采集”；卡片模式会先加载对应详情数据。
4. 插件读取页面当前可见字段，并解析该页面已经加载的第一方商品详情数据，以获得真实 SKU 矩阵。
5. 后端校验站点、企业和幂等键，第一版直接保存插件提交的页面数据，不调用 ReefAPI 或 TMAPI。
6. 平台保存原始数据、标准化字段、每个字段的来源、原图和 SKU，并形成待审核草稿。
7. 用户发起 AI 去水印任务。原图始终保留，处理结果作为独立素材保存；失败可以重试。
8. 用户在平台修改并审核草稿，点击“批准发布”。
9. 用户选择目标店铺并在确认框中再次确认。后端以幂等键创建发布记录；测试环境只执行 dry-run。

## 安全边界

- 插件不保存平台密码、ReefAPI Key、TMAPI Key、AI Key 或店铺凭据。
- 插件提交的数据始终按不可信客户端输入处理；SKU 的 `complete` 只表示字段齐全且结构自洽，不能替代人员对商城页面的最终核对。
- 一次性绑定码只能使用一次且很快过期；插件令牌只保存哈希，数据库泄漏时不能直接还原令牌。
- 插件令牌绑定用户和企业，用户停用、企业停用、令牌过期或撤销后立即失效。
- 网页 Session 和插件令牌彼此独立，插件登录不会挤掉网页端登录。
- 所有草稿、SKU、素材和发布记录都按 `organization_id` 查询，不能仅依赖前端隐藏数据。
- 后端只接受明确支持的 Shopee/TikTok Shop 域名，禁止把采集接口当成任意 URL 抓取器。
- 只有 `product:publish` 权限可以创建发布记录；必须先人工批准，并在发布请求中传入明确确认标记。
- 发布接口必须使用幂等键，重复点击不能创建两次真实刊登。真实发布提供方接入前还必须增加企业店铺、店铺状态及人员店铺范围的服务端授权校验；当前 Dry Run 只记录店铺标识，不宣称已验证店铺授权。

## 权限

| 权限 | 用途 |
| --- | --- |
| `product:collect` | 绑定插件、采集商品和请求数据源补全 |
| `product:view` | 查看采集草稿、SKU、素材及发布状态 |
| `product:edit` | 编辑草稿并批准进入发布环节 |
| `asset:watermark` | 发起或重试图片去水印 |
| `product:publish` | 选择店铺并在二次确认后发布 |

管理员拥有全部权限。其他内置角色通过 Flyway 迁移获得与职责匹配的最小权限，自定义角色仍可在系统管理中调整。

## 第一版数据来源

第一版不使用付费数据源，按以下优先级整理：

1. 商品页面当前可见的 DOM 字段；
2. 页面自带的 JSON-LD 和 Meta 数据；
3. 当前商品页已经加载的 Shopee/TikTok 第一方详情 JSON；
4. 用户在审核页面手工修正的刊登值。

每个标准化字段同时记录来源。完整 SKU 必须来自当前商品 ID 对应的第一方数据，包含平台 SKU/model ID、规格组合、售价、原价、库存和 SKU 图；不能把颜色与尺码做笛卡尔积来猜 SKU。插件同时提交平台声明的 SKU 数和实际解析数，后端再次校验。两者不一致、ID 重复或关键字段缺失时，草稿标记 `SKU_INCOMPLETE` 并禁止审核发布。

插件不拦截或上传商城 Cookie、认证头，也不绕过登录、验证码或地区限制。用户必须先在自己的浏览器中正常打开商品；遇到登录页、流量验证或拼图验证时，插件停止采集并提示用户手工完成验证。以后如果页面第一方数据覆盖率不足，再按需启用 ReefAPI 或 TMAPI 适配器，不影响现有草稿结构。

## 数据模型

- 商品采集草稿：来源平台、市场、规范化 URL、外部店铺/商品 ID、状态、原始 JSON、标准化 JSON、字段来源、创建人和企业。
- SKU：外部 SKU ID、规格属性、价格、币种、库存和 SKU 图片。
- 素材：原图 URL、处理后 URL、去水印状态、排序和错误信息。
- 插件授权：一次性绑定码、设备令牌哈希、用户、企业、权限范围、过期和撤销时间。
- 发布记录：目标平台/店铺、请求快照、dry-run 标志、幂等键、状态、响应和错误。

## 运行模式

开发和测试环境保持以下默认值：

- 商品数据源为插件页面与页面已经加载的第一方商品详情数据，不请求 ReefAPI 或 TMAPI；
- 去水印为 mock，处理结果不会覆盖原图；
- 发布为 dry-run；
- ReefAPI、TMAPI 和店铺密钥为空。

只有在后端显式配置生产数据源密钥、打开对应 live 开关并完成目标店铺授权后，才允许逐项启用真实调用。发布 live 开关应最后开启，并先用测试店铺验证幂等、失败重试和回滚流程。

## 验收清单

- 未登录插件无法采集；过期、撤销、企业不一致和缺少权限分别返回明确提示。
- Shopee 菲律宾/新加坡/马来西亚/泰国/印度尼西亚/越南和 TikTok Shop 商品详情页能够识别。
- 商品卡片和详情页重复点击只产生一个草稿。
- DOM 价格能够覆盖 Shopee 数据源缺失价格，字段来源可见。
- 每个真实 SKU 的平台 ID、规格、价格、库存和 SKU 图可保存，声明数量和解析数量一致；不完整时禁止审核。
- 图片和描述可保存；原图与去水印图不会互相覆盖。
- 登录页、验证码和流量验证页不会被误采成商品。
- 只有批准后的草稿可以发布，发布前有二次确认。
- 相同幂等键重复提交只返回同一条发布记录。
- 企业 A 的用户、插件令牌和草稿不能读取企业 B 的任何数据。
- 默认配置下没有真实第三方调用和真实店铺发布。
