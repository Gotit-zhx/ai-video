## 广告授权账户字段错误的复现与修复

2026-11-06 的只读核对中，当前公司广告账户为 0，多次授权回调记录为 FAILED，用户回到系统后看到「授权未完成」。原实现将所有异常写成相同提示，历史失败记录没有保留阶段或平台错误码，因此不能仅凭后续连通测试断言历史回调的根因。

重新核对 TikTok 官方 [Get ad account details](https://business-api.tiktok.com/portal/docs?id=1739593083610113) 后，发现实际运行制品和本地源码都对 `/advertiser/info/` 请求了不支持的 `advertiser_name`，并从同一错误字段读取保存名称。此接口支持的字段是 `name`。此前测试数据同样伪造了 `advertiser_name`，掩盖了协议错误。

最终修复：

- OAuth 回调与直接连接共用 `advertiser_id,name,currency,timezone` 字段定义，账户名称从官方 `name` 保存。
- 新增 `FinanceAdAccountContractTest`，模拟平台依据独立的官方白名单拒绝不支持字段。修改前两个入口均失败；修改后回调、账户持久化及列表显示名称通过，并验证回调只消费一次。
- 修正既有授权/删除防护集成测试的模拟响应，对账户详情请求增加协议约束，新增真实 MySQL 的直接连接名称保存及公司隔离验证。
- 保留脱敏阶段错误和分组隐藏提示。撤回此前推测性新增的专用代理类、代理配置和 HTTP 客户端构造器改动；没有修改生产网络、Compose 或容器。

协议依据与测试桩属于开发验证，不能替代一笔真实生产回调的原始错误证据。修复后仍需按已确认的发布范围激活，再用新授权链接验证真实账户。旧授权码不重放，令牌、私有环境及完整业务数据不进入仓库或诊断输出。

最终验证：8 个 Java 类的 69 项单元回归、10 项本机隔离 MySQL 8.4.13 授权集成测试及 2 套广告页面专项均通过，0 失败、0 错误、0 跳过。集成覆盖官方名称持久化与列表查询、跨公司隔离、一次性回调、失败回滚、配置变更和迟到授权防护；采用模拟官方响应，不是线上授权验收。临时测试容器、专用网络、数据卷及私有测试凭据已移除，仅保留小型验证回执；运行中的本地真实数据预览及其依赖保留。
