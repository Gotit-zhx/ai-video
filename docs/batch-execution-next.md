# 批次自动执行：目标与当前边界

> 这是 2026-09-07 的阶段记录。执行实例、提取前检查、调用次数限制以及创作配置版本保存已有后续实现；最新续接状态见 [2026-09-08 项目续接记录](project-continuation-20260908.md)。下文完整自动执行要求仍需继续完成。

用户确认的交互：选择工作批次，统一确认模板、目标店铺、规格价格、数量和预算，点击一次开始后自动流转。五个阶段是状态视图，不是必须点击的操作步骤；异常处理后继续原任务。保持参考原型布局，仅使用现有主题色。

## 已验证的基础

- 批次工作台统一入口、同批次商品选择、固定来源版本、设计预览及匹配发布批次接口。
- 现有单商品发布处理器拥有数据库租约与外部提交不确定性保护，但不包含采集、提取和设计裂变。
- 当前 `commerce_batches` 是绑定既有商品、模板、店铺的发布批次，不是采集之前就能创建的生产任务。不能把这个结构当作完整的创作批次。
- 自动执行尚未接通；界面不显示虚构运行进度，不发起自动付费生成或真实上架。

## 下一阶段实现要求

1. 建立独立创作批次 / 执行实例，支持在采集前保存关键词、链接、插件导入范围。发布批次作为下游产物关联，不强迫先有商品和授权店铺才能保存创作草稿。
2. 固定启动配置快照：来源范围、平台站点、模板版本、各店配额、设计数、预算币种与上限、权限主体和确认时间。配置修改产生新版本，不能影响已开始的执行。
3. 后端持久化阶段及每个商品/设计子任务：采集 → 检测 → 提取 → 裂变 → 复检 / 套版 → 发布。完成条件必须引用真实结果及内容版本；不允许计时器直接标记成功。
4. 后台队列与原子租约、幂等键、可恢复检查点。先记外部提交意图再调用；提交结果未知时暂停核查，不自动重复付费生成或创建商品。
5. 暂停只阻止新子任务启动，不宣称已取消在途远程调用。取消保留已执行结果与费用；失败项重试不重跑整批。
6. 每个阶段开始前验证实时用户权限、店铺授权、来源版本及剩余预算。预算需持久化预占和结算，不能只用前端确认框。
7. 页面订阅或轮询后端状态，在阶段真实变化时过渡；刷新重连恢复同一执行。多个浏览器不得重复启动。异常统一进入待处理区。
8. 首先用确定性测试适配器验证端到端推进、服务重启恢复、并发启动、超预算、失权、部分失败和不确定提交，再接真实模型与官方接口。测试适配器不能在正式环境伪装为真实完成。

后续扩展仍包括关键词热销数据、多平台多站点、POD生产校验、广告测款、7日评估、视频达人和商品生命周期；本次批次工作台不代表这些已完成。
