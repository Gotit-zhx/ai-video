# 正式视频任务恢复（2026-09-15）

本修复从服务器实际运行的 `1c09e00` 建立，恢复视频拆解过程中继续上传另一个视频，并移除失败脚本对新建入口的阻塞。不是把当前开发工作区的电商/POD 功能整体部署到生产。

## 已核对的问题

- 正式后端与 runtime 原镜像为 `timeout-1000-1c09e00`；前端为 `company-footer-20260905`，nginx 另有 ERP 路由的容器内修改。
- 生产数据库早已执行 V42/V43，V43 已取消单用户单拆解任务约束，但运行前后端仍保留旧拦截。
- `gpt-5.5` 的非流式完整视觉请求多数约 21 秒返回 500。保留同一模型、原图、完整生产提示词和 1800 token 预算，仅改为 `stream=true` 且不发送 `stream_options` 后，真实请求在 56.28 秒完成，返回全部 25 个必需字段、`finish_reason=stop` 和 `[DONE]`。这说明该网关的非流式链路不适合当前完整请求；不能通过切回旧模型或删除结构约束解决。

## 修复

- 新建入口独立于进度弹窗；列表轮询所有运行中的拆解；失败重试绑定实际选中的脚本。
- 后端允许不同脚本并行，独立线程池默认 4；同一脚本用数据库条件更新认领，避免并发点击造成重复执行；队列满时保留文件并明确失败。
- 视频拆解改为有总时间预算的会话。视频拆解、服装结构识别/复核和日用品分析共用 Chat Completions 流式兼容层：优先发送通用 `max_tokens`，不按模型名前缀添加推理参数，也不发送可选的 `stream_options`；仅在明确的参数不兼容响应后有限协商并缓存。
- SSE 按 UTF-8 增量读取并处理跨块 CRLF、多行 data、usage 和错误事件；必须同时收到正常 finish reason 和 `[DONE]`，断流或半截 JSON 不算完成。仍兼容供应商直接返回完整 JSON 的响应。
- 保留模型、图片、提示词与输出预算，不切换模型或移除参考图。上游服务、认证、模型不存在、视觉不支持、截断等错误区分处理。
- 初始商品结构识别由 Java 最多调用 runtime 两次；明确 `retryable=false` 的错误立即停止。服装兼容层每次调用最多允许一次明确的参数协商，因此上游 HTTP 请求数可能大于两次。失败后以 `STRUCTURE_ANALYSIS_PAUSED` 暂停，worker 和扫描器均不会无限拉起。原图、已保存结构及已付费图片下载恢复保留。
- 将生产已有的 V42/V43 纳入干净构建；不新增数据库迁移。

## 模型支持范围

本次兼容层支持提供 Chat Completions 接口、接受图片输入且能返回完整文本结果的模型。它只协商 `max_tokens` / `max_completion_tokens` 字段；不会把 Responses 或 Anthropic Messages 接口自动转换为 Chat Completions，也不会为缺少视觉能力的模型补出视觉能力。修改模型名称不保证供应商支持相同请求能力，需以该连接的真实视觉请求验证为准。

手动脚本及其他 Agent 路径仍使用原有流式实现，不属于此次共享兼容层的覆盖范围。日用品初始结构识别在失败后也会明确暂停，不再跳过识别继续生图。视频拆解单次模型调用上限为 300 秒、单次 runtime 会话总预算为 900 秒；Java 只对可重试故障重试整个会话，最多三次。

`READY` 且保存 9 个分镜说明拆解结果已落库，不等同于全部动作复核成功。动作复核失败时仍可能保留首轮有效结果，需结合 runtime 的 `actionStateAudited` 完成日志与 `action-state audit fallback` 日志判断。

## 恢复边界与资产保留

- 部署默认拒绝运行中的任务。允许续接时，仅纳入部署前明确记录的任务，并在停止旧后端后再次核对；图片任务必须尚无结构识别结果、生成资产或 pending 图片响应，且没有视频提交在运行。
- 图片恢复只修正停机中断产生的任务状态，让既有扫描器继续；不清除原图、冻结脚本、模型配置、自动提交标志、候选文件或已付费结果。不调用会删除候选和生成资产的“重做首帧/九宫格”接口。
- 结构识别暂停后的显式接续使用既有启动接口，须再次核对全部 item 都未生成资产或 pending 结果、冻结脚本与当前脚本完全一致、模型配置一致；按原任务的自动视频意图选择入口。此规则不能用于含部分成功资产的任务。
- 脚本续接工具仅对明确列入清单且仍为 `FAILED` 的脚本，借助其所有者有效会话调用标准重试接口。它跳过 `READY` 和正在处理的脚本，不扫描重试全部历史失败记录，也不在 POST 超时后盲目重发。
- 脚本重试成功后，会在事务中更新该脚本的 9 个分镜；这属于明确重试的结果更新。它不改已建立 AI 视频任务中的冻结脚本快照，也不删除这些任务的生成图片或视频。
- 回滚命令恢复三个旧服务镜像及保留的 nginx/页脚配置，不自动导入数据库备份；已经完成的任务及本次产生的状态仍保留。数据库备份为另外的恢复依据，不能将镜像回滚理解为整库回退。
