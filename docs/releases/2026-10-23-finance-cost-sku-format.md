# 成本币种、SKU 格式识别与 SPU 四列卡片

成本表原来把未配置的计量单位显示为「单位待确认」，容易和人民币币种混淆；自动 SKU 关联只接受严格相同的编码，导致 `(型号) *2` 无法匹配。

本次更改：

- 成本表改为「币种／人民币 CNY」，原始单价不换算、不修改。
- 匹配顺序为完整原编码、格式规范化后的唯一编码、组合装基础型号。兼容中英文外层括号、空格、`*` / `＊` / `×`，保留型号字母、尺码、连字符及组合数量。
- 完整组合装成本优先；只有基础型号时保存 `BUNDLE_CODE` 和 `bundleQuantity`。单位换算 `factor` 仍为空，不生成订单成本和利润。
- 规范化重码不自动猜测；规格冲突保留橙色需核对。既有人工关系、并发保存的关系和店铺隔离保持。
- 桌面每行四个 SPU，展开的 SKU 明细占整行；较窄屏幕自动调整为两列或单列。关联结果仍有绿、红、橙文字标记。

验证：

- `test-finance-costs-ui.mjs`、`test-finance-costs-live-ui.mjs` 通过。
- MySQL 隔离库集成测试及成本、缓存相关测试共 49 项通过；未对生产表运行测试。
- 1440px 和 1920px 桌面布局检查，四列卡片、整行明细和展开切换正常。
