# 服务器瘦身与旧 Linux 浏览器退役

按用户要求，退役服务器上的旧 Linux 谷歌浏览器，并清理废弃运行环境、历史镜像及构建缓存。此次不修改应用业务代码，也未重启线上 Docker 服务。

## 实测结果

- 本轮释放约 **21.07 GiB**。
- 最终可用空间约 **24.08 GiB**；`df -h` 四舍五入显示 25G。
- 根盘使用率从约 **97% 降至 75%**。
- 9 个线上服务容器 ID 保持不变；MySQL、Redis、文档预览及 ERP 健康检查通过。

## 清理内容

- 卸载 `google-chrome-stable`、Xvfb、x11vnc、noVNC、websockify，以及 85 个已无依赖的图形桌面组件。
- 停止、禁用并屏蔽 5 个旧服务：BOSS Linux connector、Chrome、虚拟显示、VNC 和 noVNC。9222、5908、6088 端口已关闭，重启后不会自动启动这些服务。
- 清理旧 Linux 助手可重建的 Python 虚拟环境、wheel 安装包、pip 缓存、浏览器图像及代码缓存。
- 清理 184 个废弃镜像 ID、3 个长期停止且无数据挂载的构建容器，以及无引用的构建缓存与镜像层。
- 另外 6 个旧镜像仍是保留版本的依赖层，因此继续保留，未强制删除。

## 保留范围

- 线上主应用、前端、PI 运行时、图像处理服务的当前镜像和选定的两个回滚版本，以及数据库等基础镜像。
- 全部数据库卷、业务文件、OSS 配置、下载链接和服务配置。
- 16 份现有 MySQL 备份，合计约 16.65 GiB。
- 旧 Linux 助手已收集的简历文件及浏览器登录资料；Mac/Windows 助手的程序和登录状态未改动。
- 通用主机 Node/Python 及数值计算运行库；未直接执行不加区分的系统包自动清理。

此前财务店铺删除发布中清理的旧 JAR 副本曾可从历史镜像恢复。本次新的瘦身要求进一步退役了早期镜像，因此旧版本恢复范围以本次保留清单为准。当前版本和最近的回滚镜像仍在。

### 已处理内容

- 删除 7 份旧发布目录中的 Spring Boot JAR 副本。2026-10-23、2026-10-24 的发布 JAR、当前运行文件和已保留回滚镜像不动。
- 删除 1Panel 2.2.5 的旧安装目录和压缩安装包。清理前已确认运行程序位于 `/usr/bin/1panel-core`、`/usr/bin/1panel-agent`，不依赖该安装目录。
- 清理 Maven 依赖缓存及 pip 缓存；清理前确认没有 Maven 构建进程，Maven 配置保留。
- 上述 11 项产物与缓存合计约 **861.9 MiB**。
- 将 14 份历史 SQL 备份和 9 份历史 ledger JSON 备份无损压缩为原路径加 `.gz`，节省约 **457.4 MiB**。逐个解压比对原内容 SHA-256，确认内容一致、源文件未变后才移除未压缩副本；权限、属主和修改时间均保留。

### 仍保留的主要占用

- 16 份日常 MySQL 压缩备份，合计约 **16.65 GiB**，未删除。
- MySQL 业务数据及约 **22 GB** 的二进制恢复日志。恢复日志保留策略仍是 **30 天**（`2592000` 秒），未执行日志清除或缩短保留期。
- 当前镜像、回滚镜像和运行服务依赖层，未直接清理 Docker/containerd 存储目录。

历史发布脚本若引用本轮压缩文件的原路径，需要先解压对应文件。例如：

```sh
gzip -dk /opt/heyi/releases/module-isolation-20261015/rollback/database.sql.gz
```

该命令只还原 SQL 文件，不执行数据库导入。恢复其他文件时，应先查本轮清单中的 `archive`、`original` 和 `uncompressedSha256`，按指定文件解压并核对内容。
