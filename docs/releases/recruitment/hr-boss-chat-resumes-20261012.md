# BOSS 会话附件统一入池

> 历史发布记录；镜像、测试与“当前/最新”均指记录当时。 当前入口见[业务说明](../../business/README.md)与[运维指南](../../guides/operations.md)。

招聘助手 0.1.19 在已验证的当前招聘账号下持续读取全部 BOSS 会话。候选人发送的附件简历无需先在系统打招呼、启用被动规则或索要简历，直接归档为“BOSS沟通”。明确属于系统主动、被动邀约的会话保留原来源。

收取使用固定 SDK 的候选人方向、附件卡片及下载校验；不自动同意联系方式交换、不新增对人工会话的自动话术。收取可以覆盖关闭岗位，但审批和发送仍要求对应岗位当前开放。岗位根据正式会话详情关联，缺失则保存为待核实，禁止猜测岗位或 JD。分析读取当前账号对应岗位保存的 JD。

本机分别保存最新消息游标、历史消息游标和逐条附件账本，持续分页到历史末尾，没有五页上限。重连补读、新到消息与历史补收交替执行。重复消息上传使用云端 owner/account/friend/message 唯一键，同人后续发来的不同附件消息分别入库；不同用户、招聘账号数据隔离。

采集遵守原请求预算、风险暂停和人工操作优先队列。附件失效、不可下载时保留待处理记录和重试时间，不伪造成功或重复发送索要消息。来源筛选、人才卡片、BI 统计及导出均支持“BOSS沟通”。

2026-10-12 已激活线上服务和双端 0.1.19 下载链接，本机 Mac 已运行 0.1.19，BOSS 登录态保留。上线后的真实接收账本与云端按当前租户、账号、会话和消息逐条核对，首批两条 stored 回执均对应已归档简历，姓名及职位 ID 有值；这些会话原属被动邀约，来源按原规则保留。人工会话的 BOSS沟通来源、关闭/未知职位只读、重复附件及超过五页的历史读取已通过隔离测试。当前历史队列仍在持续补收，不代表所有会话已处理完毕。
