# BOSS 登录同步与 Linux 中文显示修复

> 历史发布记录；镜像、测试与“当前/最新”均指记录当时。 当前入口见[业务说明](../../business/README.md)与[运维指南](../../guides/operations.md)。

## 已确认的原因

- Linux Chrome 手动扫码后的登录凭据与 CLI 加密存储中的旧凭据不一致。
- 原“重试招聘方验证”直接使用 CLI 旧凭据，没有先同步浏览器；历史 IP 错误被保留后，页面持续显示待验证。
- 连接器重启、部分接口验证失败都会关闭独立 Chrome，会干扰远程扫码和诊断。
- Linux 没有 CJK 字体；补装字体后，已有 Chrome 的字体缓存仍需通过保留配置重启更新。

## 修改

首次无登录态时继续使用 `boss login --cdp`。已有浏览器登录和验证重试先调用上游
`login_via_cdp(reuse_existing=True)`，写入同一账号的加密凭据存储，再读取招聘方职位接口。
这条复用路径不进入上游 `AuthManager.login` 自动强制重登的兜底逻辑。
同步过程使用独立子进程和超时控制，对外只返回结果码。

同步失败保留浏览器会话，不使用旧凭据继续验证；明确的招聘身份不符仍拒绝并退出。
连接器重启保留独立 Chrome。历史 IP 提示明确说明是上次接口响应，只有招聘方接口
真实成功才清除历史标记。原有按钮调整为“同步浏览器登录并验证”。

服务器安装发行版 `fonts-noto-cjk` 并更新字体缓存；Chrome 使用原 profile 和
`--restore-last-session` 恢复页签，中文显示与原招聘登录均已保留。
