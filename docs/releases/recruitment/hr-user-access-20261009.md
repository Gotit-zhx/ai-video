# 人力资源账号授权、资料隔离与开放职位审批

> 历史发布记录；镜像、测试与“当前/最新”均指记录当时。 当前入口见[业务说明](../../business/README.md)与[运维指南](../../guides/operations.md)。

新建的人力资源账号只有角色名称，没有 HR 权限；网页、Python 接口、AI 接口和桌面助手也都限制了原管理员身份。现在以 `hr:access` 开放整个人力资源模块，角色数据范围仍为 SELF，不授予系统管理、商品或视频权限。角色标签本身不能获得权限。

网页显示八个人力资源菜单，普通 HR 从空白入口登录时进入招聘工作台。顶栏显示“人力资源 · 全部功能”。原登录会话缓存权限，首次赋权后需重新登录。

## 数据边界

Python 以组织和稳定用户 ID 生成 `organizationCode:user:userId` 的业务 owner。简历、人才、招聘需求、部门、话术、钉钉配置、入职资料、BI 和文件读取沿用同一边界。原指定管理员保留已有 `heyi` owner，其历史资料不迁移、不共享给新账号。

同公司切换用户也清空网页 HR 状态。桌面助手检查当前 HR 权限，并保持组织、用户及 BOSS 账号的绑定隔离；不会复用另一位用户的连接。AI 接口统一检查 HR 权限，继续使用公司的 DRIVER 和现有 Pi runtime。

## 职位状态

只有来自职位管理的完整官方列表能更新状态：按用户、招聘账号和具体职位保存，最多缓存五分钟。网页详情读取、审批前核验，以及新助手配对后的状态报告共同更新。助手报告携带缓存剩余寿命，不能通过重复上报延长旧快照。

开放中才允许通过、拒绝及新 AI 分析；关闭、待开放、审核、未知或状态过期时仍可查看和下载资料。后端审批和拒绝发送任务领取再次核验，已关闭职位不会继续领取拒绝消息；取消排队消息仍可操作。缺少对应职位时不会按其他职位猜测。

## 导师流程

未选择导师时默认精确部门已验证组长，可从钉钉目录选择其他人。二面通过保存选择的 UserID 和配置版本，入职编辑和带教通知沿用这位导师。目录浏览不会发送通知；发送前再次核验唯一身份和配置版本，避免同名误发。

## Windows 网页连接诊断

用户随后反馈登录后显示 `Failed to fetch`。源码中手动首次配对仅等待四秒，并把网络 TypeError 原样显示，无法区分平台请求、本机端口和浏览器拒绝权限。首次手动检查改为三十秒；后台检查仍为四秒，保持原有退避和恢复流程。

平台连接失败显示 `PLATFORM_NETWORK_UNAVAILABLE`；本机不可达显示 `LOCAL_CONNECTION_UNAVAILABLE`；超时显示 `LOCAL_CONNECTION_TIMEOUT`。仅当浏览器权限 API 明确返回 denied 才显示 `LOCAL_NETWORK_PERMISSION_DENIED`，不支持权限名不能推断为拒绝。

未配对时也能点击“检查连接”，只读取平台模式和本机 health，不申请凭证、不查询 BOSS、不清理登录、不重放业务请求。仍需用户在实际 Windows 浏览器确认本地网络权限，具体电脑的连接原因以此诊断结果为准。

包含首次权限失败、明确拒绝权限、首次等待、平台不可达、只读诊断和页面入口的 183 项桌面及网页检查通过；安装包源码无需改动。
