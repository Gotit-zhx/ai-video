# 招聘助手连接故障：2026-10-08

> 历史发布记录；镜像、测试与“当前/最新”均指记录当时。 当前入口见[业务说明](../../business/README.md)与[运维指南](../../guides/operations.md)。

本机 0.1.14 助手 `/health` 正常。线上配对服务存活，但根磁盘可用空间为零。
以 `heyi-boss` 服务用户执行 SQLite 写入并回滚，复现
`sqlite3.OperationalError: database or disk is full`。这解释了配对接口的 503，
无需删除 Cookie、重新扫码或改变 BOSS 网络环境。

清理七天前的 Docker 构建缓存及无标签闲置镜像后，普通用户仍无可用空间。
随后对旧部署目录的不可变构建文件按 SHA-256、大小、所有者和权限核对，
将 102 份重复文件合并为硬链接，释放 6,917,225,969 字节。
所有文件路径、代码、回滚包和业务数据库保留。磁盘可用空间恢复至约 5.8 GiB；
配对数据库写入成功，原网页自动显示“招聘账号已就绪”。

自动恢复后，网页仍保留之前手动连接失败的错误提示。现在只清除已恢复的连接错误，
保留未确认的退出登录错误。配对服务对空间不足返回 `STORAGE_FULL`，安全日志只记录
错误码，不记录异常原文、路径、Token、Cookie 或简历内容。

验证：92 项 Python 测试、53 项网页连接及工作台测试通过，均为离线测试。
旧简历轮询测试固定其样例时钟，避免样例在七天有效期外自然失效。

## 发布与空间维护

`release-desktop-reconnect.py` 发布前要求至少 2 GiB 可用空间。它沿用线上最新镜像
和代码，验证文件哈希，保留回滚，并核对业务容器和挂载未改变。

`deduplicate-release-artifacts.py` 默认只检查；明确加 `--apply` 才进行合并。
范围固定为 `/opt/heyi/releases`、`/opt/heyi/deployments`，仅处理七天前的
JAR、ZIP、EXE、DMG、GZ 构建文件；拒绝容器挂载的归档路径，跳过符号链接和共享文件。
不处理业务数据库、Cookie 或用户上传文件。

归档文件合并后保持不可变；重新构建或恢复时通过新文件和原子替换写入，
不可对已有归档文件原地覆盖，否则同内容的其他归档路径也会受到影响。

空间仍会受业务增长影响。发布检查只约束该发布入口，不是全服务器磁盘监控；
本次没有添加定时清理或更改磁盘预留配置。
