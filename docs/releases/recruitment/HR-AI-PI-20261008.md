## 实现

所有招聘 AI 模式（需求分析、简历匹配、参考画像、寻源条件核对）
改为 Java 调用 pi-runtime 内网认证接口 `/v1/recruitment/analyze`。
该接口实际调用 `@earendil-works/pi-ai` 0.82.1 的 `streamSimple`，
没有代理工具、BOSS 操作、fallback 模型或自动重试；`maxRetries=0`。
选中的 DRIVER 在每次请求开始时固定，不改变平台全局配置。

适配 GPT 推理模型的 completion token 字段与低推理档，
其它兼容模型使用普通 token 字段；统一 URL 处理，完整 endpoint 不重复拼接。
SDK 只读取文本，思考内容、供应商错误正文、凭据不传入进度或日志。
完整返回后可规范化 JSON 语法，但岗位三份结构及候选人/条件 ID
仍由 Java 严格校验，缺失项不补造。截断、工具调用、断流均失败。
单次最多 10,000 输出 token、五分钟、200,000 字；错误不重发请求。
供应商停机、权限错误或模型不遵守结构仍可能失败，会显示安全诊断。

需求记录新增 `ai_progress`，按 owner、需求 ID、ai_job 和 running 状态更新；
旧任务和已完成任务的迟到进度不能覆盖新状态。Python 同一响应读取 SSE，
保留旧 JSON 兼容，不因此新增第二次请求。错误白名单接受已知 HR_AI 后缀，
仍不展示任意供应商文本。寻源错误码同步兼容。

黑白进度条展示提交、模型生成、结构校验、完成四个阶段，
生成期间显示动画、等待时间和实际接收字数，不伪造完成百分比。
关闭并重新打开需求可恢复后台进度；失败停止动画并保留需求及旧分析。

截断及断流、进度恢复、旧任务不能覆盖和不重复付费提交。
