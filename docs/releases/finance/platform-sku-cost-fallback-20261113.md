# 订单成本平台 SKU 兜底验收

日期：2026-11-13。用户要求将 2026-11-12 的平台 SPU 兜底调整为平台 SKU 兜底，并直接同步共享服务器。功能分支 `feature/finance-platform-sku-fallback`，基于 `develop` 的 `5133612`。

## 规则与兼容

- 当前公司、分组、成本仓内，先匹配商品 SKU（保留格式规范化及既有组合装规则），未唯一命中时使用平台 SKU；两者未唯一命中才提示人工确认。平台 SPU 不再参与自动兜底。
- Shopee 使用原订单的 `model_id`，TikTok 使用 `sku_id`。订单成本表“商品 SKU”右侧改为“平台 SKU”，同单去空、去重、分行，编号保持文本精度。保留原始商家 SKU 与商品 SPU 数据，新增独立的 `platform_sku_values` 展示字段。
- 保留人工确认、独立手动价格、GIFT、取消订单和实际履约成本的优先级。商品 SKU 已命中但价格无效时不切换平台 SKU 价格；平台 SKU 匹配系数为 1，不借用失败的组合装倍数。
- 新自动关系方法为 `PLATFORM_SKU_CODE`，计算行标记 `matchedBy=PLATFORM_SKU`。历史 `SPU_CODE` 仍归类为自动关系，按新规则重判，避免误作人工确认。计算源哈希更换为 `sku-platform-sku-standard-v1:`，旧结果在后续同步或既有后台重算时更新。
- 无迁移、配置或依赖变更；未将全历史成本入队。旧的持久化计算结果不因页面刷新立即更新。

## 验证

- 修改测试后，旧实现出现 7 项 Java 断言失败，页面失败于缺少“平台 SKU”列，确认测试覆盖了此次行为差异。
- 修改后 69 项 Java 单元、66 项隔离 MySQL 集成测试通过，失败/错误/跳过均为 0。覆盖两平台真实混合型号 CSV 导入、后台成本计算、订单查询、公司隔离、逐仓关联、人工关系保留及旧 SPU 策略结果重新入队。隔离测试库和临时数据库用户已移除。
- 36 组财务页面回归通过，包括平台 SKU 列顺序、长编号、商品 SKU 优先、平台 SKU 兜底、SPU 不参与兜底、旧自动关系兼容及大目录索引预算。
- 定向合并后的服务器前端回归发现其缺少 `develop` 已有的“未知成本仓保持待补齐”保护；同步时补回同一行既有校验，避免前端自动提示与后端计算不一致。
