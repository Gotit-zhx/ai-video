# 待补齐订单商品识别与成本核对

> 历史发布记录；镜像、测试与“当前/最新”均指记录当时。 当前入口见[业务说明](../../business/README.md)与[运维指南](../../guides/operations.md)。

版本：`finance-sku-identities-20261026`

## 使用方式

- 待补齐订单缺少商家 SKU 时，列表显示原订单商品图、名称、规格、购买数量、平台 SKU 和 SPU，并明确标记“商家 SKU 未提供”。商品图片无法加载时显示占位提示，其余信息仍可查看。
- 点击“核对关联”进入对应店铺、SPU 和 SKU 的关联位置，再核对真实成本型号及计价单位。沿用现有关联保存和历史订单重算流程。
- 从订单成本进入关联页后，可点击“返回待补齐订单”恢复原店铺、日期、筛选和页码。
- 订单计算明细及 Excel 导出同步补充商品身份；正常商家 SKU 仍保留紧凑显示。

## 实现边界

- 身份信息来自已同步的原订单商品行，不新增平台请求或逐行 SQL 查询。
- 只返回商品身份字段，不返回买家信息或完整平台原始数据。平台 ID 按字符串处理，避免大整数精度丢失。
- 平台 SKU 仅用于识别和定位，不冒充商家 SKU，也不自动指定成本型号。
- 本次未改动成本公式、成本关联、价格或结算金额。缺失成本继续显示待补齐，不按零计算利润。

## 验证与发布

- 113 项后端测试通过，包含隔离 MySQL 集成测试、混合商品身份、导出和商品行匹配回退。
- 4 项前端测试脚本通过，覆盖身份显示、图片失败占位、详情规格回退、准确定位 SKU、展开折叠店铺及返回时保留筛选。
- 独立浏览器测试页面检查了列表和明细布局。
- 生产只读核对覆盖所排查店铺历史范围内的 252 笔待补齐订单、6 页分页及 Excel 导出，均能读取原订单商品身份。缺失商家 SKU 的 3 个规格仍需核对真实成本型号。
- 发布仅替换 3 个后端类族和 5 个前端文件；数据库保持 V131，前端普通及 gzip 资源、匿名访问权限和服务健康检查通过。
- 发布后以实际部署的类重新读取生产数据，核对订单数量、已知成本、结算及平台费用合计；保留版本回滚资料及验证日志。
