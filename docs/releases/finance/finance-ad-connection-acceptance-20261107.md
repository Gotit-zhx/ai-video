### 验收探针误判的纠正

最初把临时 Java 验收容器限制为 0.5 CPU，新的 JVM 首次 TLS 握手失败。后续同一 JVM 不改参数即可成功；用原生产客户端、相同默认 TLS 1.3，在新容器中仅将临时额度调至 2 CPU，首次请求即通过。生产应用本身没有该 CPU 限额，原生代理限额也未改变。最终整体验收使用修正后的临时探针，并移除探针容器。

SNI 与 TLS 1.2 诊断曾出现成功结果，但进一步观察确认默认 ClientHello 已发送正确 SNI，这些结果受到进程预热影响。没有将 SNI 补丁或 TLS 降级提交到生产；未创建 v10 发布。先前失败回执与探针修正回执一并保留。
