# 广告消耗主表布局修复 — 2026-11-11

修复从已发布 `v2026.11.11.2` 的生产提交 `3e5b23f43d734e581b481deefcd4ff8ee51b38eb` 开始，使用 `hotfix/2026.11.11.3-ad-spend-layout`。正式激活以该版本的 GitHub Release 和服务器回执为准。

## 原因与修复

`.fi-ad-spend` 使用 12 列栅格，而 `.fi-span-12` 原规则只对 `.fi-chart-grid` 的直接子元素生效。三张主表卡片在广告容器里没有跨列，真实 840 像素窗口下每张卡片只有约 52 像素，出现文字竖排、表格拥挤和大面积空白。早期本地预览 helper 的行内 `grid-column:span 12` 掩盖了生产类选择器的缺口，DOM 内容回归无法发现几何布局问题。

修复仅为广告容器的直接卡片设置完整跨列，保留内层金额卡片响应式排列、表格自身横向滚动及既有数据/权限/计算逻辑。CSS 缓存版本同步更新为 `20261111-ad-spend-layout-1`。本地预览 helper 去掉额外行内跨列，按生产类结构验证。

## 验证

- 真实旧页面复现：容器约 796 像素，三卡片分别约 52 像素。
- 修复后真实浏览器 840 像素窗口：容器及三卡片均为 784 像素，顺序分行，标题区域高度正常，页面没有横向溢出。
- 480 像素窄屏：容器及三卡片均为 424 像素，三张表在自身滚动容器内横向滚动，页面没有横向溢出；测试结束恢复默认视口。
- 完整前端回归、35 组 UI 及静态资源引用检查通过。正式站点布局仍须在激活后用同样的实际宽度与截图验收，不能只凭字段存在判定样式正确。

本次不修改数据库、授权凭据、同步计划或原财务事实，不把本地工作簿数据导入生产。
