# 财务 BI 首次结算成本与店铺日期增量验收

2026-11-19，北京时间。关联[上一阶段压测](finance-bi-scale-20261119.md)。

## 实施范围

- V163 新增已发布的结算成本日事实和待补算的店铺日期表。V164 将币种和部分月口径纳入事实键，升级时保留原来的派生数据并要求重新确认覆盖。结算成本先按原口径找出订单最早有效的结算日，再在所查币种范围里去掉同日的重复流水。为空币种或指定币种分别保存结果，避免同日多币种重复计费。已确认归属月的记录沿用整月口径，部分月首日使用独立事实。
- 现有已发布月度基线可按需补齐成本，原账本正文和原生成时间继续有效。数据不足时走已有权威汇总。成本金额保存十进制文本。未知、待补齐、刷单排除、标签费用和成本任务优先级沿用既有判定。
- 北京时间业务月划分仍通过现有日历和日期校正逻辑。变更事件在确认前解析同订单的关联日期与账单，保留原、新店铺及日期。日常变动限制在受影响的店铺和日期。新增成本分片和账本的版本提交在同一租约保护事务完成。高密度或全局失效仍采用覆盖扫描。
- 读取端可在同一只读快照内将已发布的干净片段与限量的当前脏片段组合。单次最多解析 256 个待处理事件，店铺日期按有界工作量分配修补预算。待领取事件和已登记脏日共同参与判断。修补后的结果保留 PENDING 状态，未使用 Redis 保存；只有按原校验通过的完整版本进入常规投影缓存。编号明细、币种、分组和租户可见范围沿用原查询。

## 脱敏与隔离

在共享服务器只读提取有界范围。远端查询先将店铺、订单、账单、导入批次等编号映射为本次专用的稳定摘要，将货币金额以同一随机因子缩放，保留正负、零、缺失、币种及关联关系。日期及必要的归属标志保留，原始 JSON、店铺凭据、个人资料、票据和可识别名称均省略。账本的每个日期通过独立读取获取，同一个月的提取跨越多个读取快照。进行业务等价比较时，候选与原生算法使用同一脱敏数据及快照。

装载仅写入当前工作区独占的开发 MySQL。压测使用真实应用、历史汇率、Redis 和 Chrome，五个独立浏览器上下文按路由并发。从发起已登录路由导航计时，等主表、摘要和有数据的图表完成。每个批次清理该公司 Redis 财务响应快照，MySQL buffer pool 及进程内事实保留。25 秒超时按下界计入失败。


真实脱敏夹具覆盖 2026-10 整月、9 月末至 11 月初的相邻日期和 11 月 19 日的订单。10 月账本为 3,352,614 行，涉及 87 家店铺记录，其中包括 2,443,466 条平台费用、332,244 条结算明细和 184,069 条账单。另有 436,001 条订单成本、298,609 条贴单明细、323,028 条贴单订单汇总、5,228 条退件和 27 条历史归属月确认。日期范围以外的全历史流水、服务凭证、个性化配置和部分非关键来源字段省略。历史账号映射为隔离登录账号，租户与权限规则另由真实 MySQL 回归覆盖。

隔离 MySQL 为 8.4，buffer pool 为 2.5 GiB。装载时暂时减少隔离账本的二级索引，压测前按原始列定义、列序和升降序恢复并核对。初次投影开始前从脱敏账本初始化；随后每笔压测更新均由实际触发器登记。V163 原迁移文件保留，启动时 Flyway 校验通过并将隔离 schema 从 V163 升级到 V164。

- 已发布投影可用时 9/9 页通过，结算中心最慢 2.063 秒。
- 单店持续写入时 6/9 页通过。47.45 秒内提交 258 笔事务并更新 2,623 行，其中 43 条为订单成本变更。投影最多落后 42 个修订，关联订单及账单使待补算范围扩展至 29 个店铺日期。停写约 24.6 秒后账本与结算成本投影均追平。
- 全月分散写入时 5/9 页通过。94.12 秒内提交 510 笔事务并更新 5,185 行，其中 85 条为订单成本变更。投影最多落后 82 个修订，观测峰值为 873 个脏店铺日期，其中最多 508 个涉及结算成本。停写约 96.1 秒后两个投影修订均对齐。两轮写入器均未报告错误。
- 单店场景在 10 月最后一周的选定高负载店铺内选取真实脱敏记录。全月场景跨店铺及整月选择，每约 200 毫秒更新一批费用和结算金额，另每五批调整一次订单成本。费用和结算列表采用既有金额与明细口径；超出实时补算预算时走同一快照的权威回退。

持续写入的长尾集中在两个阶段。大量相关店铺日期同时变动时，仍需完整权威查询。保存的经营账本主体在发布时仍按月序列化，跨店广泛写入的构建与前台查询也会竞争 MySQL 和应用资源。结算和费用页全月场景达到浏览器超时阈值，成本管理默认贴单账单也超过 5 秒。

同一脱敏库另试过在修补汇总后按当前页面重新计数。该轮单店写入有 4/9 页通过，费用页最慢 21.815 秒；全月写入有 4/9 页通过。保留表中使用的分片计数实现。两轮的事务数和资源争用各有差异，结果用于本轮候选取舍。

复跑采用现有 `scripts/qa/test-finance-bi-latency.mjs`，设置 `FINANCE_BI_MONTH=2026-10`、`FINANCE_BI_COLD_REDIS=1`、`FINANCE_BI_SAMPLES=5`、`FINANCE_BI_CONCURRENCY=5`、`FINANCE_BI_TIMEOUT_MS=25000`，指向当前工作区隔离应用。持续写入时按上述比例追加事务，并同步采样请求修订、账本修订、结算成本修订及脏日。每页为最慢样本观测，额外的 3 秒 P95 预算和筛选页签仍可单独验证。

## 财务口径核对

在同一个隔离 MySQL 只读可重复读事务内比较首次结算成本的完整响应。先读取新投影，再执行既有原生汇总。按店铺标识排序，金额按十进制比较；只记录是否等价和计时。

| 结算成本范围 | 结果 | 新投影 | 原生汇总 |
| --- | --- | ---: | ---: |
| 全公司整月、全币种 | 一致 | 88 ms | 6,033 ms |
| 全公司整月、PHP | 一致 | 15 ms | 4,017 ms |
| 部分月 | 一致 | 11 ms | 1,997 ms |
| 单店整月 | 一致 | 4 ms | 913 ms |

上述单次 SQL 读和汇总计时独立于九页浏览器指标。回归还覆盖同日多币种重复结算、跨月前移前后的新旧归属、确认归属月、金额六位小数、成本任务及贴单代次、晚提交和租户隔离。八个相关 Java 套件共 171 项执行通过，另有财务查询、对账两项前端回归通过。生产保持现行运行源码，共享库只执行了有界只读查询，现场 Flyway V160 编号差异继续按迁移历史处理。

最终保留的分片计数源码再次通过基线、预热和专页查询三个数据库套件。隔离应用、MySQL、Redis、临时卷、掩码密钥和逐行传输文件已清理，验收目录仅保留计时、计数、水位和测试结果。
