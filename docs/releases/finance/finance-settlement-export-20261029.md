# 结算中心导出与成本日期筛选

> 历史发布记录；镜像、测试与“当前/最新”均指记录当时。 当前入口见[业务说明](../../business/README.md)与[运维指南](../../guides/operations.md)。

## 问题

结算中心仅有页首通用报表入口，明细表附近缺少导出操作。成本管理直接进入时使用独立的最近 30 天，没有承接财务日历。

成本的 `ORDER` 范围已按首次结算筛选，但没有指定记录的 `BILL` / `RECONCILIATION` 范围仍先按账单日期筛选。正式数据核对：订单 `586208660231587825` 的结算归属为 `2026-10`，对应账单日期仍为 `2026-09-30`，因此从账单范围查询成本会跨月混入。

## 修改

- 结算明细、结算账单、待结算表头增加「导出 Excel」，默认当前页签，沿用已有导出字段设置。
- 导出固定打开窗口时的日期、分组、店铺、平台、币种、汇率快照及编号；导出全部匹配记录，不受分页影响。增加等待状态、防重复点击、超时与错误反馈，关闭窗口中止请求。
- 成本管理承接财务日历；修改成本日期同步保存到财务筛选。页面与导出使用同一个筛选快照，日期不合法或初次读取未完成时不能导出。
- 未指定记录的账单、对账成本范围改用首次结算归属。明确指定单张账单时仍核对该账单的完整关联订单，页面标明此时日期筛选不适用。
- 成本 Excel 的订单成本和 SKU 成本明细将「结算归属日期」提前；保留下单日期作为核对列。成本单价、取价月份、取消单排除与刷单排除规则保持原口径。
- 按月校正仍只在覆盖整月时计入，不编造官方完成日；成本页补充「查看该月整月」入口。

## 验证与发布

- 44 项后端单元测试、3 项前端场景脚本通过。
- 独立临时 MySQL 库回归通过：八月下单九月结算、九月账单十月归属、取消单成本、期间导出与单账单核对；测试库与账号已清理。
- 受影响 Java 类的修改前编译结果与生产逐字节一致，三个前端文件的修改前内容与生产一致。
- 正式发布目录：`/opt/heyi/releases/finance-settlement-export-20261029`。
- 正式镜像：`ai-commerce-platform:finance-settlement-export-20261029`、`ai-commerce-frontend:finance-settlement-export-20261029-2`。
- 只覆盖 `FinanceCostReport`、`FinanceCostExport` 及三个前端文件；其余 JAR 内容、配置、MySQL、Redis 与 Flyway 134 保持原状。
- 已验证服务健康、静态资源及 gzip 内容、未登录导出接口拒绝访问。发布时等待正在执行的任务结束，之后恢复财务同步调度，未清除同步断点。
- 使用线上实际部署类和临时 SELECT-only 账号，逐一核对订单、账单、对账三个入口的页面及生成的成本 Excel：原先 15 笔订单均在九月，另 27 笔均在十月。校验后已删除临时账号。
- 收尾的前端覆盖保留成本导出期间的禁用状态，后台刷新不会重新启用下载按钮；此步未重启后端。

这次修复没有新增平台订单完成时间字段；已确认归属月份的订单继续明确标注“按月校正”。
