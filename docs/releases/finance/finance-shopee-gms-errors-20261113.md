# Shopee GMS 无计划返回的排查与修复

2026-11-13 对原有八家 GMS 异常店铺逐家进行一次官方只读报表核查，窗口为 2026-10-01 至 2026-10-30，符合至多 30 个业务日的限制。八次均为 HTTP 200、`ads_error_product_gms_campaign_not_found`，没有有效计划 ID 或费用字段，没有 warning。脱敏结果仅保留错误码、请求标识和响应形状；未保存完整响应或凭据。

这表明官方在该查询中未找到 GMS 计划。八家原状态均为 ERROR、没有已识别计划或有效十月日报。用户随后明确要求“未找 GMS 计划的直接标 0，并提示未找到 GMS 计划”，本次以该明确业务规则统计；与实际日报明确返回零费用的来源分别留证。

系统另有两处错误处理缺陷：Shopee 客户端在上游同时返回 message 时丢失 error 的结构化身份，GMS 采集随后将其泛化成“报表未完成”。修复后客户端保留安全结构化错误码并兼容原异常文本；GMS 采集对该具体返回及空历史计划集合，按实际请求窗发布政策零值，状态 PARTIAL 并明确提示“未找到 GMS 计划，按 0 统计”。其他错误继续按权限、授权、限流或一般异常处理，不根据上游自由文本冒充无计划。

本次调整三份后端源码及相关测试、说明，不改变 CPC 减 GMS 的公式、原始 CPC、凭据、数据库结构或前端。政策零事实带 `SHOPEE_GMS_NO_CAMPAIGN_ZERO_V1`、官方错误码、请求边界及独立范围版本，正常推进已查询窗口的检查点并每小时复查。已有历史计划继续读取真实日报，已有非政策历史事实不能被无计划回复覆盖；以后发现真实计划会使旧范围零值失效并重核历史。暂停、授权或应用配置变化后的晚返回仍被发布守卫拒绝。

回归覆盖结构化错误码、畸形错误码脱敏、原刊登拒绝和规格同步重试兼容，以及无计划窗口零值、31 日边缘、后续真实计划重核、历史非零保护、暂停晚返回和各表/导出一致。新增政策用例在实现前有 3 项断言失败、0 执行错误；正式回归数量与生效结果另记实际回执。

最终本地回归共 138 项通过、0 失败/执行错误/跳过：85 项单元测试，19 项 GMS、22 项 CPC、6 项 GMS 报表、6 项广告导入/归属集成测试。数据库测试仅运行在本任务可销毁 MySQL 库。独立复审 Critical 0、Important 0；原异常文本兼容及畸形错误码脱敏均有真实客户端到调用方的回归保护。无计划返回伴随不完整 warning 时仍保留未知，不触发政策零值。
