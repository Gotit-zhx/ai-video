# 贴单明确零金额及状态简化

> 历史发布记录；镜像、测试与“当前/最新”均指记录当时。 当前入口见[业务说明](../../business/README.md)与[运维指南](../../guides/operations.md)。

用户确认：原表金额明确填写 0 时就是实际 0 元，不应因原表计费状态文字标成失败。

- 导入以数值金额为准，0 正常计入；原表计费状态仅保留为来源资料，不作为金额有效性的判断。
- 金额为空、非法金额、公式未转值、明确的单价/数量乘积冲突、非人民币及账单合计不符仍会拒绝。
- 费用明细中有正式费用类型的记录优先于同一订单/日期/仓库的通用零额占位，跨文件来源仍去重。
- 已导入来源的旧 `billing_priority=0` 在汇总时按实际数值重新解释，保留原始行和原始金额，不要求重传。
- 去掉“原表计费失败”快捷筛选、下拉项、文件问题计数和行标签。保留待匹配、已匹配及金额/归属冲突。
- 指标改为“结算期贴单金额”，说明 9 月贴单、10 月结算会计入 10 月。
- 同时补上千易真实限流响应的共享冷却和降速，防止各店独立重试导致请求拥挤。

验证：

- 13 项精确线上 JAR 的隔离 MySQL 贴单集成测试通过，包括旧零元来源重新计算、并发入队、
  锁住账单时订单继续同步、跨月结算、重复来源和删源。
- 本地金额解析 5 项通过，1 项需要专用样例文件的测试跳过；千易客户端 6 项通过。
- 账单界面测试通过，确认没有计费失败控件，旧计费失败来源显示 0.00 和正常匹配状态。
- 已发布 `ai-commerce-platform:finance-label-zero-20261030`、
  `ai-commerce-frontend:finance-label-zero-20261030`；schema 保持 139。
- 后端只替换贴单解析、贴单计算、千易客户端 3 个类族；前端只替换贴单工作区及对应缓存版本。
  原订单同步队列修复、千易配置和其他应用内容保留。
- 已请求后台重新生成现有账单汇总，原始金额和来源行均未修改。
