## 使用方式

1. 在“成本管理 → 商品成本表”上传 XLSX/CSV，说明计价单位、SKU/SPU/混合类型、原始来源、操作原因和依据。表头在同一行，仓库逐行明确；公式转值，长编号保留文本，金额为 CNY。系统不再用前言或上一行内容猜缺失仓库。
2. 上传只产生暂存核对单，现有成本资料不立即变更。设置、手动成本、人工关联和删除也走同一暂存机制。
3. 打开“导入与操作核对”，核对实际分组/店铺、来源、单位、编号类型、SPU 统一成本声明、旧新值及来源、校验原因和真实影响范围。
4. 普通资料待核对不等同必须他人审批；有权限者可按核对单要求确认。改价覆盖、已有人工关系替换、仓/口径/换算变化、删除、大范围及 MIXED 待核验资料需要另一位同公司财务管理人员确认，提交者不能自审。
5. 涉及已有订单时必须确认历史影响。当前查询月份不会限制原保存逻辑；固定人工价仍适用于相关规格的历史及后续订单，本次只增加明确提示和门控，不新增计价期间规则。
6. 确认前服务端重查配置、范围和版本；过期单先重新预览，硬错误不能忽略。表格内容错误需修原表重传；资料说明可“补充资料”重新校验。重复提交/确认不会重复保存与入队。
7. 已应用后的“撤销本次操作”生成反向核对单，须再次校验和独立复核。存在后续人工依赖或配置变化时拒绝恢复，不删除其他已确认操作的有效资料。应用或撤销均沿用原后台重算流程。

影响数量是已入库订单范围上界，不是精确受影响订单数；金额影响未核定时明确显示未知。未同步订单没有被宣称完整覆盖。未知零价不当真实零，真实手动零价仍使用原单独确认流程；GIFT 规则不变。

## 实现保护

- V153 仅新增 `finance_cost_input_changes`，记录显式人工输入、文件/语义哈希、校验、目标原状态、基线和确认记录。新上传的原文件可按哈希引用已有副本；公开接口不返回原 bytes、完整 payload/state 或无界订单资料。旧来源已有的解析资料保留，不伪造此前未保留的原始工作簿。
- 所有原注解人工 HTTP 成本写入口先暂存；校验通过后在事务中调用原保存函数。公司、管理权限、独立确认人、版本、硬错误、修订及范围确认都由服务端执行。
- XLSX 数字编号先检查安全整数/位数，再转确定性字符串，预览、JSON 持久化及应用保持同一业务键。文本长编号和前导零不改。极端指数使用有界编码，不展开巨量十进制字符串。
- 反向操作检查后续显式人工关联，排除四种自动 method，避免普通自动关联随机使预览过期。输入操作统一分组、草稿、原操作的锁顺序；组路由的非权威查询在本次事务外，组锁后再建立有效配置快照。
- 详情显示未知值，不把来源声明当作真实性证明。客户端写入按钮结合只读权限和服务端能力标记；已销毁视图不因旧请求返回刷新新页面。列表轮询只查询，失败保留当前已读内容。
- 人工改价预览按实际局部更新生成旧新值，不将未修改的型号和仓库误报为删除。服务端持久保存有界目标/单位摘要，未变单位也可由独立复核者核对，且优先于客户端填写的单位说明。
