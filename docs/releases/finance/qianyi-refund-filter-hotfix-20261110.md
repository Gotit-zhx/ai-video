# 千易退款筛选参数紧急修复

目标版本：`v2026.11.10`。生产基线为 `v2026.11.9` / `a727b7c62af8926074d3e1f32bc2339f12f08bd5`，修复分支为 `hotfix/2026.11.10-qianyi-refund-filters`。本文记录修复和发布前验证；实际激活结果以正式 Release 附件与服务器回执为准。

## 问题与修复

千易退款页保存筛选时给未设置的 `costStatus` 建立了 `undefined` 值。刷新或重新进入时，这个值被带回查询并序列化成 `costStatus=undefined`，后端按状态格式拒绝，页面出现“千易状态筛选不正确”。线上静态脚本哈希与复现版本一致，原千易单据仍在入库。

保存筛选状态时过滤 `null` / `undefined`，保留用户主动清空的空字符串。金额、收货日期、单据资格、公司隔离、后端状态校验及同步检查点继续沿用。仅前端组件输入变化，使用现有后端镜像，无数据库或控制面升级。

## 验证与发布

- 新增真实前端刷新回归，并在上游替身中遵循后端的状态格式约束。旧代码明确失败且显示原错误，修复后通过。
- 验证初始筛选、刷新、切换订单后重新进入退款、清空类型/状态/日期、分页、导出及过期响应隔离；千易弹窗原回归与静态资源引用检查通过。
- 候选仍须完成全部必需 CI、准确镜像的容器冒烟、来源证明、源码/镜像摘要及现场空间预算检查。生产操作持双锁，沿用 10 GiB 保护线及额外临时预算，不清理业务数据或备份。
- 按 Gitflow 合入生产并打正式标签，标准 Production deployment 激活后检查真实退款页首载、重复刷新、切换回返和列表；再将 hotfix 合回 `develop`。不将页面恢复等同全部千易数据已经对账。
