# 财务广告数据质量修复

目标版本：`v2026.11.10.2`。生产基线 `v2026.11.10.1`，生产合并 `22e659fd57944590cb0a4137cb583f6bb01aaecf`；修复分支 `hotfix/2026.11.10.2-ad-report-coverage`。本文记录修复与发布前证据，正式激活结果以 Release 附件和服务器回执为准。

## 问题及行为

空报表原先写入覆盖天数和金额零，界面据此显示“接口返回零消耗”，把“接口没有给出记录”误作完整业务结论。本次使用返回记录数区分空报表、合计零、未知和部分日期，新增记录数列及当前筛选下的店铺关系范围。发现尚未完成或失败时保留未知状态，不断言未授权。普通 BASIC 明确不包含部分 Shop 创建的 GMV Max，当前投放可用性不代替真实历史资格。

暂停后重新授权原先会自动重新启用；暂停/恢复也未撤销在途租约。本次保留暂停与断点，显式暂停/恢复撤销旧租约。暂停账户仍参与专属店铺的导入防重，恢复前再检查冲突；未来退避保留。导入拒绝明确充值、转账或未拆分混合字段当成实际投放消耗。

刷新如未返回已有事实日期的记录，改为保留该窗口原金额、覆盖和检查点，提示待核对并自动退避；明确返回的零消耗仍可正常替换旧金额。分页对空响应也核对页码和记录总数字段格式。

令牌交换未返回账户编号时，授权补查接口原先将 token 放 query，触发平台认证拒绝。本次按官方契约改为 Access-Token header，保留字符串 app_id/secret、会话应用分路、原子保存及脱敏失败阶段，不重放授权码。

## 真实只读核对

2026-11-10 校验正式运行镜像与配置后，持两把共享发布锁执行有界、只读官方差分：

- 公司 40 家 TikTok 财务店铺、28 个已启用广告账户；发现关系实际仅关联两家唯一财务店铺。其余 38 家未在现有关系范围内，不能据此填零。
- 两店 10 月 GMV Max 整月 overview 与已入库合计一致。抽样日的现有查询、PRODUCT/LIVE 拆分和 overview 合计一致，未证实当前查询造成样本漏算，未盲改 GMV 请求或扩大计费口径。
- 28 个账户的普通 BASIC 月报均 code=0、空 list、total_number=0。这证明未返回普通报表记录，不能证明全部媒体消耗为零。
- 当前不可投放标志的账户仍有非零历史，因此继续读取并保留历史费用。
- 账户发现的原请求返回 40104，属于缺少正确位置的 token。保持同一 token、应用和密钥，仅修正 header 后 code=0，返回 28 个账户，与本地现有账户一致；没有自动扩大授权或新增账户。

探针不启动 Spring、迁移或财务写入，不输出凭据、账户编号及完整请求/响应；临时 JVM/类文件按本次唯一目录清除。逐账户金额只保留在私有小型回执，未纳入 Git。

## 财务口径与保护

平台账单广告费与广告佣金按结算口径分项，已包含在平台费用的部分不再次扣利润；独立 AD 只额外扣一次。GMV Max 专项与普通广告/账单覆盖未证实时不直接相加，归因收入不代替销售收入或净利润。充值非消耗、退款不重复扣、参考汇率和公司隔离保持。

保留 v2026.11.10.1 的千易筛选 undefined 过滤及请求内共享成本索引修复，不改数据库迁移、控制面、连接配置、同步计划或上游限流。
