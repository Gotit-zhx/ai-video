# 广告总览来源与 GMV Max 显示修复

目标版本 `v2026.11.10.4`，支持分支 `hotfix/2026.11.10.4-ad-overview-sources`。本修复在已发布 v2026.11.10.2 上开发；正式候选须纳入串行发布的成本及导出修复 v2026.11.10.3，不能覆盖另一会话的工作。本文记录发布前结果，实际激活以正式 Release 回执为准。

## 问题和修复

总览的「广告费用」是账单广告费与普通独立 `AD` 的已入账合计，「其中广告佣金」是其子集。GMV Max 专项因与账单和普通报表的覆盖尚待核对而不直接相加；此前总览分组及店铺表未提供专项列，使已有 GMV Max 记录的店铺看起来没有广告数据。

本次在总览卡片增加 GMV Max 报表分项，在分组和店铺经营明细增加「GMV Max 报表消耗（待核对）」列；包括仅有专项费用、没有订单排行或普通广告的店铺与分组。已入账合计、佣金包含关系、原币/人民币换算及利润计算不变。普通独立明细页签改为明确名称，并说明另两个来源的入口。Shopee 来源提示按店铺、分组、平台及原币范围显示。

广告卡片原先固定打开普通 `AD` 明细，导致卡片金额来自结算广告费时，下钻却见空表。本次按真实记录选择默认来源：普通 `AD` 有记录时沿用，否则先选账单 `FEE`、再选专项 `AD_GMV`。新增 DOM 红绿用例验证账单来源及仅专项来源均打开相应页签，记录、分页、导出和金额保持独立。

## 原始来源核对

- TikTok 使用 Shop 结算交易 `fee_tax_breakdown` 派生广告费用。抽样用结算记录主键反查原始叶子，核对来源金额、取反符号、日期及汇率后，截图的两列数值可解释；没有发现两列重复绑定或佣金重复加计。
- Shopee 现有结算适配已解析 `order_income.pay_per_sale`。抽样返回零时不派生非零广告费；普通 AMS 佣金及充值/技术支持混合字段不应拿来填广告列。少量抽样不能证明整月真实投放为零。
- 现用 Shopee 应用的 CPC/GMS 报表在 PH/TH/MY 六次只读调用均返回 HTTP 403 / `error_api_permission`。默认浏览器应用列表仅见一款 ERP System 应用，与现用 Partner 身份一致；未找到另一个已获 Ads 权限的应用。不修改密钥或授权，不声称已补齐 Shopee 独立投放。
- v2026.11.10.2 激活后的 TikTok 全 56 组合官方核对发现三组历史缺口。经隔离 99 项合同测试、完整生产 DRY、独立审查后，定向补入 9,007 条真实 API GMV 明细；原始事实、其他来源、凭据、归属、stage、checkpoint 及调度均保留，最终全部授权范围的 10 月费用与官方逐日汇总一致。临时进程确认退出后清理，私有业务金额不进入本文件。

## 验证与边界

新增真实 DOM 回归先复现缺列及币种范围提示问题，再验证专项列、仅专项店铺/分组、卡片分项、缺失与真实零值、佣金及利润不重复相加；普通明细的新名称继续支持查询、分页和导出。完整前端回归和静态引用检查通过；正式候选和准确镜像仍需全部必需 CI、容器冒烟及来源证明。

本次显示修复无迁移、配置、控制面或后端费用计算变化。Shopee Ads 权限是外部接入条件，不能通过填零、重复授权或把其他佣金当广告费绕过。后续有权限的应用接入须单独核实令牌所属应用、CPC 与 GMS 覆盖关系、分页和数据完整性，不能只换一把密钥就复用原应用令牌。
