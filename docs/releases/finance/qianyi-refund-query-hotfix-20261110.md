# 千易退款全店铺成本汇总超时修复

目标版本：`v2026.11.10.1`，从生产 `v2026.11.10` / `d057541d64ec88efe7f04a9250df3ddd265856a4` 创建 hotfix。本文是发布准备记录，激活与真实页面结果以正式 Release 及服务器回执为准。

## 原因及实现

前一版本修复了状态参数序列化错误，真实全店铺查询随后暴露原有后端超时：退货成本汇总按店铺重复解析同一分组的大型成本书，且每笔退货单重建 SKU 索引。独立只读 Java 探针在相同生产代码和筛选下复现 `TransactionTimedOutException`，耗时约 16.6 秒，超过原 15 秒只读事务期限。

本次仅在单次 `FinanceQianyiReturnCostSummary` 请求内共享按组织/分组划分的成本目录，并按店铺复用退货专用 SKU 索引。保留北京时间收货月份、店铺成本仓、组合换算、历史单价、赠品、未知与部分成本，以及不采用平台商品 ID 猜测映射的规则；不改金额口径、权限、同步检查点、数据库或超时保护。

## 验证

- 两项新增性能回归在旧代码失败，修复后与原成本、千易退货单元测试合计 22 项通过。验证目录共享、公司隔离、下一请求读取新版本、索引复用及逐单收货月份。
- 独立只读探针仅在独立 JVM 中加载候选类，未启动 Spring、迁移或写入业务数据。在同一筛选下成功返回 2,596 笔和首屏 50 条，耗时约 4.4 秒；临时类及进程均已清理。此结果不等于全部金额与官方账目已对账。
- 本机默认隔离 Docker 套接字不可用，本地 MySQL 集成未执行成功；不使用已有服务器上下文运行测试。正式候选必须完成 GitHub 托管机上的隔离数据库、完整 CI、真实镜像冒烟和来源证明，再按 Gitflow 激活及合回。
- 发布后检查真实退款首载、重复刷新、切换返回及分页；原前端修复继续保留，所有业务卷、备份和后台同步恢复规则继续生效。
