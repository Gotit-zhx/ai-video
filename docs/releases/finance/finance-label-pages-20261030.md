修复「查看明细 / 查看全部」在大账单下等待过久，并增加「全部记录 / 原表计费失败 / 待匹配 / 已匹配」快捷筛选。

## 查询与界面

- 先验证文件属于当前公司，再按文件主键分页，每页最多 50 行；只对当前页关联店铺和费用状态。
- 来源总数直接查询来源行，避免在全部 28 万行上进行宽表关联及排序。
- 文件、状态、订单编号和分页请求使用 `detailsOnly=true`，不重复计算结算期间汇总。日期、分组、店铺改变仍重新计算期间汇总。
- 文件之间按上传时间倒序，文件内按原表行号排序；跨文件分页连续。
- 读取时保留旧表格并显示等待条，取消被后续操作替代的请求，旧响应不覆盖新筛选；超时显示重试提示。
- 快捷按钮与状态下拉框同步。原表计费失败与订单是否匹配是两个维度，因此同一行可以同时属于「原表计费失败」和「已匹配」。

本次只修改查询与界面，不修改成本金额、结算日期口径、导入队列、同步检查点或数据库结构。
