## 已确认的问题

11 月 7 日的新回调为 `FAILED / TIMEOUT`，账户未保存。生产宿主机和容器默认解析结果连接超时；使用可信 HTTPS DNS 返回的地址后，TCP 可建立，但 TLS 握手被重置。主机 IPv4/IPv6 的 OUTPUT 默认允许且无该链规则，应用没有配置代理或域名覆盖。

本轮仅对无凭据连接采集有界 TCP 元数据：握手往返约 155 毫秒；ClientHello 发出后约 4 毫秒收到多个 TTL、窗口等特征不同的 RST，约 155 毫秒后仍收到原连接的 ACK。这个时序与特征支持链路中存在连接干扰的判断，尚不能确定具体设备或运营环节。没有捕获授权码、令牌或业务请求，详细元数据仅保存在仓库外私有目录。

## 候选修复

- 新增 `FinanceAdHttp`，为授权码交换、账户发现、账户详情和后续广告报表提供同一个可选私有 HTTP CONNECT 通道。
- 仅广告组件使用该通道；通用 `MarketplaceHttp` 及 Shopee、TikTok Shop 等调用保持原连接。未配置时复用原客户端，不启用代理。
- 隧道仅允许 `https://business-api.tiktok.com:443`，保留目标域名、系统证书链和主机名校验，不接收 URI 内凭据，不自动改走其他路由，不跟随重定向。沿用完整响应超时和不重复提交授权 POST 的行为。
- 失败回执同时保留操作阶段和原因，例如 `[TOKEN_EXCHANGE][TIMEOUT]` 或 `[ACCOUNT_INFO][TLS]`，仅使用固定文案及数值平台错误码。
- 当令牌响应中的账户数组为空时，也调用官方 `/oauth2/advertiser/get/` 补查授权账户，避免将空数组直接视作最终列表。补查仍无账户时，明确提示平台已授权但未返回可接入账户；账户 ID 格式异常和指定账户未授权分别分类，不保存部分账户、不重放授权码。

服务端私有环境配置：

```dotenv
APP_TIKTOK_ADS_PROXY_HOST=
APP_TIKTOK_ADS_PROXY_PORT=0
```

主机为空且端口为 0 表示不启用；启用时同时填写应用容器可达的私有 CONNECT 主机和端口。连接地址不是 TikTok API 地址，也不接受带用户名、密码的代理 URL。配置由运维维护，不从浏览器或授权链接读取。

生产通道须部署在自有可达环境，经过私网或加密隧道连接，服务端限制来源及目标为官方广告接口，不暴露公共开放代理。代理转发 TLS 字节，不终止 TikTok TLS。不能把 CDN IP 永久写进 hosts，也不能关闭证书校验来掩盖连接失败。个人电脑隧道只适合临时验证，不能据此宣称长期生产连接已恢复。
