## 最小运行方案

候选采用单个原生 Xray 核心进程，仅提供私网 HTTP CONNECT，允许的目标为 `business-api.tiktok.com:443`，其他目标默认拒绝。没有 GUI、TUN、订阅转换服务、规则订阅或 GeoIP/GeoSite 数据库。官方运行制品固定版本和摘要，配置生成工具、systemd 限额及安装说明见 [ops/finance-ad-proxy](../../../ops/finance-ad-proxy/README.md)。

服务配置为一个 Go 调度核、32 MiB Go 内存目标、64 MiB 内存硬上限和 10% CPU 配额。启动及失败请求阶段观测到进程 RSS 约 31.7 MiB；这不是成功业务流量的峰值承诺，仍需节点有效后补测。目标 HTTPS 的证书校验保持启用。

应用可从已有挂载广告 properties 文件读取 `proxy-host` / `proxy-port`，保留应用 ID、密钥及加密 revision；无需新增 Docker 环境或挂载。该主机组件归入 `operations` 指纹，必须实际安装、验证并记录后才可登记指纹，不因源码同步而视为已安装。

## 节点验证结果

所有探测均不携带 TikTok 授权码、访问令牌或业务数据；未调用在线订阅转换服务。只使用用户提供的节点参数，完整凭据留在私有文件。

| 检查 | 结果 |
| --- | --- |
| ECS 到节点端口的 TCP 连接 | 可建立，约 2 秒 |
| ECS 系统解析与可信 HTTPS DNS 的节点 A 记录 | 一致 |
| Xray 26.10.31 配置校验及精确域名路由 | 通过；诊断确认请求进入指定 VMess 出站 |

| ECS 经节点访问公开 HTTPS 对照站点 | 同样超时 |

| 本机官方 V2Ray 5.53.0 经同一节点 | 同样超时 |

本地代理返回 `CONNECT 200` 只表示它接受了连接请求，不表示远端节点鉴权或目标 HTTPS 已成功。现有证据将问题范围缩小到该节点、提供的节点参数或其转发链路；不能据此断言具体为过期、欠费、UUID 失效或某个网络设备故障。
