# 财务 BI 九页延迟基线与首轮改造验收

2026-11-19（北京时间） · 隔离环境

## 基线与实施范围

在独立工作区用同一套 MySQL 8.4、Redis 8 和 Chrome 跑真实 HTTP 和渲染。合成夹具有 64 家店铺、136,800 条账本记录，涉及 TikTok Shop、Shopee、PHP、THB、当月订单和 2026 年 10 月整月数据。使用真实应用会话、已有业务日汇率逻辑和实际 SQL。成本账单等页面存在合法的空数据状态，重载路径未覆盖所有业务数据分布。

改动前使用 `develop` 的 `51336128`。候选以同一提交的后续财务性能分支 `872c81d1` 为基础，复用已有的专页查询、Redis 分页缓存、投影任务和成本页按需加载。总览接入已经发布且通过版本校验的 MySQL 投影，Redis 未命中时复用原始财务呈现算法生成响应。总览读取投影时跳过明细计数和独立广告消耗正文。结算等页面继续走专页查询，整月读取省掉仅部分月份首日使用的 JSON，有需要时继续按原口径读取。结算中心的首屏仍包含三类金额、趋势和有序明细。

共享服务器只进行了只读核验。现场财务源码有独立未提交改动。现场 V160 文件属于商品采集，候选分支另有财务 V160，后续集成需按现场已执行的 Flyway 历史和文件指纹处理编号冲突。既有 [2026-11-13 至 14 日现场验收](finance-workspace-performance-20261113.md)记录了大范围费用、成本和订单实际超时，隔离基线不覆盖这些真实重月负载。

表内单位为秒。线上为同一登录会话逐页操作，按默认 10 月及今日范围测量核心模块，包含工具导航等待。线上保留正常缓存和后台同步，未施加并发压测。超过观测窗口的请求只记下界。隔离列为每页 100 次、每批 5 并发，900 次全部完成且低于 5 秒。九页的 P95 均低于 3 秒。候选总览和结算均确认走 READY 投影。相邻页面可复用同一进程内事实，develop 首轮和隔离候选列适用条件不同。

首轮扩大样本发现 10 次未进入页面且会话接口成功的超时。隔离浏览器延迟财务脚本 550 毫秒复现结算链接未发出财务查询，5.51 秒测试截止。会话恢复在有权访问的财务链接上等待延迟脚本就绪后，同样的场景结算页 1.49 秒完成。900 次数据使用该修复。延迟样本后重新验证了导航权限、租户隔离、业务日期、DECIMAL 精度与原币/人民币一致性。

## 持续写入和剩余瓶颈

线上只读采样确认 MySQL 8.4.11 和 Flyway 160。9 月、10 月和 11 月的 9 个投影分区当时都存在已构建结果，但构建与请求版本均未对齐。另一次采样中，10 月三种平台范围各有 31 个待补算日期。READY 快路径在隔离环境达标，线上慢样本仍需要降低持续写入时的权威回退和补算成本。

后台连续更新一个合成费用记录，与 5 个并发浏览器同时运行，触发结算 PENDING 回退。10 次总览使用当前源快照，最慢 2.308 秒。结算保留精确计数与明细，将原 2 秒轮询预算降到 250 毫秒，两个各 10 次样本的最慢耗时从 4.731 秒降至 2.985 秒。缩短预算后的 READY 冷 Redis 复测 10 次，最慢 1.417 秒。实际 250 毫秒预算从得到 PENDING 状态后起算，连接排队和原查询额外计时。

35 项 Java 验证通过，覆盖已发布结果等价、精确金额、原币和人民币、租户范围、已有缓存与正在更新时的当前金额、以及结算有序明细和精确计数。16 项相关前端导航测试和 7 项财务 UI 测试脚本通过。

最终候选追加每页 30 次、每批 10 并发的冷 Redis 测试。270 次全部低于 5 秒，最慢为结算中心 1.884 秒，整月总览最慢 1.747 秒。候选匿名总览请求返回 HTTP 401。

线上下一阶段需先解决 10 月结算及费用的持续补算落后，再用具有真实代表性和相同授权范围的隔离数据验证冷读、并发、写入混合负载及财务等价性。现场保持现有运行版本。

## 复跑入口

`scripts/qa/test-finance-bi-latency.mjs` 支持 `FINANCE_BI_ROUTES`、`FINANCE_BI_MONTH`、`FINANCE_BI_SAMPLES`、`FINANCE_BI_CONCURRENCY`、`FINANCE_BI_COLD_REDIS` 和 `FINANCE_BI_TIMEOUT_MS`。运行时从私有开发配置或环境变量读取测试账号密码。JSONL 只记录路由、状态码、计时和投影状态。完整或并发测试使用隔离服务，冷 Redis 测试自动核对当前工作区的开发 Compose 实例。

```sh
FINANCE_BI_BASE_URL=http://localhost:18087 \
FINANCE_BI_LOGIN_FILE=.env.development \
FINANCE_BI_MONTH=2026-10 FINANCE_BI_SAMPLES=100 \
FINANCE_BI_CONCURRENCY=5 FINANCE_BI_COLD_REDIS=1 \
node scripts/qa/test-finance-bi-latency.mjs
```

Playwright 可从已安装依赖解析，也可通过 `PLAYWRIGHT_MODULE` 指定模块入口。已有 Chrome 可用 `FINANCE_BI_CHROME` 指定可执行文件。浏览器停在登录、请求超时、页面报错、核心图表未完成，均计入未达标。
