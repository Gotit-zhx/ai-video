# 成本全店导出自动分批

日期：2026-11-10。版本 `v2026.11.10.5` 已通过标准 CI/CD 上线；后台分片能力已部署，但真实全店规模验收发现聚合分页过慢，尚未完成业务闭环，继续由[聚合读取优化](cost-export-scan-once-20261110.md)修复。

## 问题

用户确认正常浏览器实际提示为超过 50,000 笔订单或 200,000 条 SKU 明细。此前浏览器验收工具拒绝保存文件是独立的工具权限边界，不能把它当作这次大范围导出失败的原因。

旧成本页面同步等待一个 XLSX，服务在达到单文件安全上限时拒绝整个范围。全公司待补齐超过上限后，要求用户手动缩小日期，无法完成预期的一次批量导出。

## 实现

- 保留原财务行生成与同步接口，新增后台个人任务和固定快照文件导出；不新增数据库表、迁移或财务数据写入。
- 在原公司、日期、店铺、分组、平台、原币、来源记录、编号及成本状态范围内，按小键分页取数据，再读取单页 JSON；避免大 JSON 排序及大 OFFSET。
- 每份最多 50,000 单 / 200,000 SKU，按完整订单分片；小范围保持 XLSX，多份 ZIP 包含分片与数量清单。期内退货参考只列一次，金额与空值规则沿用原实现。
- XLSX 临时数据落私有目录，结果采用文件流，保留有界队列、体积、保留期、并发及维护门控；文件仅本人同公司可取，未完成或过期不能下载。
- 页面显示进度、真实 XLSX/ZIP 类型与固定筛选，保留可见下载链接，未知提交以原幂等键核对，不自动重复创建；关闭面板不取消已受理的后台生成。

## 验证进展

- 初次新增 API 尚未实现时测试编译失败，记录为缺少功能接口，不声称已经执行行为断言。
- 第一轮 32 项单元测试、64 项隔离 MySQL 集成测试通过，无跳过。覆盖整单分片、SKU 边界、空结果、失败清理、精度、权限/幂等/保留期，以及超过 500 键时并发重算和新增结算不改变固定快照集合。
- 默认生产上限 50,001 单的真实 ZIP/XLSX 生成回归通过：两份文件分别 50,000 / 1 单，流式逐条核对全部编号、末单与数量。最终 33 项单元测试和 31 组财务页面回归通过；隔离数据库 64 项仍通过，无跳过。
- 独立审查发现并修复旧 GET 列表覆盖新 POST 任务、慢提交时切换范围误报提交成功两项竞态；均有受控延迟回归，定向复审通过。文件快照、分片、资源与权限部分未发现阻断问题。
- 初次托管检查的失败发生在工具链安装 FFmpeg 超时，未执行到该任务的测试。构建准备沿用已有 Dockerfile 的 Ubuntu HTTPS 策略，保持原域名、签名校验和限时，不跳过测试；新运行结果另以候选回执为准。
- 生产规模耗时、真实任务状态与下载入口在上线后验收；此前工具拒绝的文件保存不通过其他方式绕过。
- 生产十月全部店铺待补齐 106,853 单任务已受理，页面刷新后继续生成，但键分页重复聚合导致最终失败；临时文件清理完成，维护关闭。该结果明确不能作为大范围导出成功验收。
