## 需求与设计

用户要求以分组、店铺和消耗明细三张表组织两平台投放费用，保留原资金表的现金、信用额度和广告赠款三项。用户确认系列可以跨店，缺少准确拆分数据时保持待分配，核实后再归属，不使用收入比例估计。TikTok 使用广告账户来源 ID，Shopee 店铺报表使用真实平台店铺 ID，解除账户与单一店铺之间的强制等同；无需先完成广告 OAuth 才可导入。已核实分配不会被后到的自动匹配覆盖。

新增专门资金表导入与版本化金额分配；现有 AD/AD_GMV 事实仅作为读取来源，不改写旧平台费用、订单、成本或利润。官方精确来源和金额一致的单店记录可自动归属；多店或不一致来源待核实。平台账单费用、广告佣金、效果指标及同步诊断继续保留在折叠辅助区。

新接口位于 `/api/v1/finance/advertising`：

| 路径 | 用途 |
| --- | --- |
| `GET /spend` | 三表汇总及 50 行明细分页；`search`、`assignment` 只限制明细 |
| `GET /spend/{key}` | 查看原币来源及当前分配 |
| `PUT /spend/{key}/allocations` | 管理员按来源指纹提交核实金额，保留旧版本 |
| `POST /imports` | `preview=true` 校验资金报表；核对后 `preview=false` 事务发布 |
| `GET /export` | 按完整筛选导出分组、店铺、明细和口径说明 |

写入复用现有财务管理权限与本站 Origin 防护，并检查调用窗口的公司身份。新增迁移 `V150__finance_ad_spend_workspace.sql`，只增加专用资金来源及分配历史表，不改变既有迁移。批量导入按 250 行处理，冲突回滚整份；新查询限制 50,000 条，超过明确拒绝而非截断。

## 验证与接手入口

新增纯计算、隔离数据库及真实 DOM 测试，覆盖符号、三项守恒、资金/API 重叠、可选类型列不影响身份、跨店余款、金额变动复核、后到 API 的未知身份处理、公司隔离、权限/Origin、全量三表导出和长 ID 文本、延迟查询切换。全量前端回归、定向财务单元测试及隔离数据库测试的最终计数以同目录验收 JSON 为准。

用户工作簿只在本机以实际生产解析器读取，校验每行三项合计及全量汇总；原文件未修改，也未进入仓库。仅监听回环地址的本地预览使用原币数据，账户以明确的预览标识展示，全部未知归属仍待分配。它不连接生产、不代表已经确认店铺归属，也不包含真实 Shopee 投放数据。
