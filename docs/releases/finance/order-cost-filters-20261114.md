# 订单成本分组、店铺与待补齐筛选

日期：2026-11-14。功能分支 `feature/finance-order-cost-filters`，基于 `fork/develop` 的 `5133612`。本次为本地实现及验证，未修改或重启共享服务器。

- 仅订单成本页为成本分组、财务店铺增加“全部”。全部分组/全部店铺表示当前公司权限范围内的全部已入库资料；选分组后可查看该分组全部店铺，也可进一步选单店。
- “所有店铺待补齐”改为“待补齐”。状态筛选保留当前范围；分组或店铺改变时回到第一页，查询期间禁用导出，导出使用相同条件覆盖全部分页。
- 订单筛选与成本目录配置选择分开保存。父视图刷新不会将“全部”改回默认店铺，其他成本页仍使用具体店铺。全店范围不能编辑某家隐藏店铺的设置；选单店后设置读取该店的真实目录，读取失败或过期不改变订单筛选。
- 从单条账单等入口进入时，单独切换成本状态不解除来源限定；主动选择分组或店铺后按期间的已结算订单查询。
- 使用已有查询、汇总及后台导出接口，无生产 Java、数据库迁移、计算口径、权限或后台任务改动。

验证：

- 新增真实组件 JSDOM 回归，先在旧代码明确失败于缺少“全部”，再通过。覆盖全公司/分组/单店、待补齐、空组、跨页、查询与导出条件、重挂载、晚返回响应及真实店铺设置。
- 实际导出 POST 集成回归覆盖两种“全部”组合和当前店铺待补齐，同时保留导出幂等、身份隔离及结果未知恢复检查。
- 37 组财务 DOM 套件通过。
- 64 项隔离 MySQL 集成通过（含 63 项共同配置回归）。实际比较多组、多店、其他公司、编号筛选的查询全页订单集合与 XLSX 全量集合，并核对筛选合计；测试库及受限用户已清理。
- 对只读取得的当前服务器前端，私有三方兼容候选保留懒加载、平台 SKU 匹配及其他新增逻辑，并通过同一筛选回归。候选没有写入服务器，后续同步仍需重新核对实际源码和维护状态。
- 独立审查发现设置目录读取失败会使当前订单面板的刷新序号过期，已补“已加载后失败直接刷新”和“订单查询在途时失败”的 RED/GREEN 回归。失败时仅在仍为同一订单范围的情况下重建面板，恢复查询、刷新和导出，不覆盖用户后来选定的范围；37 组界面回归及私有兼容候选再次通过。
