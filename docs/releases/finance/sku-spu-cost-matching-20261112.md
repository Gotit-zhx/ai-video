# 订单成本 SKU / SPU 匹配验收

日期：2026-11-12。功能分支 `feature/finance-cost-sku-spu-fallback`，基于 `develop` 的 `fe7b597`。当前完成实现、本地验证和独立审查，尚未同步共享服务器。

## 行为

- 订单成本表的“商品 SKU”右侧新增“平台 SPU”，同单多个商品 ID 去重分行，长编号保持文本精度。
- 当前公司、分组和成本仓内自动匹配：商品 SKU（含原有格式规范化、组合装规则）→ 平台 SPU → 人工确认。平台规格 SKU ID 不作为 SPU 使用。
- 保留人工确认、独立手动价格、GIFT、取消订单及实际履约成本优先级；已命中型号的缺价、零价、数量问题不通过切换 SPU 价格掩盖。
- 前端关联提示、自动关联接口和订单计算共用相同顺序；已有自动 SPU 关系遇到新的有效 SKU 型号时重新优先 SKU。大成本目录按仓构建并复用查找索引。
- 更新计算源哈希版本，使后续同步及现有重算入口能更新旧算法结果；本次没有全历史入队、数据库迁移、原始账本写入或共享服务器重启。

## 验证

- 原基线 25 项相关单元通过。新增测试在原实现出现 5 项 Java 断言失败，页面回归明确失败于缺少 SPU 列；实现后最终 67 项单元通过，0 失败、0 跳过，包含成本分片导出回归。
- 66 项隔离 MySQL 集成通过，0 失败、0 跳过。包含真实混合型号 CSV 导入、Shopee/TikTok 两平台后台计算及订单查询、公司隔离、逐仓自动关系、人工关系保护、旧算法结果重新入队、原始商家 SKU 不被改写。
- 34 组财务页面回归通过。新增覆盖列顺序、长编号、双匹配优先级、双未命中、人工关系，以及 1,000 型号 × 500 商品在无映射/已有自动映射两种情况下的成本行读取预算。
- 独立审查发现前端逐商品扫描成本目录的性能问题，修复为每次挂载按仓复用索引；定向复审及 10 个匹配边界断言通过，无剩余阻断或重要问题。

验证使用合成数据和可销毁数据库。共享服务器实际数据覆盖、历史队列完成状态和真实浏览器负载不属于本次本地验收；运行新代码及存量重算仍按项目共享服务器协作规则执行。
