# 项目同步与刷单核对表合计发布 · 2026-11-06

状态：候选准备，尚未激活。版本 `2026.11.6`；发布分支 `release/2026.11.6-project-sync`。

## 变更与范围

将 `develop` 中的项目目录整理、交接文档与刷单核对表合计同步到项目服务器。多会话约定先经 `feature/multi-session-coordination` 用 `--no-ff` 合回 `develop`，发布分支再从集成分支建立；不在共享工作区切换分支。

线上业务增量是刷单核对表合计：本金原币非零的来源行统计笔数，代刷费非零金额按人民币求和，覆盖费用分组及精确编号查询的全部分页。来源行合计与按首次结算、平台和店铺去重的期间统计分别显示；不改变原始平台金额、利润公式或既有刷单去重规则。

目录整理涉及源码、构建入口、工程脚本和说明。服务器现有 Compose、历史发布依赖、业务卷及其他服务不随源码目录迁移。完整源码在独立目录留存，运行制品采用经过差异核对的增量替换。

## 候选验证

- Java 主源码与测试源码编译通过。
- 三项新增 MySQL 场景通过：55 条来源跨页、公司/分组/精确多编号隔离、本金与代刷费独立零值及空查询。
- 三项既有 MySQL 回归通过：刷单标记及移除来源、首次结算期间与费用去重、错误分组隔离。测试只连接随机命名的可销毁 QA 库，专用账号仅有该库权限。
- 两项解析单元测试通过；未提供私有原始工作簿的用例跳过，不伪造该项验收。
- charges、costs-live、source-orders 三组 UI 回归通过。
- 从实际线上 JAR 提取依赖后，以 Java 21、`-g -parameters` 编译旧源码，`FinanceOrderCharges.class` 与线上完全相同，再以相同参数编译候选。该比较确认了替换基线；全量 Maven 编译产物不直接覆盖生产 JAR。
- 接下来的镜像构建必须使用已安装压缩保护工具返回的不可变基础镜像。激活前再次核对实际镜像、容器、文件、配置与活动业务；沿用工作器停领及恢复机制，保留同步检查点和限流。
