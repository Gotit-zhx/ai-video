## 原因与处理

真实失败发生在模型请求已发送后、完整响应收到前，原始错误为 UND_ERR_SOCKET。旧 runtime 将其包装为 502；请求结果未知使图片进入 REVIEW_REQUIRED，用户再次重试会命中旧失败记录，不能接续。原解析还需区分供应商网关错误、损坏响应与明确的业务拒绝。

运行时增加持久化图片操作记录：保存输入摘要、已发送次数、模型路线、完整供应商响应及最终结果。相同请求并发加入同一操作；已有成功结果直接复用；容器重启不清零重试预算。凭据和原图不写入该记录。网络失败由主模型切至 Grok，再允许一次 Grok 网络恢复；不同模型各自使用稳定请求标识。供应商是否支持幂等计费由供应商决定，未知请求仍可能已经计费。

Java 到 runtime 的连接断开后，使用相同请求体和 progressRequestId 重连一次，接回原任务或缓存。连接池尚未取得连接的情况继续按未发送排队；HTTP明确响应不会由 Java 层盲目重复。

DNS保留正常系统解析，仅全为198.18/15虚拟地址时通过可信DoH获取真实公共地址；TLS验证不关闭。

## 视频

Shopee每个商品支持一个视频，自动选第一个有效采集视频。读取当前企业的本地视频归档并核对长度和SHA256，最大30MB。先完成视频准备，再上传商品图，避免转码等待时重复传图片。

媒体上传使用独立持久化账本：初始化、4MiB分片、完成、转码状态均保存。已确认分片和转码会话复用；完成响应丢失先查询原上传ID。未知初始化最多3次。视频等待每15秒重新调度，独立等待上限30分钟，不消耗普通失败重试次数；超时保留进度。只有视频和图片都就绪才进入商品创建边界。

上传保留 UNLIST 待上架、默认库存999、默认250g、无品牌、自动物流和原价汇率换算；沙箱前50规格，正式保留全部规格。
