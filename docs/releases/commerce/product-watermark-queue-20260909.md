# 商品去水印与并发队列（2026-09-09）

最新用户要求覆盖此前的直接生图方案：只保留生成前水印检测，取消生成后复核。当前链路为 Grok 前置检测 → PRESENT 才提交图片模型 → 下载并归档结果；ABSENT 保留原图；UNCERTAIN/检测失败不提交生图。无后置视觉调用、无本地局部合成。图片模型提示词仍要求保留商品结构、颜色、刺绣、标签等。

## 并发与恢复

- V81 持久化逐图队列，同一商品的图片并行执行。
- 数据库全局锁控制最多 500 个 RUNNING，额外任务保持 QUEUED，调度器每秒补位；多个实例共用此限制。
- job_id + image_id 唯一，重复提交不会重复入队。
- 模型/下载请求不占用长数据库事务；短事务提交图片状态、进度和任务汇总。
- 单图失败不取消兄弟任务；全部结束后商品进入 READY 或 FAILED。
- 工作线程每 30 秒续租，租约一小时。未领取任务重启后继续排队；失联的已领取任务过期后标为失败/结果未确认，不盲目重复付费调用。
- 逐图进度端点 /api/v1/product-captures/{id}/image-progress 按当前公司及商品查询，页面每 3 秒读取。
- 前端分别显示水印检测中 / AI 去水印中（光波）、排队中（无光波）、失败（红框及原因），并显示本商品数量与全局 500 上限。
