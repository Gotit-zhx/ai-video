# 生图连接等待超时与自动回队

> 历史发布记录；镜像、测试与“当前/最新”均指记录当时。 当前入口见[业务说明](../../business/README.md)与[运维指南](../../guides/operations.md)。

商品 `8a8180ca-43f7-4637-8172-65147820e274` 的任务共 24 张，旧状态为成功 20 张、失败 4 张。

4 条失败日志的最深异常均为 `ConnectionRequestTimeoutException`：等待 Apache HTTP 连接池租用超过 180 秒，请求尚未发送。对应 runtime 进度均为 404，账本没有生成结果。这不能归类为模型已经接单后的响应超时。

## 修复

- 商品图片生成使用专用 HTTP 连接池，总连接和单目标连接均为 512，配合全局 500 个水印任务并发。
- 租用连接等待 60 秒；若仍未拿到连接，记录明确的“未发送”异常。
- 仅对上述明确未发送异常，把账本从 `EDITING` 退回 `DETECTED`，交给既有队列延期重试。界面应保持排队状态，任务不会因连接繁忙被标为失败。
- 自动回队复用原始归档和已保存的前置检测，保持原图 hash 与检查 ID，不重新读取远端图片。
- 专用连接与响应超时分别为 10 秒、60 分钟。HTTP 客户端关闭自动重试、重定向及 Cookie。
- 已经发送后发生的读取超时、断流等不能当成“未发送”，继续保留不自动重复提交的原行为。

真实回环 HTTP 测试覆盖 12 个请求同时到达、超过旧单目标 5 个连接的限制；缩小测试池复现租用超时，确认第二个请求未到达服务端。另验证响应超时、断流与 HTTP 503 不在 HTTP 客户端内自动重复 POST，以及工作器走延期队列。

最终相关 Java 测试 64 项、真实背景样本检查 2 项及 Node 全量 88 项通过。app 与图片服务已部署，健康状态均为 HTTP 200 / UP；运行 JAR SHA256 为 `5a72ec8a486937ceb4aeaf18c223a955dc4dd0b1bdcfb0ddf4c7634f4b7d0992`。
