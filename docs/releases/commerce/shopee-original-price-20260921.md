# Shopee 原价换汇取值修复

> 历史发布记录；镜像、测试与“当前/最新”均指记录当时。 当前入口见[业务说明](../../business/README.md)与[运维指南](../../guides/operations.md)。

根因：采集器独立保存当前促销价 `price` 和原价 `original_price`；界面提示原价换汇，但发布器基础价与变体价都读取 `getPrice()`。本例 73 个 SKU 当前价均为 0.01 MYR，真实原价 15–17.8 MYR，导致价格换算后只有约 0.15 PHP。

修复：基础商品价格取每个 SKU 的原价中的最小值；变体使用自身原价。有有效原价时优先使用，无有效原价才回退自身当前价，缺价不再借用其他 SKU 价格。显式发布价格保持优先。采集记录和原有促销价不修改。发布回执记录 priceBasis。

在获取 Shopee 目标店铺/类目标题限制的同一次官方请求中读取 price_limit，检查基础价及全部 SKU 换算价，失败发生于媒体上传和商品创建之前，避免等待数分钟后才被拒。

27 项定向测试通过，包含实际 0.01/15.80 MYR 原价优先、243.24 PHP 换算、不同 SKU 原价的独立换算、显式定价不变、官方价格边界和原有发布行为。生产只替换相关 6 个 class，保留标题适配、视频补帧压缩、原工作流重复创建保护。

本例任务使用原汇率快照 15.395109，原价范围换算为 230.93–274.03 PHP。恢复脚本只在精确价格拒绝、无外部商品编号、无同店执行中/成功任务、商品版本一致且仍已审核时接续原任务，保留失败审计和原素材处理记录。

线上已部署，健康 UP，配置和挂载不变。原任务再次实际提交，标题与价格校验已通过，平台下一项明确拒绝为 `Size Chart is required for selected category`，没有创建商品。采集 raw/normalized 数据递归检查没有 size_chart / sizeChart 等字段。精确核对该新增失败审计且无 external_id 后，释放该任务目标占位，保持 FAILED 并明确提示需补尺码表，未擅自改类目或编造尺寸。
