# 印花模板保存后被误判为已改动

> 历史发布记录；镜像、测试与“当前/最新”均指记录当时。 当前入口见[业务说明](../../business/README.md)与[运维指南](../../guides/operations.md)。

2026-09-16，用户模板“委屈”v1 保存后，创建裂变报“模型或印花位置已变化，请重新保存四面效果”。

确认：保存接口先验证渲染绑定，之后写入 MySQL JSON。旧绑定对所有几何、表面位置及质量数值的原始序列化结果做 SHA-256。MySQL JSON 对浮点小数的解析存在末位舍入差异，读回时哈希改变。固定种子 10,000 个双精度数的本机 MySQL 往返中有 1,002 个出现差异，例如 0.9525102111858401 → 0.95251021118584。此差异不代表模型被移动。

修复：新渲染绑定带 v2 前缀，哈希中数值统一到小数点后九位；仅哈希归一化，不改模型数据。素材哈希、印花顺序、图片集合继续严格校验，移动 0.001 的印花仍被拒绝。有效旧版绑定继续兼容，不对客户端传入的不匹配旧绑定自动放行。

恢复：仅修复已由保存接口验过的持久化快照 350ad349-6e37-4046-bef3-82f42dd29c0e 的 renderBinding 字段，以旧绑定条件更新，影响 1 行。修改前后除 renderBinding 外 JSON 语义完全一致。读取数据库修复后的配置调用 requireSurfaceRenders 通过。未重新生图，未启动裂变，未更改模型、印花位置或任何图片。

验证：CommerceSurfacePrintTemplateTest 包含 MySQL 实际舍入数值回归和真实位置修改拒绝；原素材替换/排序校验测试继续通过。证据保存在 output/print-binding-check-20260916/，含修改前完整备份和条件修复记录。
