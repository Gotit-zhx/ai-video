# 财务 BI

入口：`#finance-overview`。仅平台超级管理员可见和使用；不能通过给普通管理员分配权限开放此模块。服务端每个财务接口均通过 `OrganizationAccessPolicy.isPlatformAdmin` 校验，数据按企业和用户隔离。

## 页面

- 财务总览：净结算、订单、退款、平台费用、广告消耗、外部成本；收入趋势、店铺排行、费用构成、订单状态、广告成本趋势及店铺汇总。
- 结算中心：账单、交易明细、TikTok 官方预计待结算。
- 对账中心：同店铺、账单编号、币种的账单金额和结算交易金额核对。明细分页未完成、金额未知、数据缺失不会标为一致。页面每页 50 张账单，显示总数；Excel 导出支持当前筛选的全部账单（最多 100,000），不受当前页限制。
- 订单与退款、费用与调整：分页明细及趋势。
- 广告分析：TikTok 广告账户消耗、曝光、点击、转化；可选 GMV Max 专项消耗、归因收入、SKU 订单数及归因 ROI。两种消耗不相加。
- 财务店铺管理：统一配置独立财务店铺与广告账户。店铺授权状态、令牌与商品运营分开保存。初始关闭店铺同步，由超级管理员按店铺开启。可移除财务店铺，历史记录保留但从当前看板隐藏。广告账户连接、更新授权、启停同步全部在此，广告分析页仅保留报表功能。
- 实时大屏：独立暖白橙红展示页，支持全屏；今日订单金额、有效订单数、客单价、小时趋势、店铺成交榜、订单状态及最新订单。不显示买家个人资料。

沿用 HR 看板的 Tabler 设计参考和本地 ECharts 6.1.0。原有首页、全局配色、助手和 HR 业务不变。财务页面仅提供开始、结束日历筛选，按所选日期范围计算指标、明细和导出；图表自动选择适宜聚合粒度，不再提供日/周/月 K 或快捷周期按钮。趋势连接空缺点，空缺金额仍为未知而非补零。

手动筛选、翻页显示局部加载状态并保留原内容，后台轮询只更新变化部分。无新数据时保留图表实例和数据，不重复执行动画；有新数据时更新变化的序列，保留缩放、图例选择和页面焦点。

## 人民币切换

“原币 / 人民币 ¥”一键切换看板、图表、明细和导出。原币模式按单一币种统计；人民币模式可把不同币种分别换算后汇总。原始账单永不被改写。

参考汇率来源：ExchangeRate-API 免费接口 `https://open.er-api.com/v6/latest/CNY`，页面及导出提供来源链接。将以 CNY 为基准的报价取倒数，得到每一单位原币对应的 CNY。使用 BigDecimal 计算，换算金额保留六位用于汇总，页面显示两位。

每天缓存一个参考快照。外部服务故障时最多使用三天内快照，并显示汇率日期；没有可用汇率或某币种缺失时明确报错，绝不只换算部分金额后冒充总额。刷新按钮重新选取可用快照；翻页及导出固定使用当前看板快照。

采用同一参考汇率重述所选时期的金额，**不等同历史交易汇率、银行结汇金额或人民币会计账簿**。原币对账结果不受人民币四舍五入影响。

## 官方接口与口径

| 数据 | Shopee | TikTok Shop / TikTok for Business |
|---|---|---|
| 订单 | `/api/v2/order/get_order_list` + `/get_order_detail` | `/order/202309/orders/search` |
| 退款 | `/api/v2/returns/get_return_list` | `/return_refund/202309/returns/search` |
| 已释放结算 | `/api/v2/payment/get_income_detail`，`income_status=1` | `/finance/202309/statements` |
| 结算拆分 | `/api/v2/payment/get_escrow_detail` | `/finance/202501/statements/{id}/statement_transactions` |
| 预计待结算 | 当前版本不以订单金额推算 Shopee 待结算 | `/finance/202507/orders/unsettled` |
| 广告消耗 | 支持导入平台账单 | `/open_api/v1.3/report/integrated/get/` |
| GMV Max 专项 | 不适用 | `/open_api/v1.3/gmv_max/report/get/` |
| 采购、头程等成本 | 手工导入 | 手工导入 |

当前不提供资金流水、提现、银行到账、打款接口。平台结算不意味着银行到账。

订单按创建日期，结算和费用按平台结算日期，广告按平台返回的账户报表日期。待付款及取消订单保留记录但不计入订单金额；只有已完成退款计入成功退款金额。空金额保留未知，不伪造为零。

TikTok 结算扣费的负数转为费用正数，退款返还相反；原始响应保留。“已结算净额”汇总 TikTok 交易的 `settlement_amount`，Shopee 优先取 `order_income.escrow_amount_after_adjustment`，缺失时取 `escrow_amount`。平台已在该笔结算中扣收的费用包含在这个净额内，“平台费用”用于展示拆分，不再次扣减。未由平台在该笔结算中扣收的广告、采购、头程等支出不包含在内，因此净结算不是净利润，也不确认银行到账。结算账单与明细不能相加，广告归因收入与订单金额不能相加。

GMV Max 需在广告账户连接弹窗填写可选的广告平台店铺 ID（不是假定商品店铺内部 ID）。使用官方 `advertiser_id, stat_time_day` 维度和 `cost, orders, gross_revenue, net_cost` 指标。该专项授权出错不会阻塞普通账户报表；错误单独显示。跨店账户可保持未分配，不强行摊到某个店铺。

广告授权使用 TikTok for Business 官方授权链接；店铺与广告都可生成、复制链接，由账户管理员在自己的浏览器完成授权。首次在「财务店铺管理 → 广告应用配置」保存广告应用 App ID / App Secret，并把页面提供的回调地址登记到广告开放平台。不能使用 TikTok Shop 应用密钥替代广告应用。密钥按组织、用户隔离，AES-GCM 加密，不回显。

广告回调为 `/api/v1/shop-authorizations/callback/tiktok_ads`，使用 32 字节随机、一次性、带过期时间的 state；数据库只存 state 摘要。服务端以 `auth_code` 调用 `/open_api/v1.3/oauth2/access_token/`，再通过 `/advertiser/info/` 验证账户。账户 ID 留空时接入本次授权返回的账户，保留已存在账户的归属；指定账户时必须出现在本次授权中。全部验证和写入以事务完成，失败不部分导入，重复回调不重复交换令牌。新账户默认跨店未分配；绑定专属店铺需指定账户 ID。

广告令牌 AES-GCM 加密保存，不回显。店铺授权不等于广告授权。广告接口及导入的广告费用不能在同一个绑定店铺重复接入。广告应用信息按当前用户独立配置，系统不会把商品运营或其他用户的应用凭据复制过来。

## 同步与数据质量

- 历史订单及退款通道：完成一轮后每 10 分钟同步增量。
- 结算、待结算、广告：每小时。
- 独立 `ORDER_LIVE` 通道首次补当天；之后从上轮请求截止时间向前重叠 5 分钟读取更新，整轮成功后 60 秒再次排队，不依赖大屏是否打开。水位保存请求截止时间，不用任务完成时刻，避免分页耗时造成漏单。历史 `ORDER` 通道和实时通道各自保存游标、租约与退避。
- 实时大屏每 15 秒读取已入库数据；关闭或隐藏后停止页面轮询。平台回传、分页、多店排队等会延迟，页面展示实际完整同步时间，不能承诺逐单秒级推送，也不能承诺百店均在一分钟内完成一轮。
- 初次分批回补近 90 天平台仍提供的数据；凌晨后的首次增量回看最近 30 天。平台权限、接口保留期和店铺开通时间决定实际覆盖范围。
- 初始订单、结算回补优先近 30 天，再继续历史区间；已开始的历史分页、账单交易游标通过 `backfillResume` 一并保存，近期数据取完后原样恢复，不丢页也不跳过历史区间。同步进行中的看板和明细每 15 秒刷新，页面隐藏或有编辑弹窗时延后刷新。
- 预计待结算为动态快照，每小时完整检查最近 90 天及系统仍保存的更老待结算记录，只有分页完整后才清理消失的预估记录。
- 独立 4 线程同步池，每个平台在单个应用实例内最多并发 2 个店铺；同一家店铺的全部通道串行。抢占使用短事务及店铺行锁 `FOR UPDATE SKIP LOCKED`，跨实例也不能同时领取同店铺的有效租约。10 分钟租约每 30 秒续期，游标、成功和失败更新均校验本轮令牌；过期任务不能覆盖新任务进度。分页间隔 2 秒，平台每页条数不变；失败仍指数退避，最大六小时。广告保持原来的独立任务。
- API 稳定 ID 幂等更新，不按名称/金额判重。未识别响应结构不会当作“无数据”推进游标。
- Shopee 收入接口兼容文档中的 `income_detail_list.list`、嵌套形式及实测的 `response.list`。成功响应的空 `response: {}` 表示该区间无收入，可继续下一时间段；缺少响应体、未知字段或损坏的列表仍会报错并保留游标。
- TikTok 账单逐页抓取交易，完整后才改为已结算对账状态。上游数量在分页期间变化则重放该账单/时间窗，已有记录幂等覆盖。
- 原始响应仅用于留存和校验，详情接口不直接返回可能包含买家信息的原始 JSON。

## 可配置字段

明细与对账提供“字段设置”，按企业、用户和数据类型保存。主要字段默认保留；“显示”和“导出”是两套独立选择，不必为了导出而撑宽页面。对账、全部明细和每种业务记录分别配置，CSV 和 XLSX 实际使用所选列。

扩展字段来自已留存官方响应中的白名单路径，包括支付方式、平台时间、商品行数/名称、运费、优惠、结算佣金/手续费/税费、广告曝光/点击/转化等。只提取安全标量，保留未知值；不返回买家资料、令牌或原始 JSON。不同平台字段不混用，不适用字段为空。扩展金额明确标注原币；人民币模式只转换已定义的金额及对账列。

## 导入、导出

支持 UTF-8 CSV / XLSX，标题行映射，单次导入最多 20,000 行、12 MB。类型为账单、广告费、外部成本；验证全部行后事务提交。相同文件与映射重复导入不重复入账；记录编号稳定时允许更新原记录。文件中的公式不执行，导入需先转为值。

导出按当前平台、店铺、日期和币种筛选，不限于当前页面；最多 100,000 条。Excel 包含明细、统计口径、对账，人民币模式增加汇率快照及换算列。金额单元格可直接计算；订单等长 ID 保持文本。CSV 做公式注入防护。

## 部署及验收

迁移 `V117__finance_bi.sql` 新增六张财务表；`V118__finance_independent_configuration.sql` 新增财务专用店铺、授权会话和字段偏好表，关闭原来从商品运营关联的财务同步。旧财务数据保留但不参与新独立店铺的统计；商品运营店铺和凭据不修改。广告授权仍独立，关联选项仅来自财务店铺。独立配置发布使用 `scripts/release-finance-configuration.py`，备份财务表并校验商品运营凭据未变化；最初专用发布脚本 `scripts/release-finance-bi.py` 在现网镜像上增加 finance 包及迁移，覆盖四个已审阅前端文件；验证所有其他 JAR 项和其他运行容器保持不变。

发布前留存数据库快照和旧镜像。不会打断正在执行的应用或 HR 请求；发布前检查任务和租约。回滚保留新增财务表，不能删库回滚或改写 Flyway 历史。

自动测试覆盖超管限制、用户隔离、时间聚合、混合币种转换、固定汇率导出、未完整账单、平台异常结构、幂等 ID、导入原子验证、数值 Excel、CSV 公式防护、XXE；另在隔离 MySQL 库验证迁移、外键、金额精度和对账 SQL。

仓储与事务服务可能被 Spring CGLIB 代理，跨 Bean 获取 JdbcTemplate、汇率服务、店铺授权服务必须调用方法，不得直接读取目标对象字段。回归测试使用真实类代理验证两个后台任务、看板和人民币导出。线上需等到 `Finance shop sync ready` 和 `Finance ad sync ready` 均出现才确认后台同步调度可用；这两条就绪记录不代表真实店铺数据已经同步。

本地 UI 验收数据仅在独立预览服务模拟，绝不进入生产。真实广告数据需管理员配置广告应用并完成官方授权；真实店铺数据需开启财务同步后检验相应平台权限。

`V119__finance_ad_authorization.sql` 增加独立广告应用表和授权会话上下文，不修改历史财务记录、店铺授权或商品运营数据。`scripts/release-finance-live-ads.py` 仅覆盖四个财务类族、新迁移和三个财务前端资源；其余 JAR 项与运行服务保持原样。大屏改用暖白底、橙红主卡和金色点缀，订单金额在屏幕中央，左右展示关键指标；仅此页面采用该配色。

财务页面内容区固定单列纵向排列，`fi-span-*` 仅用于图表网格的直接子项，避免明细表跨列规则生成隐式列、拉伸页签或挤压趋势图。
