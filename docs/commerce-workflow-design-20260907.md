# 多店商品开发与运营工作流 — 第一阶段

## 现状与边界

先合并并推送已有测试代码（d7b8727），保留插件、采集、多店授权、官方发布和生成纠错。本阶段新增登录后商品采集页面的工作流规划器和 POST /api/v1/commerce-plans/preview，使用 product:view 或 product:publish 权限。无持久化，无 AI 调用、发布、广告或删除行为；输入只用于本次预览。无数据库变更，无线上部署。

规划模板 v1 明确区分原商品数、设计版本数、素材图数和刊登草稿数。现货仅变更营销素材，不新增实物款式；POD 可以新增设计，但执行前必须绑定真实基础款、印刷规格和生产文件。店铺数量只是占位，不能代表实际授权。每份草稿只分配一次，不乘以店铺数。

预算单位随市场确定，口径固定为每店每日总上限，不是每条新计划预算。七天预算是同一观察窗口内全店预算上限，不是实际支出预测，也不涵盖晚开始批次的额外投放周期。排期为审核通过且无失败情况下的理论下限。GMV Max尚未接入该规划器。

## 模板持久化进展

新增 V55 commerce_template_versions，组织隔离的工作流模板保存、最近100个模板列表、最近100个历史版本查询。更新先锁定版本1，再校验 expectedVersion；唯一键防止并发产生相同版本。旧版本不更新，后续批次将引用 snapshotId。

前端可以刷新本公司模板、载入、新建与保存新版本。保存需要 product:edit，读取需要 product:view 或 product:publish。模板不会复用权利、供货及生产文件确认，批次必须重新检查。尚未进行本地数据库迁移或运行中服务升级，不代表端到端已验收。

## 后续领域模型（除工作流模板外尚未实现）

所有业务实体必须绑定 organization_id，关联操作校验同租户；模板写入单独授权。

1. CommerceTemplate / TemplateVersion：商品、视觉、店铺、广告和流程五类；已运行任务使用不可变快照。
2. SourceProduct → ProductDesign → ListingDraft → PublishedListing：关联现有 ProductCapture / SKU，禁止以图片数替代商品数；保存素材来源与使用权证据。
3. SupplyVariant / ProductionAsset：生产基础款、颜色尺码、印刷区域、分辨率、供应商 SKU；展示图与生产图分别存储。
4. CommerceBatch / BatchItem：来源、模板快照、真实 shop_id、配额、幂等键、质检与执行状态；复用现有 ProductPublishWorkflow，不重复实现平台上传。
5. AdvertisingPolicy / Experiment / MetricSnapshot：广告账户独立授权；币种、时区、归因窗口、最低样本量、退款及成本口径明确。
6. GrowthAction / FulfillmentLink：视频、达人样品审批、供应商订单，优先通过 ERP 适配器接入履约。

## 十模块路线

店铺管理前端已从商品采集页抽到独立一级菜单 `#shops`。授权回调指向 `/?view=shops`；原有刷新、解绑及平台筛选继续复用。铺货页仅保留管理入口和发布时选店。此步不新增店铺分组、成员级权限、环境标记或默认配置，它们仍在后续范围中。退出或切换公司会清理模板/批次缓存，异步成功响应通过代次校验避免回填旧公司数据。

新增批次草稿 API `/api/v1/commerce-batches`（GET列表、GET详情、POST创建），V56存储批次及实际商品/店铺条目。创建固定 templateSnapshotId 与 captureVersion，验证公司、店铺状态、平台站点、店铺数量及重复组合，使用幂等键防止重复创建。每店按模板额度生成 plannedDay，仅为本批次相对排期，尚不是跨批次全店配额预留。状态保持 DRAFT，不派发图片、发布或广告任务。POD设计与生产文件尚未关联，不能把草稿当作已批准商品。

选品中心、商品素材库、AI工作台、店铺模板中心、批次中心、刊登中心、广告测款中心、数据策略中心、爆款增长中心、供应履约中心。公共层共享权限、队列、费用上限、日志和人工审批。

下一批优先：可保存的租户隔离模板和版本 → 批次草稿绑定实际商品与授权店铺 → 质检门禁 → 人工确认后派发已有发布工作流。关键词热销榜数据源需独立验证，不能把搜索前50当热销前50。

广告阶段先接只读报表和人工策略验证，再开放预算上限内的自动操作。暂停与下架优先于删除；样本不足不淘汰；调整目标 ROI 不保证实际收益；不允许每日自动新建计划造成预算叠加。

## 验收

店铺运营配置新增 V57 与 `/api/v1/shops/{id}/operating-settings` GET/PUT：分组、人工环境标记、店铺每日额度、固定默认模板版本、乐观锁。默认 UNKNOWN，不从域名或店铺名猜测环境。默认模板必须属于本公司且匹配平台站点。批次创建要求环境已确认且不混用 TEST/LIVE，按模板与店铺额度的较小值排期。人工标记不等于官方沙箱路由已验证，不切换API地址；跨批次全店配额锁定仍待实现。

批次工作台已接入真实模板、商品分页搜索、店铺列表和批次接口，按所选匹配店铺均分实际商品。新增前端测试覆盖站点过滤、每款只分配一次、网络失败幂等重试。MySQL 8.4独立临时容器已执行V55/V56并通过 scripts/test-commerce-schema.sql 约束验证；没有变更运行中数据库。尚未在完整登录应用中完成端到端保存回读和视觉验收。
