# 手动邀约优先发送

网页原先只把邀约写入云端队列，助手最多等待下一次 30 秒轮询，而且先同步职位、简历及历史回执；页面每 5 秒刷新一次，还可能用另一条旧消息的状态代表本次发送。

0.1.18 为“发送邀约到 BOSS”增加即时本机接口。提交时生成的云端消息 ID 和招聘账号 ID 是唯一派发依据；助手按当前平台用户、招聘账号读取这条任务，在队列真正执行时原子领取。客户端不能直接指定收件人或替换云端消息正文。重复点击或多个网页竞争仍只有一次 SDK 写入。

手动发送和手动索取简历优先于待执行的列表读取、分页同步和后台补收。正在运行的后台纯读取可以停止并让出进程；正在进行的发送不会被中断。共享请求间隔、额度、账号限制及原来的本地发送记录不变。

页面每秒核对本次消息，收到 SDK 明确的 `sent` 回执立即显示成功，不等待云端上传。云端暂时未同步的 `sending` 不会覆盖已确认的本机成功；持久化回执由后台继续同步。10 秒仍未确认会明确提示继续核对，保留防重复发送锁。外部平台或网络异常时不能保证 10 秒内发送成功，也不会用“排队成功”代替“发送成功”。

自动化验证覆盖队列优先级、后台读让出、不中断写、并发去重、账号和用户隔离、旧成功记录与本次发送区分、10 秒提示及云端回执滞后。测试使用合成候选人和回执，不向真实候选人发送测试消息。
