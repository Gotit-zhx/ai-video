# 模板配色、可选主图风格与印花缩略图

模板配置增加可选的主图风格和显式配色。颜色支持色盘、常用色和 HEX 输入，并随印花模板版本保存。选中风格后，发布图集全部由所选主图模板提供；生成未完成时不能混入旧商品主图。未选风格保留原图集流程。首页和原有主题样式不变。

新模板配色通过已保存的模板在服务端冻结，不能由提交计划的客户端覆盖。前后左右的服装改色使用配置色号；原商品仅提供尺码、售价、库存等规格。新颜色生成独立的 SKU 标识，规格冲突仍要求核对，不能叠加原商品库存。

已存在且没有配色字段的不可变模板保持旧行为。编辑保存新版本需配置至少一种颜色；历史执行继续使用既有快照。

印花列表和选择后的缩略预览使用最长边 256 像素的透明 PNG，按需加载，不再向浏览器传输高清原图。服务器按公司与内容指纹缓存最多 128 张小图；每次请求仍校验当前素材归属与权限，浏览器私有缓存需重新验证。首次访问的历史素材需读取原档生成缩略图；后续命中缓存。实际制作与“查看透明原图”保持使用原始高清文件。

## 验证

- 209 项相关后端测试通过，覆盖配色校验、计划冻结、原生透明印花、四面改色、SKU 规格、风格图集和缩略图权限/缓存/原图保真。
- 60 项相关前端测试通过；修改的 JavaScript 语法检查通过。
- 本地隔离页面使用真实前端代码和模拟 API，验证风格与颜色保存/刷新回读、清空可选风格、三位 HEX 归一化、重复与非法色号拦截。
- 390 像素视口无横向溢出，色盘保持在可视区域；素材选择加载 6 张 256 像素缩略图，原图请求数为 0。
- 修复实际浏览器验收发现的固定画布遮挡和色相条被全局输入框背景覆盖的问题。
- 原测试中的二维印花样本在未修改的基线也会失败，已仅修正为原生透明 PNG 样本，生产透明性检查未放宽。
- 发布前核对受影响的 51 个既有生产类，均与基线源码规范化字节码相符。

验证没有创建真实付费生图任务，也没有向店铺发布测试商品；模型输出的实际视觉质量仍取决于所用模型。

## 发布范围

使用 `scripts/release-template-palette.py` 在当时运行的应用和前端镜像上覆盖本次类与静态文件。保留其余 JAR 条目及环境、挂载、网络配置，不改数据库结构，不更换 Pi/招聘服务。HTML 保留线上 HR 脚本原有缓存标识。

发布流程校验当前镜像基线、任务空闲、健康状态及 HTTPS 静态文件指纹；失败回退到发布前镜像。验证后清理重复构建文件，保留回滚镜像与发布凭据。
