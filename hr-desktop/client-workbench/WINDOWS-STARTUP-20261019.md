# Windows 0.1.26 启动与窗口接管

用户反馈：启动时偶尔没有 Ai boss 窗口，偶尔出现原版 BOSS 窗口，
重复打开数次后才正常。未取得用户 Windows 现场日志，以下是源码中已确认的缺口。

- 原入口的 running mutex 只用于阻止安装覆盖，未检查已存在的实例。
- 原启动器固定等待 12 秒后才接入，不以原客户端真实窗口状态为依据。
- 接管完成后未显式恢复隐藏或最小化窗口。
- 原客户端保存的 show 函数和延迟命名的窗口可能绕开原接管时机。
- Windows 窗口未指定 Ai boss 的任务栏 relaunchCommand。

修复：

- 已有实例只收到唤起事件，不再启动第二个控制器。
- 独立的 Ai boss 启动界面显示真实阶段；仅暂时隐藏此次创建的原生 PID 的窗口。
- 观察原生 Chrome_WidgetWin_1 顶层窗口后才开启本机接管通道；
  标记必须同时匹配本次随机 launchId 和实际 child PID，不再固定等待 12 秒。
- 界面接管完成且启动入口确认实际 HWND 可见后，才认为启动完成。
- 捕获窗口创建、延迟命名、加载与真实 show 事件；恢复隐藏、最小化窗口。
- 任务栏重新打开命令指向安装目录 Ai boss.exe。
- 尚未恢复出的空身份不参与启动账号比对；已有风险状态继续暂停招聘任务，
  保留界面供用户确认，不绕过登录或风控。

账号目录、官网会话、招聘记录、云端去重、冷却时间、邀约额度均不调整。
原版 EXE/ASAR 的校验与私有交付边界保留。

验证增加了过期启动标记拒绝、延迟窗口、原生 show 绕行、空身份、
连续三次启动、隐藏及最小化恢复、入口到集成窗口交接。
Windows 安装包必须在隔离 CI 中通过这些实际窗口和安装检查后才替换下载入口。
真实 Windows 用户的现场复验不等同于隔离 CI 检查。
