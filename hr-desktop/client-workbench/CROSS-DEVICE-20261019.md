# 跨设备重复收取修复

2026-10-19 的只读核查确认：同一平台用户、同一 BOSS 招聘身份在 Mac
保留了旧会话目录键，在新 Windows 上使用稳定身份键，云端因此分成两套账号记录。
原账号有 76 条记录（66 条待审批），Windows 新键有 3 条。其中 1 条与原账号
的候选人、附件消息完全相同，来源由原被动邀约变成了 BOSS 沟通。
“待核查会话”表示等待检查聊天内容，不能作为待审批简历数量。

0.1.25 将本地资料目录和云端账号标识分离。绑定在原生身份验证后完成；
别名只在同一平台用户范围内解析。两个已有数据的账号不自动合并。
`reconcile_hr_account.py` 默认只在内存副本预演；正式执行先锁定写入并备份，
核对重复数量、文件哈希、审核结果和关联记录，存在冲突就整体回滚。
重复行保留可追溯归档，原审核、人才关联、文件和下载链接不删除。

连接恢复后先分页同步云端已入库附件，再启动 BOSS 自动收取。
清单使用单调序列，同一账号、候选人、消息精确去重。它仅恢复元数据；
不重新下载 OSS 文件，不跳过同一候选人后来发送的新附件。两个本地收取
通道都识别云端确认，无法完成同步时自动收取等待恢复，不先扫完整历史。
已确认的主动邀约来源可通过云端同账号、同职位、同会话记录恢复。

Windows 原客户端已登录但请求标识尚未准备时，返回 `SESSION_PREPARING`，
助手继续进行有期限的本机会话检查。真实退出、风险和身份不符仍停止。
原 BOSS 和系统资料目录、网卡直连、每小时 500 次共享预算、每日 150 次招呼、
历史慢收及禁止重放未确认发送的规则不变。

验证范围：跨设备清单恢复、分页、账号与平台用户隔离、相同附件重试、
同候选人新附件、来源与审核保留、原生会话准备和现有主动/被动邀约夹具。
离线检查不等于 Windows 真账号业务验收。此次未向候选人发送测试消息。
