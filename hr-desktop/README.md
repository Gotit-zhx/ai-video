# 赫逸招聘助手

Mac（Apple Silicon）和 Windows x64 共用的招聘客户端。使用 Electron 内置 Chromium，
运行经过固定版本校验的 boss-agent-cli 2.0.0，不需要 HR 安装 Python、命令行或浏览器插件。

## 使用

1. 安装并打开客户端，桌面只显示黑白悬浮球。拖动调整位置，点击展开或收起 BOSS 页面。
   启动时不打开远程页面，也不会自动登录、搜索或发消息。
2. 打开 `https://hoyee.org.cn/?lang=zh#hr-overview`，登录获授权的赫逸管理员账号。
3. 进入招聘页面会自动连接本机助手。浏览器首次提示本地网络权限时允许连接。
4. 点击“在助手中登录 BOSS”；在客户端的官方 BOSS 页面扫码确认。
   网页只显示连接进度，不再展示或轮询二维码。
5. 招聘工作仍在原网页中完成。应用内只保留 BOSS 页面，去掉概览、工作台和导航。
   任务实际执行时，窗口边缘与悬浮球出现流动光波；执行结束即停止，等待扫码不显示执行光波。
   系统启用“减少动态效果”时使用静态亮边。

支持职位、投递、推荐、候选人、会话、在线简历、索取与接收附件功能，以及按职位启用的被动邀约。
登录不会擅自开启职位的被动邀约；已启用的规则会继续处理候选人的有效主动消息。
手动索取需要用户确认；发送结果不明时保留记录，不自动重发。
遇到平台验证/账号限制立即暂停，不尝试绕过。客户端不保证或承诺免于平台限制。

## 被动邀约、简历池和话术

0.1.10 增加职位卡片内的“上传简历 / AI 寻源”，不再提供独立寻源菜单：

- 每个招聘账号、每个职位分别上传至多 10 份 PDF/DOCX 参考简历，每份上限 10 MB。
  文件保存在私有 OSS，提取正文后显式点击 DRIVER 分析；同文件去重，失败不自动重试模型调用。
- 正式 JD 与参考简历共同生成建议 JD、技能画像和依据，不自动修改 BOSS 发布的职位。
- 每次选择 5/10/15/20 人，最多读取两页、40 张本职位推荐卡片，单次批量 AI 分析。
  实际不足目标人数时如实显示。仅按岗位相关技能、经验和成果给出人工参考，不使用个人敏感属性。
- HR 在候选人卡片点击“打招呼”，选择/编辑主动话术并确认后，助手调用固定 CLI 的 `hr greet --yes`。
  队列按账号隔离，读取卡片超过 30 分钟则停止发送，发送前后均持久化；不明确的结果不自动重发。
  旧助手不会领取主动招呼。沿用总请求预算、风险暂停与至少 60 秒的自动写入间隔。
- 成功招呼通过 SDK 会话资料的加密候选人 ID **和**职位 ID 同时匹配，绝不按姓名猜测会话；
  对方回复或发送附件后进入原有索取、接收、人工审批和人才库邀约流程。
- 简历池新增全部来源、主动邀约、被动邀约，与职位和审批分类组合筛选；旧记录默认被动邀约。
  切换账号不迁移本地 Cookie；同一账号恢复连接时按云端成功记录补接具体会话。

- 0.1.6 起，职位卡片可勾选“被动邀约”，默认关闭。仅处理启用后候选人的主动消息：
  先发送话术管理中配置的默认“被动邀约回复”，确认成功后再索取简历；HR 已回复时跳过自动回复。
  未配置默认话术时显示待配置；启用前的历史消息不补发。重复通知、进程重启、发送结果不明确均不重发。
- 每 30 秒执行一次本地调度，最近会话每 120 秒检查一次，新消息按活跃时间优先；
  独立的自动发送间隔至少 60 秒，保留 SDK 的逐请求间隔与每小时总额限制。
  自动任务接近请求额度时等待，为 HR 的手动操作保留额度。以上数值不构成平台风控豁免。
- 状态和操作记录显示在职位卡片及简历池；状态刷新只读取本机记录，不额外请求 BOSS。
- 助手每两分钟进行一次有界检查，发现会话、核对回复、索取和接收分阶段执行；
  开启后不是即时批量发送。所有实际 BOSS 请求继续受单进程互斥、六秒间隔、每小时预算和风控暂停约束。
  索取使用固定 CLI 的官方 `request-resume` 操作，聊天页须为 `https://www.zhipin.com/web/chat/index`。
- 已索取的附件继续按既有七天期限和失败次数限制检查，关闭开关仅停止新索取。
  原件保存到私有 OSS；已下载文件和上传确认分别持久化，平台网络暂时中断不会重新发送索取。
- 简历池的“AI 辅助分析”只有 HR 点击才调用配置的 DRIVER，每次一个请求，不自动重试。
  结果仅供参考；未能提取文本的 Word/扫描件可查看原件后补充正文，岗位资料也可补充。
- HR 点击“通过，加入邀约”后，人才进入所选项目组的邀约阶段，不发送额外邀请消息。
- HR 点击“不通过，自动婉拒”后，服务端读取话术管理中已启用的默认婉拒，替换 `{姓名}`、`{职位}` 并排队。
  没有默认话术时须先配置；无需第二次发送确认。每条记录保留审批人、话术版本及完整发送文本，
  修改话术不改变已排队消息。
- 拒绝消息按当前账号隔离，由助手先领取后发送；领取或发送中断不自动重发，显示“结果待核对”。
  尚未开始发送的消息可取消。同一招聘账号重新登录接续原队列，切换其他账号不会继承。

服务端模块是 `passive_pool.py` 和 `resume_storage.py`，同原 HR SQLite 一起备份。
安装 `scripts/boss-agent/resume-pool-requirements.txt`，通过 systemd `LoadCredential` 提供
`APP_HR_OSS_CREDENTIALS_FILE`，另配置 `APP_HR_OSS_ENDPOINT`、`APP_HR_OSS_BUCKET`。
凭据不进入仓库、网页或桌面助手。发布使用 `release-passive-pool.py`，只替换 HR 控制器类，
保留线上 JAR 中其他修复；启动时将中断的分析和不明确的发送标记为待人工处理。

换电脑需安装对应版本并重新扫码，浏览器登录资料不会在 Mac 和 Windows 之间复制。
平台原有业务资料仍在服务器。本版新增的简历索取追踪保存在执行电脑，
只在同一浏览器会话下恢复；新登录或换电脑不会自动迁移旧会话的待接收队列。
这些历史记录保留在原电脑，切换前应先核对未完成的索取。

关闭或最小化 BOSS 窗口会收起到悬浮球，页面与任务保持运行。右键悬浮球或托盘可暂停、
释放浏览器资源、退出。拖动位置会记忆；断开显示器后自动移回可见桌面。
退出会结束运行时。0.1.9 起，仍保有登录态的助手在休眠、重启、临时连接失效后自动恢复：
先核对平台用户、已绑定的招聘者身份及本地浏览器与 CLI 的会话一致性，不调用登录、同步或职位探测接口。
主动退出登录、手动暂停、身份不匹配及真实平台限制保持停止。未启动客户端时，不会退回服务器执行 BOSS 请求。
在网页点击“退出 BOSS 登录”、平台右上角“退出”，或右键悬浮球选择“退出 BOSS 登录”，
都会清除助手专用浏览器的 Cookie/缓存和本机保存的各次登录凭据。正在执行的本机操作
先停止再清理，不会重发。简历记录、风险暂停记录及操作记录保留，不调用 BOSS 全局退出。
平台退出会等待助手确认清理结果；助手离线时明确提示未确认清除，不伪报成功。
过期的本机配对凭证只能用于清理自身会话，不能继续读取数据或执行招聘操作。

## 连接边界

- 网页只调用 `127.0.0.1:17861`，严格校验 Host、Origin、随机本机会话凭证。
- 服务器签发 60 秒、只能使用一次的配对凭证；本机向赫逸兑换身份。
- 同一用户只有一台设备持有有效执行凭证；每 15 秒以内重新校验，失效停止新任务。
- 执行凭证有效期 30 分钟，网页在到期前 2 分钟自动续接。正常每 25–35 秒
  检查本机缓存状态，断线以约 2–60 秒渐进退避；切回页面、网络恢复时立即检查。
  间隔浮动用于避免多个网页同时请求，只作用于连接检查，不用于伪装 BOSS 请求。
- 多个网页共享续接结果；自动连接不会抢回另一台设备。电脑休眠或网络恢复后，已有登录态
  通过本地核对即可继续原有已授权队列；预算仍按原记录等待，不重放结果不明的发送。
  账号限制、验证码、身份不匹配不自动恢复。网卡变更时只重建助手私有直连通道，不修改系统代理或路由。
- 临时平台网络错误阻止当次任务，但不删除仍有效的凭证；明确失效才暂停授权。
- 网页配对的网络会话与 BOSS 浏览器独立持久化，不再创建内置赫逸页面。
  本地悬浮球与窗口外壳单独隔离，BOSS 页面无 Node/preload 权限。
- CDP 仅监听本机随机端口。BOSS Cookie 经 stdin 交给本地子进程，不写入日志或上传。
- 实际请求仍受原来的互斥、预算、账号限制保护；使用经过哈希审核的 SDK，不自动升级 SDK。

## 网卡直连

默认选择有默认网关的实际有线或 Wi-Fi 网卡。Mac 使用 `IP_BOUND_IF`，Windows 使用
`IP_UNICAST_IF`，同时绑定该网卡的本地 IPv4 地址；DNS 查询也绑定相同网卡。
不采用系统代理、环境代理或虚拟网卡的默认路由，不更改其他软件的网络设置。

内置浏览器通过仅监听 loopback、有随机凭证的本机转发端口连接同一网卡；
HTTPS 的 TLS 字节原样传递，不解密。CLI 接口和附件下载绑定同一网卡。
QUIC 和非代理 WebRTC UDP 已关闭，避免旁路流量。绑定/DNS/连接失败时停止，
不会切换到系统代理。没有 IPv4 实际网卡的网络暂不支持；换网卡后重新启动助手。
这解决本应用的出口选择，不改变 BOSS 官方的账号或 PC 登录限制。

## 构建

每个目标系统分别构建 Python 运行时，不交叉打包另一系统的可执行文件。

```sh
# 在 hr-desktop 目录，Node 22+、pnpm 11.25、Python 3.12
pnpm install --frozen-lockfile
node node_modules/electron/install.js
python -m venv runtime/.venv
# Mac:
runtime/.venv/bin/python runtime/install.py
runtime/.venv/bin/python runtime/build.py
# Windows:
runtime\\.venv\\Scripts\\python runtime\\install.py
runtime\\.venv\\Scripts\\python runtime\\build.py
pnpm test
pnpm run dist:mac
# Windows 使用 pnpm run dist:win
```

构建时从仓库 `scripts/boss-agent` 提取同一份连接规则，只调整 Windows 文件锁、
未使用的 Unix 服务类以及本机 CDP 端口。上游许可在 `vendor/BOSS-AGENT-CLI-LICENSE.txt`。

`--self-test` 必须指定临时目录 `HEYI_TEST_USER_DATA`，阻断外网并使用合成 Cookie，
验证嵌入浏览器、会话隔离、运行时完整性、CDP、配对、直连路由和实际窗口渲染，不访问 BOSS。
GitHub Actions 同时生成 Mac/Windows 安装包和测试记录。

当前打包不含 Apple Developer ID 公证或 Windows 发布者证书。
对外分发前可配置组织的签名证书；现有版本可能出现操作系统的未知发布者提示。

## 线上更新

只更新招聘前端、连接服务及 CSP 中本机端口白名单。连接服务设置
`APP_HR_DESKTOP_ONLY=1` 后拒绝服务器招聘执行；原账号浏览器和暂停记录保留。
无需重启商品服务、数据库或服务器 Chrome，也不更改 SSH、代理或网卡配置。

## 重新登录与断线补收

0.1.8 起用官方页面当前用户 ID 的本地散列绑定业务记录，Cookie 更新或主动退出不会
删除待接收、已发送和入库进度。退出仍清除 Cookie 和加密登录凭据。不同招聘账号隔离。
旧版会话目录只在已归档消息 ID、候选人 ID 和当前招聘者 ID 全部匹配后认领；
不使用姓名、公司或职位相似度猜测账号，也不读取旧凭据发请求。

成功登录后会补查已索取但未入库的简历，并按职位分页检查断开期间的新招呼，
包括已在手机标为已读的消息。游标、消息去重和发送记录保存在本机，检查中断可接续。
只对已开启被动邀约的职位执行原配置；补查本身只读，已发过的回复和索取不会重放。
已主动发来的附件直接进入接收流程，不再重复索取。每次只处理一项，沿用共享额度、
发送间隔和遇限制即暂停的规则，不通过重新登录清空风险或请求预算。

`filterByLabel` 返回完整 `result` 会话索引时一次收完；只有明确分页的响应才继续翻页。
不认识的响应重复页保留游标并退避，不把未知分页当作补收完成。

## 简历姓名与原始附件名

助手保留候选人附件卡片与已验证下载响应中的原文件名，随机本地文件名仅用于安全落盘。
云端按“原文件名 → PDF/Word 正文 → 首页面 OCR”识别姓名，纯编号、通用标题、
岗位词及歧义名字不作为姓名。界面下载名称保留原文件名，人工编辑过的姓名不被覆盖。
旧记录按提取版本幂等补齐，不改变审批、AI 分析、邀约或发送状态。

可选 OCR 在连接服务所在 Linux 安装 `tesseract-ocr tesseract-ocr-chi-sim poppler-utils`；
只在前两步没有姓名时执行，最多渲染一页，渲染 8 秒、识别 12 秒上限。
低置信度姓名继续留待核对，不调用 AI 服务，也不新增 BOSS 请求。
