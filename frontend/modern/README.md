# Modern finance workspace

This React/TypeScript frontend is an opt-in finance surface. The classic finance UI remains available. Host selection, login/session adaptation and production activation belong to the classic integration layer; feature modules never call legacy `window.Finance*` widgets.

Use Node 22.12 or newer. From this directory run `npm test`, `npm run typecheck`, and `npm run build`. After building, run `node tests/build-smoke.mjs` to import the generated ESM mount entry and verify the one-CSS manifest contract. Build output is ignored under `../assets/finance-modern`; do not publish source or dependencies.

`src/app/mount.tsx` exports `mountFinanceRoot`. Mount on a disposable host element and insert styles/overlays into its ShadowRoot. `FinanceApplication` supplies the nine-route shell. Its `pages` slots (`shops`, `costs`, `charges`, `qianyi`, `refunds`) accept components receiving `{route}`; these consume `useFinance()` for API, owner, permissions, filters and translation. Unfilled slots explicitly direct users to the classic workspace. `fees` aliases `fee-records`; `expense-ledger` is the charges slot.

All reads use the scoped Query client. Default dates are the previous full Asia/Shanghai month, all native currencies displayed in CNY. Business dates remain date strings. Native-currency filtering and amount display mode are independent: a native currency can be viewed in CNY, and advertising can display all original currencies separately. Scope/display-mode edits clear the resolved native currency and historical snapshot; the UI identifies automatic original-currency selection explicitly. `ORDER ALL` directly queries records; other record modes coordinate with an overview snapshot, while reconciliation carries its own evidence. Unknown amounts remain unavailable, known partials remain marked, and no totals are computed from a paginated table. Advertising spend, booked advertising and GMV Max remain separate scopes.

Reusable operations are under `src/features/finance/operations`: personal FieldSettings, frozen ExportDialog, personal ExportJobs and management-only ImportDialog. Export jobs transmit a real Idempotency-Key; unknown submission recovery is explicit and reuses the same key/body. Closing/inactivity/owner changes clear scoped controls and cancel applicable reads/downloads. Generic and funding imports preview before commit and never automatically replay writes. Viewer-safe personal fields and export jobs remain available without management permission.

UI labels use `useFinance().t`. The shared catalog currently adds substantial bundle weight; route and ECharts imports are lazy. Browser viewport/theme/language acceptance and full costs/shop/Qianyi action flows run through `npm run verify:ci` against an explicit localhost API fixture. Production activation remains a separate gate. See [the acceptance matrix](../../docs/guides/finance-modern-acceptance.md).

Financial presentation retains known ORDER/FEE aggregates while incomplete settlement gross stays unknown. Operating tables preserve partial/estimated markers; booked-advertising and GMV support tables remain distinct from spend reporting. Account coverage is filtered by confirmed account/store relationships and shows observed/expected days plus no-record/verified-zero states. Catalog FX fields use explicit allowlisted row.fx accessors; timestamp labels retain UTC, Beijing or shop-local bases. Cache and settlement-calculation receipts identify retained snapshots and unfinished calculations.

Browser acceptance waits for Modal and Select opening motion to finish before pointer selection; an initially stable preparation frame is not the final popup position. Mapping failures print at most 12 pointer events with coordinates and open state, while keeping the selected-value, popup-close and submitted-mapping assertions. The structured error audit retains native request cancellation events, including Linux WebKit's exact `Load request cancelled`, and still rejects page errors, ordinary network/HTTP failures and duplicate injected diagnostics.

Every modern Modal opening in browser acceptance must call `shadowDialog(page)` before interacting with or measuring its contents, including reopening after an identity change. Classic `.fi-dialog` flows keep their existing readiness behavior.
