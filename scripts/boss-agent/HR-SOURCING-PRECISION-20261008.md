# 寻源条件简化与原文核验

用户截图中的图像算法岗位，把只有一条依据、另外两条待核实的人选显示为
100 分并收录；泛化的“相关或可迁移经历”也把人力资源、LLM/RAG 任务当成
视觉岗位依据。原分数只以已知条件权重作分母，不能表示整体信息充分。

## 行为

匹配界面以核心方向、关键技能、实战经历三项为主，权重、必需项及增删条件
放入默认折叠的高级设置。使用 JD 建议只更新编辑草稿，HR 确认保存后才能寻找。
建议复用岗位 JD、需求分析结果，不额外调用模型。优先从职位名确定专业方向，
技能只推荐正式 JD 中明确出现的工具；保留 HR 手动编辑。

所有正向或部分匹配都须提供同一候选人卡片中的连续原文引用；系统检查
引用是否真实出现在输入中。核心方向再核对方向词，普通算法、LLM/RAG、
一般编程经历不作为视觉方向的直接证明。缺少引用或无法验证时改为待核实。
词语与引用校验不能替代语义判断，任务关联仍由模型判断、HR 审阅。

入选须同时满足已知条件分至少 80、已知信息权重覆盖至少 60%，
每个必需条件均完整匹配。必需项未知或仅部分匹配不入选，明确相反则不符。
Python 再校验覆盖及必需状态，避免异常返回绕过入选规则。
结果主标签显示完整满足几条，分数注明为已知条件参考分，另列信息覆盖率；
展开依据可看原文。旧规则结果标记为旧条件结果，禁止新联系，须 HR 核对保存后
重新评估。已确认的话术命令仍保持幂等，不重复发送。

分页、预算等待、风险暂停、100 人无匹配停止并给建议、逐人明确确认后联系保留。
发布前同时检查寻源分析、画像和发送是否空闲，避免中断正在付费的分析。

工作台 58。覆盖少量证据高分不入选、必需项未知或部分匹配、伪造引用、
LLM 引用不证明视觉方向、真实 OpenCV/目标检测引用、旧条件保留与复核、
JD 建议不启动模型或 BOSS 操作，以及原有分页、停止及确认边界。
