## 结论

它在职位列表采集上采用的“读取页面自身响应”思路，值得作为后续浏览器适配器的
设计参考。但没有可比较的封禁率、账号样本或同环境实测，不能断言它对招聘账号
更安全，更不能保证永远不被识别。

它面向求职者侧公开职位、职位描述、薪资分析；不是招聘方候选人、聊天、
索取和接收简历的完整接入。把它替换到当前 HR 系统，仍需自行开发这些能力。
只更换库而仍由同一台云服务器承载登录，不会自动改变服务器运行环境。

## 实际实现

| 项目 | 此项目 | 当前线上 HR 接入 |
|---|---|---|
| 主要数据 | 职位列表、职位详情 JD、薪资和技能摘要 | 招聘职位、候选人、会话、已授权索取的简历 |
| 列表读取 | CDP Network 监听页面自行收到的职位响应 | 已安装 SDK 2.0.0 的多数招聘只读命令仍走保存 Cookie 的 HTTP 客户端 |
| 页面行为 | 导航搜索页、滚动加载；详情新建页面并读取 DOM | 专用服务器 Chrome 扫码；简历索取通过现有沟通页动作 |
| 凭据 | 默认独立、持久浏览器 profile，不复制日常浏览器 Cookie | 独立 profile 和加密凭据；请求前检查主 Cookie 和 UA 是否一致 |
| 限制处理 | 首次搜索响应和登录探测识别限制并停止 | 持久暂停标记、跨进程串行与预算、单次受控 HTTP、禁止隐式刷新 |
| 预算 | 10 页、单进程 500 次计数；部分页面访问后的计数 | 跨进程持久预算；页面内部网络请求未被全部计入 |
| 实际安全性证据 | 项目说明及合成测试，不等于无封禁验证 | 本系统回归测试；历史手机和电脑退出的确切因果仍未证明 |

## 可以借鉴的部分

1. `NetworkJoblistCapture` 通过 CDP 读取页面收到的 `joblist.json`。
   职位列表不另外注入 XHR，也不要求单独维护一份用于该列表的 HTTP Cookie 快照。
   这可减少这条链路的重复认证状态和额外构造请求；不证明其他功能具有同样行为。
2. 默认独立 profile，主浏览器登录态复制是显式选项；不会在每次运行时默认覆盖。
3. 将正常抓取的首次搜索响应兼作状态判断，减少一次无关的专门探测。
4. 明确识别限制、有限等待、增量保存，方向与当前保护一致。

注意：“被动”指获取响应的方式。脚本仍主动导航、滚动并打开详情页，
这些动作会让官网产生请求。它不是完全无访问的观察器。

## 需要修正或进一步验证的地方

### 翻页限制检查不完整

`scripts/boss_cdp_raw.py` 的 `scrape_list()`：
`gate_first_response(data)` 只在 `pg == 1` 的分支调用。
第二页以后将响应交给 `map_api_jobs()`；无数据时 `continue`。
因此后续页面若返回限制响应，可能被当作空结果继续后续滚动，
而不是按首次响应的限制逻辑立即停止。这是静态代码发现，
没有用真实账号复现。

### 请求预算不跨进程持久化

`MAX_API_REQUESTS = 500` 和 `_request_counter` 是进程内变量；
`incr_request()` 没有账号级数据库预算或跨进程锁。
重复运行或多个进程同时运行不能共享这个计数。
每次导航产生的官网内部网络流量也不等于一次脚本计数。
不能把“500 次”理解为平台认可的安全值。

### 登录等待仍会产生搜索访问

`wait_for_login()` 调用 `probe_login_state()`；
后者会导航真实搜索页，轮换关键词/城市并等待响应。
等待间隔从 3 秒退避到最多 15 秒，默认等待上限 300 秒。
它不是仅检查本机 Cookie 或等待用户确认。
对于当前正在分析登录异常的账号，不应照搬这种额外导航探测。

### 不能从 README 的工具比较推导不会触发限制

README 对直接 CDP 相比 Selenium/Playwright 的描述是作者主张，
不是可控实验结论。此项目的变更记录本身提到旧版注入 XHR 遇到
`code 37` 后修改实现。它同样会遇到平台限制和页面变化。
随机滚动、鼠标动作也不能作为账号安全保证。

### 并非招聘者适配器

`/wapi/zpgeek/search/joblist.json`、职位详情和求职分析并不覆盖
招聘方聊天、简历授权以及延迟接收。不能用职位抓取成功证明
招聘方接口、写操作和会话撤销问题已解决。

## 对当前系统的建议

- 保留现有业务后台、权限、记录和 OSS，不直接替换为这个爬虫。
- 后续评估本人电脑上的专用浏览器承担平台会话，云端管理业务数据；
  HTTP 平台请求也应随会话迁到本机，否则只迁 Chrome 仍保留混合路径。
- 对确需的只读页面，可以评估读取用户正常页面收到的响应，
  逐项适配、最小采集；不移植随机模拟操作来承诺“不可识别”。
- 继续保持账号串行、持久预算、明确风险立即停止、不确定写入不重发。
- 先完成账号与任务绑定。当前新号观察期间暂停旧待接收任务的自动检查，
  保留数据库；这一暂停不是完整的多账号隔离实现。
- 不在账号已经受限后，自动改走另一工具或通道反复尝试。
