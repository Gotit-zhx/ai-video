# BOSS 招聘连接稳定性复盘

日期：2026-09-28。目标：查清可证明的问题，按上游契约改进连接器，
停止限制期间的请求；不通过反复登录验证账号风控，不承诺绕过或解除限制。

## 已确认的直接原因

在服务器现有 BOSS 登录页，通过本机 CDP 只读检查，页面同时显示：

- 背景：扫描成功、请在 App 端确认登录。
- 安全提示：由于上次登录行为存在异常，暂时关闭 PC 端登录权限。
- 预计开启时间：2026-09-29 13:44:43。
- 官方要求：限制解除后，由实名本人操作；实时扫码，手机与电脑在同一地点。

当时浏览器没有主登录 Cookie，CLI 也没有保存有效登录凭据。因此本次没有
完成网页登录。旧连接器先匹配“扫描成功”就结束了页面分析，遗漏安全弹窗，
于是用户界面继续等待。手机确认动作与平台接受网页登录是两个不同状态。
原 CLI 到时会关闭自己创建的临时页，所以稍后 VNC 看到首页不代表登录成功。

以上证明**当前等待的原因和界面误判**，不能证明历史上每次手机被踢的具体原因。
上游平台没有返回精确触发请求、评分规则或会话撤销日志。

## 调用路径与风险因素

| 路径 | 实际实现 | 结论 |
|---|---|---|
| 新扫码登录 | `boss login --cdp`，专用 Chrome/profile | 用的是上游 CDP 登录；不是网页前端直接调用登录 HTTP 接口 |
| 已有会话同步 | 上游 `login_via_cdp(reuse_existing=True)` | 只在用户显式动作后同步，成功后做一次招聘职位验证 |
| 职位、投递、聊天记录、推荐 | 招聘者 adapter → HTTP 客户端 → 保存的 Cookie | 配置 CDP 不会自动把这些请求转为浏览器请求 |
| 索取附件简历 | 招聘者 adapter → 现有聊天页 Vue 动作 → WebSocket 发送证据 | 不是普通 `BrowserSession.request`；需单独覆盖动作预算 |
| 本地断开 | 删除服务器凭据、停止专用浏览器、清理该 profile 的 BOSS Cookie | 未调用平台全端退出或会话撤销接口，不能据此认定它踢掉了手机 |

**已确认的实现缺口或放大因素：**

- 较早连接器每 120 秒检查一次简历，每轮最多 20 个会话；多数认证/风险失败
  没有全局停止。属于可重复触发请求的设计缺口，不能当作实际请求次数。
- 原 SDK 的 HTTP 客户端在 403/安全验证、Token 过期和限流时有自动刷新或重试。
  原调用方未对所有路径设置统一跨进程预算。
- SDK 的 `_cdp_login` 在复用会话被判过期时，会自动再用
  `reuse_existing=False` 强制重登。我们的会话同步已绕开该路径，
  本次进一步在统一 SDK 入口禁止这种隐式切换，避免检查与登录之间的竞态。
- 之前的保护只覆盖 HTTP 和普通浏览器请求，漏掉原始 CDP 聊天动作与会话验证探测。
- 登录页把安全限制弹窗误当成仍在等手机确认，容易诱导用户反复扫码。
- 某些浏览器异常不在旧异常捕获范围内，工作线程结束后可能仍留下 pending；
  子进程超时后的管道回收也缺少第二个时限。

**需要区分的推测：**

手机与云服务器的地点、网络出口不一致是需要重视的环境因素，与官方本次提示相关。
但未采集或比较手机与服务器的完整地点/设备数据，不能认定这就是唯一触发条件。
也不能把“云 IP 一定被封”“用了 CDP 就不会风控”或“开源项目保证安全”当作结论。

因此无法可靠给出“触发了几次、每一次对应哪个请求、哪一次让手机退出”的因果表。
当前暂停记录是对已看到的官方安全提示的持久化，不是历史风控次数统计。

新增日志仅记录登录开始/结果、动作类型、时间、固定错误码及耗时。
不记录 Cookie、Token、请求参数、姓名、手机号、会话内容或账号指纹。
这能改进后续关联分析，不能补造已经缺失的历史证据。

## 修复后的行为

- 登录页优先识别 PC 登录限制、明确安全验证及风险文案，再识别扫码进度。
- 登录工作进程每轮最多等待 5 秒后检查现有页面；检查有独立 10 秒上限。
  只是读取服务器本机浏览器状态，不向 BOSS 重放请求、不刷新页面。
  用户关闭工作台也不影响后台发现风险并停止。
- 官方 PC 限制和预计时间持久保存；限制期间不能重新扫码，清除本地会话或
  重启连接器也不会清除该限制。
- 预计时间到达不自动恢复调用，不自动扫码；仍需用户确认官方限制已解除后手动发起。
- 显式扫码/同步最多 30 分钟 3 次；单次仍有有限等待时间；重复点击正在进行的
  登录不会再计次或创建新工作线程。次数限制跨服务重启、本地会话清理保留。
- API 风险/认证失败全局暂停；HTTP 不隐式刷新，不跟随认证重定向或重试。
- 已有跨进程预算是 6 秒间隔、每小时最多 120 个受控请求或动作，
  本次覆盖原始 CDP 聊天动作和已有会话验证。官网页面自身的内部请求不被逐一计入，
  所以不能把这个预算宣称为所有网络流量的总限额或平台认可的安全频率。
- 简历检查每 5 分钟最多 3 个待接收会话，最长 7 天；风险立即停止，
  连续 3 次传输失败也暂停。已索取、已接收和结果不确定记录保留，不自动重发。
- CLI 使用独立进程组；回收有界且不终止独立 Chrome 服务。风险提示页面保留供 VNC 查看。
- 前端停止转圈，显示真实限制和预计时间；扫码动画不冒充登录成功。
- 校验安装版本与已审阅源码哈希；SDK 变化必须重新审阅和测试。

官方限制在真实连接器中可读、新登录被本地拒绝、HTTPS 页面正常及进程/数据保持。

是否实际解除，再由账号本人手动尝试一次；若仍出现安全提示立即停止。
不在到时后自动触发后台任务。

从本次官方提示看，本人手机与本机浏览器同地点的运行方式更符合平台要求。
如后续调整接入方式，应让本机浏览器承担平台会话，服务器承担业务和记录管理；
这需要单独设计账号隔离、授权、连接状态和数据最小化。不能在限制期间改用
代理、隧道或另一通道继续尝试，也不能承诺插件、本地浏览器或可见界面免于风控。
